# 실험 계획: 한 관절 로봇 링크를 ROS 2 노드로 적분하면 글의 에너지 드리프트 판독 순서가 그대로 통하는가

## 질문

이 글(`research.md`)은 주어진 `K`, `U`의 덧셈·나눗셈만 Python 3.12.3으로 검산했고 "물리 엔진이나 실물 로봇을
실행한 결과는 아니다"라고 적었다. 이 실험은 글과 같은 초기 에너지(`K₀=4 J`, `U₀=6 J`, `E₀=10 J`)를 갖는
한 관절 링크(균일 막대 진자, 모터 토크 0)를 ROS 2 Jazzy 노드가 실제로 적분하고, 다른 노드가 `/tf`와 상태 토픽만
받아 에너지를 계산할 때 글의 판독 순서가 성립하는지 확인한다.

1. 마찰·토크가 없는 보존 모델에서 `E=K+U`의 드리프트는 적분기와 시간 간격 `h`에 따라 얼마나, 어느 방향으로 생기는가?
   글의 표처럼 "줄어드는" 방향만 나오는가, 늘어나는 적분기도 있는가?
2. 같은 모델·초기조건·종료시간에서 `h`, `h/2`, `h/4`로 줄이면 최대 편차 `max|ΔE|`와 종점 편차 `ΔE(T)`가 수렴하는가?
   감소 비율(관측 차수)은 적분기마다 어떻게 다른가?
3. 시간 이력에서 "한 방향 누적"과 "제한된 진동"이 실제로 구분되는가? 종점 편차가 최대 편차보다 훨씬 작아지는 경우가 있는가?
   0.1 s 간격으로 내보낸 로그(ROS 경로)의 최대 편차는 적분 스텝마다 잰 최대 편차를 얼마나 놓치는가?
4. 위치에너지 영점을 바꾸면(최저점 0, 회전축 0, `+100 J`) `ΔE`는 그대로이고 퍼센트만 달라지는가?
   `E(0)`가 0에 가까운 영점에서 퍼센트는 얼마나 부풀고, 미리 정한 `E_scale`로 나눈 값은 영점과 무관한가?
5. 댐핑이 있으면 `K+U`가 줄어드는 양은 `h`를 줄여도 0으로 가지 않고 물리적 손실 값으로 모이는가?
   대신 비보존 일을 뺀 장부 잔차 `ΔE − W_nc`가 0으로 수렴하는가?
6. 글의 점검 목록 중 세 가지 실수(운동에너지의 평행축 항 누락, 중력 위치에너지 부호 반전, 상태와 위치를 한 샘플 어긋난
   시점으로 짝지음)는 `h`를 줄여도 개선되지 않는가?
7. 에너지가 가장 잘 보존되는 실행이 관절각 궤적·주기도 가장 정확한가? (글: 에너지 검사는 충분조건이 아니다)
8. (글이 인용한 MuJoCo 문서의 취지) RK4와 implicit(후진) 오일러의 에너지 거동은 실제로 다른가?

## 글이 주장한 예측값

글의 수치는 손으로 정한 설명용 입력의 산술이다. 실측이 아니라 실행 전 예측·주장으로 둔다.

| 항목 | 글의 주장(예측) |
|---|---|
| 초기 에너지 | `K₀=4.0 J`, `U₀=6.0 J`, `E₀=10.0 J` (이 실험의 입력으로 그대로 사용) |
| 큰/작은 시간 간격 | -0.1 J(-1.0%) → -0.02 J(-0.2%): 작은 간격에서 드리프트가 줄었다(설명용, `h`·적분기 없음) |
| 마찰 포함 | -0.5 J(-5.0%)는 적분 오류의 증거가 아니다(물리적 소산일 수 있다) |
| 보존 조건 | 시불변·무구동·무마찰이면 `K`와 `U`가 오르내려도 `E`는 일정해야 한다 |
| 영점 이동 | `U'=U+C`에서 `ΔE`는 그대로, 퍼센트는 달라진다. `+100 J`면 퍼센트 크기가 작아진다 |
| `E(0)≈0` | 상대 변화율이 지나치게 커진다 → `ΔE`[J]와 미리 정한 `E_scale`을 쓴다 |
| 시간 이력 | 종점만 우연히 0에 가까울 수 있고, 제한된 진동과 한 방향 누적은 이력으로만 구분된다 |
| 수렴 | `h`→`h/2`→`h/4`에서 오차가 줄고 관심 궤적도 한 값으로 모이면 이산화 오차 설명이 강해진다 |
| 개선 안 될 때 | 에너지 식 누락 항, 중력 부호, 기록 시점 불일치 등을 먼저 의심한다 |
| 에너지 장부 | 0에 가까워야 할 값은 `E(t)-E(0)`가 아니라 일·소산을 뺀 잔차다 |
| 적분기 | RK4와 implicit 계열은 서로 다른 에너지 거동을 보일 수 있다(MuJoCo 문서 인용, 수치 없음) |
| 충분조건 아님 | 에너지가 거의 보존돼도 위상·관절 궤적이 틀릴 수 있다 |

실행 전 가설(교과서 지식으로 적은 예측이며 측정이 아니다):

- 전진(explicit) 오일러는 무마찰 진자에서 에너지를 **늘리고**, 한 방향으로 누적하며 `h` 절반마다 오차가 약 절반(1차)이다.
  글의 표와 달리 드리프트 부호가 양수일 것이다.
- 준암시적(symplectic) 오일러는 에너지 오차가 한 방향으로 쌓이지 않고 제한된 폭에서 진동하며, 폭은 1차로 줄 것이다.
- RK4는 오차가 매우 작고 4차(비율 약 16)로 줄 것이다. implicit 오일러는 마찰이 없는데도 에너지를 **줄이고**(수치 감쇠) 1차일 것이다.
- 영점: 최저점 0이면 `E₀=10 J`, 회전축 0이면 `E₀ = 10 − m·g·L/2 ≈ 0.19 J`라 퍼센트가 약 50배 이상 부풀 것이다.
  `E_scale = m·g·L`(가동 범위 전체의 위치에너지 폭, 실행 전 정의)로 나눈 값은 세 영점에서 같을 것이다.
- 누락 항·부호 반전·시점 어긋남은 `h`를 줄여도 최대 편차 비율이 1 근처에 머물 것이다.
- 에너지 오차가 가장 작은 실행과 관절각 오차가 가장 작은 실행은 같은 적분기 안에서는 대체로 일치하겠지만,
  적분기 사이에서는 "에너지 오차가 작은데 위상 오차는 큰" 조합(준암시적 오일러)이 나올 것이다.

## 측정 방법

- 환경: 하네스의 `ros:jazzy-ros-base` 컨테이너(네트워크 없음, 1 CPU, 1 GiB). `rclpy`, `tf2_ros`, `std_msgs`,
  `geometry_msgs`만 쓴다. 패키지 버전은 `package.xml`, rmw 이름은 실행 중에 읽는다.
- 모델(입력): 회전축 고정 균일 막대, 질량 `m=2 kg`, 길이 `L=1 m`, `g=9.81 m/s²`, 축 기준 관성 `I=mL²/3`,
  질량중심 `L/2`. 초기 관절각·각속도는 글의 `K₀`, `U₀`에서 실행 중에 역산한다(`U=m g (L/2)(1−cosθ)`, `K=½Iθ̇²`).
  종료시간 `T=10 s`. 댐핑 실행은 관절 점성 댐핑 `b=0.02 N·m·s/rad`.
- 적분기: 전진 오일러(`fe`), 준암시적 오일러(`se`, 속도 먼저), RK4(`rk4`), implicit 오일러(`ie`, 뉴턴 반복).
  `h = 4, 2, 1 ms` (h, h/2, h/4). 댐핑 실행은 `fe`, `rk4`만. 비보존 일 `W_nc=∫−bθ̇² dt`는 같은 적분기로 상태에 덧붙여 적분한다.
- 노드 두 개를 한 프로세스의 executor가 백그라운드 스레드에서 돌린다.
  - `link_sim`: 실행 하나를 끝까지 적분하며 매 스텝 자기 에너지를 계산해 전체 스텝 기준 통계(최대 편차, 부호 변화 횟수,
    전후반 최대 편차 비, 상승 영교차로 잰 평균 주기, 적분 CPU 시간)를 낸다. 그다음 0.1 s마다의 상태를 로그처럼 내보낸다:
    `/tf`에 `world → com_<실행>`(질량중심 위치·자세, stamp=시뮬레이션 시각), `/link_state`에
    `Float64MultiArray[실행 번호, 샘플 번호, t, θ, θ̇, W_nc]`.
  - `energy_monitor`: `TransformListener`가 채운 `tf2_ros.Buffer`에서 그 stamp의 질량중심 높이 `z`를 조회해 `U`를,
    상태 토픽의 `θ̇`로 `K`를 계산한다. 즉 에너지는 적분기를 모르는 별도 노드가 로그만으로 계산한다.
    한 샘플을 받을 때까지 기다린 뒤 다음 샘플을 보낸다(락스텝, `threading.Condition`).
- 판독값(각 실행): `ΔE(T)`, 퍼센트, 전체 스텝 `max|ΔE|`와 0.1 s 로그 `max|ΔE|`, 최대 시각, `|ΔE(T)|/max|ΔE|`,
  마지막 2초 안의 최소 `|ΔE|`/`max|ΔE|`(`min2s`: 종료시간을 조금만 옮겨도 종점 값이 얼마나 달라지는지),
  부호 변화 횟수, 선형 추세 기울기, 후반/전반 최대 편차 비, 모니터와 시뮬레이터의 `ΔE(T)` 차이(ROS 경로가 값을 바꾸지 않는지).
- 이력(`series`): `h=4 ms` 네 적분기의 모니터 `ΔE`를 1 s 간격으로 출력한다(글의 정성 그래프에 대응하는 실측 이력).
- 수렴: 같은 적분기에서 `max|ΔE|(h)/max|ΔE|(h/2)`와 `(h/2)/(h/4)` 비율, log₂ 관측 차수.
- 궤적: 기준 궤적은 같은 모델의 RK4 `h=1/16 ms`(실행 중 계산)다. 0.1 s 샘플의 `max|θ−θ_ref|`, `|θ(T)−θ_ref(T)|`,
  평균 주기 차이를 잰다. 기준 궤적 자체의 에너지 드리프트도 출력한다.
- 영점(질문 4): 같은 로그에서 `U`의 영점을 최저점·회전축·최저점+100 J로 바꿔 `E₀`, `ΔE(T)`, 퍼센트, `ΔE/E_scale`을 계산하고
  세 `ΔE`의 최대 차이를 출력한다.
- 실수 재현(질문 6): RK4 무마찰 3개 실행의 같은 로그에서 모니터가 (a) `K`를 질량중심 관성 `mL²/12`로 계산,
  (b) `U` 부호 반전, (c) `θ̇`를 한 샘플(0.1 s) 앞선 stamp의 TF 높이와 짝지음 — 세 경우의 `max|ΔE|`와 `h` 비율을 잰다.
- 스크립트의 숫자는 모두 입력·제한값이다(질량, 길이, g, `K₀`, `U₀`, `h`, 샘플 간격, 댐핑, 영점 상수, 대기 상한).
  결과 숫자는 적지 않는다. 출력은 `kind` 필드가 있는 JSON 줄이며, 하네스가 stdout 끝 8000자만 보관하므로
  유효숫자 4자리로 줄이고 열 이름+배열로 압축한다.

## 판정 기준

- 질문 1~2: `run` 줄의 `dE_T` 부호와 `order` 줄의 비율을 그대로 읽는다. 비율이 h마다 1보다 크게 유지되면 "수렴".
- 질문 3: `sgn`(부호 변화)와 `h2h1`(후반/전반)이 누적(`h2h1`>1, 부호 변화 적음)인지 진동인지 판정한다.
  `mxS/mxF`가 1보다 작으면 로그 간격이 최대 편차를 놓친 것이다. `min2s`가 0에 가까우면 종점 하나로 판정하는 위험이 크다.
  `series`(1 s 간격)만 보고 누적·진동을 판정하지 말고 전체 스텝 지표(`sgn`, `h2h1`, `slope`)와 대조한다.
- 질문 4: `zero` 줄에서 세 `dE`가 같고(float 차이만), `pct`가 다르고, `scaled`가 같은지 본다.
- 질문 5: `damped` 줄에서 `dE_T`가 h마다 0이 아닌 한 값으로 모이고 `resid`가 비율 1 초과로 줄어드는지 본다.
- 질문 6: `bug` 줄의 비율이 1 근처면 "h를 줄여도 개선되지 않음".
- 질문 7: `run` 줄의 `mxF`(에너지)와 `thE`(관절각), `perE`(주기)를 적분기 사이에서 대조한다.
- 대기 시간 초과(`timeouts`)가 0이 아니면 그 결과보다 이 사실을 먼저 보고한다.
- 예측과 다르면 결과를 그대로 보고하고 글의 설명을 결과에 맞춘다.

## 한계

- 물리 엔진(Gazebo, MuJoCo, Drake)이나 실물 로봇이 아니다. 한 자유도 진자 방정식을 Python으로 적분해 ROS 2 토픽·TF로 전달했을 뿐이다.
  접촉, 관절 한계, 제약 솔버, 다자유도 결합, 강성 문제는 다루지 않는다.
- SciPy `solve_ivp` 같은 적응형 솔버는 ros-base 이미지에 없어 측정하지 않았다(글의 `atol/rtol` 주장은 검증 범위 밖).
- 결과는 이 모델·초기조건·`T=10 s`에 한정된다. 관측 차수와 부호를 다른 로봇이나 다른 엔진으로 일반화하지 않는다.
- 시간은 stamp로 정한 시뮬레이션 시각이다. `/clock`, `use_sim_time`, 통신 지연은 재지 않는다. CPU 시간은 1 CPU 컨테이너의
  Python 반복문 시간일 뿐이다.
- 실물 장치를 움직이는 단계가 없으므로 정지 절차가 필요한 동작은 없다.

## 시행착오

- 하네스(`--try`)는 plan.md가 없으면 실행을 거부하므로 이 계획을 시험 실행 전에 썼다.
- 설계 단계: 같은 저장소 `robot-simulation-timestep-position-error` 실험 기록에서 두 가지를 가져왔다. `/tf`는 VOLATILE이라
  구독 매칭 전에 보낸 첫 TF가 버려질 수 있어 구독자가 그래프에 보인 뒤 시작한다. 바쁜 대기 폴링은 1 CPU에서 executor와
  GIL을 다퉈 느려졌으므로 `threading.Condition`으로 기다린다.
- 설계 단계: 매 적분 스텝을 ROS로 보내면 최대 10000스텝×여러 실행이 되어 60초를 넘길 수 있다. 그래서 전체 스텝 통계는
  시뮬레이터 노드가 직접 계산하고, ROS로는 0.1 s 샘플만 보낸다. 이 차이를 숨기지 않고 질문 3의 측정 대상으로 삼았다.
- 설계 단계: 처음 고른 `h = 10, 5, 2.5 ms`는 전진 오일러가 10초 안에 에너지를 크게 불려 막대가 넘어갈(회전 운동으로 바뀔) 수
  있다고 보고 `4, 2, 1 ms`로 낮췄다. 이 판단은 손 추정이며 실제 값은 결과로만 말한다.
- 설계 단계: 실행마다 시각이 0부터 다시 시작하므로 같은 child frame에 과거 stamp를 다시 넣으면 tf2가 오래된 데이터로
  경고·무시할 수 있다. 실행마다 child frame을 따로 둔다(`com_<실행>`). 버퍼 보관 시간은 30 s로 늘렸다.
- 설계 단계: tf2에서 stamp 0 조회는 "가장 최근 변환"을 뜻한다(같은 저장소 timestep 실험 기록). 한 샘플 어긋난 시점 실수(질문 6c)가
  t=0을 조회하면 엉뚱한 최신 값을 받으므로 모든 샘플 stamp를 1 s 뒤로 밀었다(`STAMP_OFFSET_NS`). 시뮬레이션 시각 `t`는 그대로다.
- 시험 실행 1회차(`--try`): 종료 코드 0, 대기 시간 초과 0, stdout이 8000자 안에 들어갔다. 측정 항목을 두 개 더했다.
  종점 위치 민감도(`min2s`)와 1 s 간격 이력(`series`)이다. 글이 "종점 하나가 전체 거동을 숨긴다", "그래프로 누적과 진동을 구분한다"고
  주장하는데 1회차 출력만으로는 이를 직접 읽을 수 없었다.
- 시험 실행 2회차: 측정은 끝까지 출력됐지만 종료 시 `terminate called without an active exception`과 함께 종료 코드 139가 났다.
  executor 스핀 스레드가 도는 중에 노드를 파괴한 순서 문제로 보고, `rclpy.try_shutdown()` → 스레드 join → executor 종료 → 노드 파괴로
  바꿨다. 그러자 스핀 스레드가 정상 종료 신호(`ExternalShutdownException`) traceback을 stderr에 남겨, 그 예외만 잡도록 했다.
  측정 코드는 바꾸지 않았다.
- 시험 실행 3~6회차(종료 순서 수정 후): 4회 모두 종료 코드 0, 대기 시간 초과 0이었지만 stderr에 위 traceback이 남았다.
- 시험 실행 7~9회차(예외 처리 후): 3회 모두 종료 코드 0, stderr 비어 있음, 대기 시간 초과 0. 컨테이너 기동을 포함해
  한 번 실행이 60초보다 훨씬 짧았다.
- 시험 실행에서 본 판독 주의점(수치는 옮기지 않음): 준암시적 오일러의 1 s 간격 `series`는 한 방향으로 쌓이는 것처럼 보였다.
  반면 같은 실행의 전체 스텝 지표(부호 변화 다수, 후반/전반 최대 편차 비 약 1)는 제한된 진동을 가리켰다. 에너지 오차의 진동 주기가
  1 s 샘플 간격과 거의 맞아 생긴 겉보기 추세(aliasing)로 보인다. 그래서 본문은 1 s 이력만으로 누적이라 쓰지 말고 전체 스텝 지표와
  함께 써야 한다. 이 현상은 글의 "출력 저장 간격과 내부 적분 스텝을 혼동하지 않아야 한다"는 경고의 실제 사례로 다룰 수 있다.
- 시험 실행의 수치는 이 문서에 옮기지 않는다. 본문의 실측 숫자는 하네스 정식 실행의 `results.json`만 근거로 한다.
