# 실험 계획: 매 에피소드 reset(seed=42) vs 한 번만 seed vs seed 목록

## 질문

평가 루프에서 에피소드마다 `env.reset(seed=42)`를 부르면 20 에피소드 중 서로 다른 시작이 몇 개인가?
그 루프의 성공률 추정값은 seed를 처음에 한 번만 줄 때나 에피소드마다 다른 seed를 줄 때보다 얼마나 흩어지는가?
성공률 숫자만 보고 이 실수를 알아챌 수 있는가?

## 무엇을 실행하는가 (범위)

- **Gymnasium·MuJoCo·Gymnasium-Robotics(Fetch)를 실행하지 않는다.** 하네스 이미지(`ros:jazzy-ros-base`, 네트워크 없음)에는 Gymnasium이 없고 설치할 수 없다.
- 대신 Gymnasium 1.4.0의 시딩 경로를 numpy로 그대로 따라 한 장난감 2차원 목표 도달(reach) 환경을 쓴다.
  - `np_random(seed)`: `SeedSequence(seed)` → `PCG64` → `Generator` (research.md의 `seeding.np_random` 확인 내용과 같은 경로).
  - `reset(seed=정수)`: PRNG가 이미 있어도 새로 만든다. `reset()`(seed=None): 기존 PRNG를 이어서 쓰고 `np_random_seed`를 바꾸지 않는다.
  - reset에서 목표 위치를 `np_random.uniform(-0.15, 0.15, size=2)`로 뽑는다(Fetch `_sample_goal`과 같은 방식, 범위 값은 설계 선택).
  - 그리퍼는 원점에서 출발하고, 결정적 정책은 목표 방향으로 step마다 최대 0.01 이동한다. 목표 거리 < 0.05면 성공하고 에피소드가 끝난다.
  - 어려운 조건(hard)은 시간 제한 8 step, 쉬운 조건(easy)은 20 step이다.
- ROS 2 부분: 환경 노드(`toy_reach_env`)가 에피소드 시작 관측값을 `std_msgs/Float64MultiArray`로 `episode_start` 토픽에 발행하고,
  별도 평가 노드(`start_counter`)가 **받은 메시지만으로** 서로 다른 시작 수를 센다. research.md가 권한 점검법
  ("에피소드별 첫 관측값을 기록해 서로 다른 값이 몇 개인지 센다")을 토픽 기록으로 해 보는 것이다.
- 네트워크 없음, 1 CPU, 외부 패키지는 이미지에 있는 rclpy·std_msgs·numpy만 쓴다.

## research.md 기준 예측값 (실행 전에 적음)

- 루프 A(매번 같은 seed): 서로 다른 시작 1개, 서로 다른 시작 비율 1/20 = 0.05. 성공률은 0 또는 1만 나온다.
- 루프 B(한 번만 seed)·C(seed 목록): 서로 다른 시작 20개.
- 성공률 추정 분산: 독립 시작 n개면 p(1−p)/n. research.md 예시 p=0.6이면 n=20에서 0.012, 실질 n=1에서 0.24, 배율 20.
  표준오차 배율은 √20 ≈ 4.47.
- p=1(항상 성공)이면 어느 루프든 분산 0이고 성공률이 같아 실수가 숫자에 드러나지 않는다.
- 같은 seed로 평가 전체를 다시 실행하면 A와 B 모두 같은 숫자가 나온다(재현성은 같다).
- 루프 B 주의점: step에서도 같은 PRNG를 쓰는 환경이면 정책이 바뀔 때 이후 시작 순서가 바뀔 수 있다. 루프 C는 영향을 받지 않는다.
- 이 장난감 환경 고유의 기하 예측(실험 설계자의 산술, research.md 값이 아님):
  - hard: 8 step × 0.01 + 0.05 = 0.13 안의 목표만 성공하므로 p ≈ π·0.13²/0.3² ≈ 0.59.
  - easy: 20 step × 0.01 + 0.05 = 0.25 > 정사각형 모서리 거리 √2·0.15 ≈ 0.212이므로 p = 1.

## 무엇을 어떻게 재는가 (출력 JSON 줄의 `measure`)

1. `seeding_rule`: 같은 환경에서 `reset(seed=42)` → `reset()` → `reset(seed=42)`, 그리고 새 환경의 `reset(seed=42)`를 비교한다.
2. `p_reference`: 조건별로 seed 7을 한 번 주고 20000 에피소드를 이어 실행해 성공 확률 p̂와 표준오차를 잰다.
3. `ros_link`, `single_eval`: seed 42, 20 에피소드 평가를 조건 2개 × 루프 3개로 한 번씩 실행한다. 받은 메시지 수,
   로컬 기록과 토픽 기록의 서로 다른 시작 수, 성공률, 평가 후 `np_random_seed` 값을 기록한다.
4. `rerun_same_seed`: seed 42로 평가 전체를 5번 다시 실행해 루프 A·B의 성공률이 매번 같은지 본다.
5. `repeated_eval`: 기준 seed를 바꿔 가며 20 에피소드 평가를 1000번 반복하고, 루프별 성공률 추정값의 표본 분산(ddof=1),
   0 또는 1만 나온 비율, 나온 값의 종류 수를 잰다. 2번의 p̂로 계산한 p(1−p)/20, p(1−p)/1과 나란히 출력한다.
   - A: 반복 r마다 seed 1000+r을 매 에피소드 재사용. B: seed 1000+r을 처음에 한 번. C: 10000000+20r+i(반복끼리 겹치지 않음).
6. `variance_ratio`: hard 조건의 분산 비 A/B, C/B.
7. `policy_change_start_order`: 25 step 환경에서 이동 속도가 다른 두 정책(0.010, 0.007)을 seed 42로 평가해,
   20개 시작 중 두 정책이 같은 시작을 받은 수를 센다. step 잡음 없음(slip 0, Hopper처럼 reset에서만 PRNG 사용)과
   step 잡음 있음(slip 0.004, FrozenLake 미끄러짐처럼 step에서도 PRNG 소비)을 루프 B·C로 비교한다.
8. `runtime`: 전체 실행 시간(초).

## 판정 기준

- 루프 A의 서로 다른 시작이 1이 아니거나, B·C가 20이 아니면 예측이 틀린 것이다.
- hard 조건에서 분산 비 A/B가 20 근처(반복 1000번의 표본 오차 범위)가 아니면 p(1−p)/n 모델이 이 환경에 맞지 않는 것이다.
- easy 조건에서 세 루프의 성공률이 모두 같으면 "성공률만으로는 루프 A 실수를 알아챌 수 없다"가 확인된 것이고,
  이때 서로 다른 시작 수(1 대 20)가 실수를 드러내는지 함께 본다.
- 토픽으로 받은 메시지가 20개보다 적으면 그 `single_eval` 줄의 토픽 기준 개수는 쓰지 않는다.

## 한계

- 장난감 환경이다. 시작 무작위성이 목표 위치 하나뿐이고, 정책과 동역학이 결정적이라는 research.md의 가정을 일부러 만족시킨 설계다.
  MuJoCo 접촉 물리, 확률적 정책, PRNG 밖의 상태(LunarLander-v2 버그 같은 경우)는 다루지 않는다.
- p≈0.59와 p=1은 이 환경의 설계로 정해진 값이며 실제 로봇 정책의 성공 확률이 아니다.
- 실제 하드웨어는 쓰지 않는다. 시뮬레이션 평가 결론이다.

## 시행착오

- 첫 시험 실행(`--try`)은 실패 없이 끝났다(종료 코드 0, 약 5초, ROS 2 구독 연결과 메시지 20개 수신 정상).
- 시험 실행 뒤 고친 점 하나: 처음 버전은 easy 조건의 p를 코드에 1.0으로 적어 `predicted_var_*` 계산에 넣었다.
  결과 숫자를 미리 적는 것과 같아서, easy 조건도 hard처럼 20000 에피소드로 p̂를 실행 중에 재도록 바꿨다.
