### 4-1. QUESTION_END (질문 소제목) — 오탐 22건 / 일치 110건 (20%)

현재: `(\?|나|까|가|지|요|할까|될까|는지)$`. 받침·단어를 보지 않고 마지막 한 글자만 본다.

**오탐 (질문이 아닌데 질문으로 셈)**
- `지` 16건 전부 오탐: "가입 조건 4가지", "계산 예시 3가지"(×3), "비과세 요건 4가지", "투자설명서에서 먼저 볼 7가지", "할부로 차를 살 때 먼저 따질 다섯 가지", "구청 공영주차장은 1~5급지", "비정품 배터리 메시지", "시외노선 우등 할인과 프리미엄 마일리지", "연간 지원 시간 한도와 중복 금지", "환불 기준과 연간 중도 해지", "의무가입기간 3년과 중도해지" 등
- `가` 6건 오탐: "2026년 MRI 건강보험 수가", "2026년 대장내시경 수가", "2026년 치석제거·진찰료 단가", "매도 손익과 손익분기 매도가", "청소년 드림·힘내라 청춘·온라인 특가", "할인가·할인율 역산·할인 전 정가"
- `요`: 이번 표본에선 소제목 오탐 0건이지만 "개요/필요/중요"로 끝나면 오탐한다(본문 문장 "지니뮤직 요금제 개요"가 해요체로 잡힌 사례 있음, 4-2).
- 질문하신 사례: "지급일과 신청"은 맞게 안 잡힌다(정상). "노인일자리 가" 같은 소제목은 표본 101편에 없었다(공개 1682의 H2에도 없음). 다만 현 정규식은 "…가"로 끝나면 무엇이든 질문으로 세므로 그런 소제목이 생기면 오탐한다.
- `나` 56건은 손으로 본 범위에서 모두 진짜 질문("…받나", "…어디서 보나")이었다. 단 "하나"로 끝나면 오탐 가능.

**미탐 (질문인데 못 셈)**
- "내 본인부담금은 얼마일까요? (계산기)" (1919) — 끝 괄호 때문
- "금 시세는 어디서 보나: KRX 원/g" (2040) — 콜론 뒤 꼬리 때문
- "한 권당 얼마인지 계산하기" (A_1898)는 질문형이 아니므로 미탐 아님(정상).

**수정 제안** (`proposed_fixes_check.py`에 구현, 위 오탐 12개·정탐 12개 assert 통과)
```python
Q_TAIL = re.compile(r"\s*(\([^()]*\)|:.*)$")          # 끝 괄호·콜론 꼬리 제거
STOP_END = ("단가", "하나", "개요", "필요", "중요")
def is_question(h):
    h = Q_TAIL.sub("", h).strip()
    if h.endswith("?"): return True
    if h.endswith(STOP_END): return False
    if re.search(r"(나|까|는지|인지|[나까가죠]요)$", h): return True        # 맨 '지'·맨 '요' 삭제
    return h.endswith("가") and (ord(h[-2]) - 0xAC00) % 28 == 4          # '가' 앞 글자 받침 ㄴ만(인가·다른가·비싼가)
```
주의: 콜론 앞이 질문이 아닌 "비교 기준: 어떤 요금제를 골랐나"는 이 수정으로 오히려 놓친다. 콜론 처리는 "앞 또는 뒤가 질문이면 질문"으로 두 쪽을 다 보는 편이 낫다(미구현).

### 4-2. tone() 말투 분류

전체 KO 101편 문장 11,412개: 해라체 9,974 / other 1,124 / 합니다체 299 / 해요체 15.

**미탐·오분류**
1. **끝 괄호** 87문장: "…셈입니다(중간값 재료면 457,700원)." → `rstrip`이 `)`만 지워 "…원"으로 끝나므로 other. 합니다체로 쓴 1919에서 합니다체가 덜 잡힌다. 해라체 글도 "…다(지침 제17조)." 같은 문장이 other로 빠진다.
2. **"~자" 청유형 해라체** 약 180문장("확인하자" 106, "보자" 40, "넣자" 11, "두자" 10…) → other. 해라체 비율을 과소 집계한다.
3. **날짜 마침표에서 문장이 끊김**: `(?<=[.?!])\s+`가 "2026.1.1. 기준"에서 자른다. "국민건강보험법 시행령 별표 2(2026.9.15." 같은 조각이 문장 1개로 들어가 other로 셈(1919에서만 3건).
4. **폼 라벨이 문장으로 셈**: 계산기 안의 `<p>` 라벨("갚을 금액(원)", "처음 넣는 원금(원)", "자료 확인일: … 기준")이 문장으로 들어가 other가 된다. 말투 비율 분모와 평균 길이를 흐린다.
5. **해요체 오탐**: "지니뮤직 요금제 개요" → 해요체(2건). "필요."로 끝나는 메모형 문장도 같은 문제.
6. **인용문**: 큰따옴표 안 문장의 어미로 판정한다. 예: 2276 `프리패스 티켓도 "시행하고 있지 않습니다".` → 해라체 글인데 합니다체로 셈. 2304 공지 전문 인용 → 합니다체. D_1609 `"…동일한 세대로 본다".` → 해라체. 표본 전체에서 14문장이라 점수 영향은 작다. 1919 노트가 말한 "인용문 안 '…제외한다'"는 `<p>` 밖(목록 등)에 있어 채점 대상이 아니었다.
7. **~습니다 vs ~니다**: `endswith("니다")`로 습니다·입니다·합니다를 모두 잡는다. 오분류 없음(정상).
8. **"~해 보세요"를 해요체로 셈**: 1919의 해요체 5문장이 전부 "~해 보세요/물어보세요"다. 기준 문서 §3-2는 A그룹 합니다체 블로거도 "확인해 보세요"로 맺는다고 적었으므로, 권유형 "~세요"는 합니다체 글 안에서 감점하지 않는 편이 기준과 맞다(정책 판단 필요).

수정 제안(구현·assert 통과): 끝 괄호 주석 제거 후 판정, `"다","자"`를 해라체로, STOP_END는 other로, 문장 분리는 `(?<!\d\.)(?<=[.?!])\s+`.
효과(1919 합니다체 비율): 0.860 → 0.897, 문장 129 → 126. 1916·2070·1925는 변화 없음(원래 해라체).
인용문 제외·폼 라벨 제외는 **미구현**(따옴표 안 구간 제거, 계산기 `<div>` 안 `<p>` 제외가 필요).

### 4-3. template_flags

1. **closer 미탐 (가장 큰 버그)**: 정규식이 `에 확인하자\.?$`라서 "…을/를 (다시) 확인하자"를 못 잡는다. 예약 글 대부분이 "결제 전에 공식 홈페이지에서 **다시 확인하자**", "가입 전에 결제 화면의 **금액을 확인하자**"로 끝난다. `확인하자\.?$`로 바꾸면 예약 9 → 47편, 공개 4 → 15/16편. 그래도 1956·1994·2046처럼 마지막 `<p>`가 면책 문장("…권하지 않는다")이고 closer가 바로 앞 문단에 있는 글은 놓친다 → 마지막 3개 문단을 보도록 바꾸길 권한다.
2. **opener 미탐**: 날짜 없이 시작하는 "…이용약관(2026년 9월 2일 시행)으로 가격과 조건을 확인했습니다." (1941, 1966, 2043) 3편. 수정: 첫 문단이 `확인했습니다\.?$`로 끝나면 플래그(날짜 조건 삭제). 적용 시 74 → 77편.
3. **faq_exactly_7이 너무 좁음**: FAQ 8개 12편(1963·2043·2276·2279·2295·2301·2310·2316·2360·2363·2369·2372), 6개 5편(2076·2191·2210·2282, 공개 1609)은 같은 틀인데 플래그도 없고 FAQ 점수 10점도 받는다. "6~8개"이거나 "자주 묻는 질문 고정 소제목과 함께 나오는 FAQ"로 넓히길 권한다.
4. **checked_box 오탐 가능성**: 기준 문서 §6-4-1은 자료 확인일 상자를 "한 줄 메타 정보로 줄인다"고 권하는데, 규칙은 "자료 확인일" 문자열이 어디 있든 플래그한다. 권고대로 한 줄로 줄여도 감점된다. 현재 표본에선 이 경우가 없어 실제 오탐 0건.
5. **반복 소제목 미탐(참고)**: "가족 구성별 예시 계산"(9편), "연령 기준과 무료 대상"(6편), "일행별 예시 계산"(5편)이 여러 글에 똑같이 나온다. template_flags는 고정 4개만 보므로 못 잡는다. 글 사이 중복은 `analyze_posts`(공개 글 전체 감사)의 몫이지만, `--files` 사전 점검에는 빠져 있다.

### 4-4. EN 채점 (score_en)

1. **opener 미탐 7/8**: "Short answer:" 문단이 맨 앞 `<pre>` 오류 출력과 첫 설명 문단 **뒤**(두 번째 `<p>`)에 있어 `paragraphs[0]`만 보는 규칙이 놓친다. 1732만 잡힘. 수정: `any(p.startswith("Short answer") for p in parser.paragraphs[:3])`.

### 4-5. 점수식 구조 문제

1. **FAQ 이중 감점**: faq_exactly_7은 rules에서 −8, faq 항목에서 −10으로 두 번 깎인다(EN의 faq_exactly_5도 같음). FAQ 7→8개로 바꾸기만 해도 +18점이라, 틀을 그대로 두고 숫자만 바꾸는 쪽으로 유도한다.
2. **rules 바닥 포화**: 플래그 5개 이상이면 rules가 0점에서 멈춘다. 예약 글 대부분이 5~6개라 플래그를 1~2개 없애도 점수가 안 오른다. 개선 추적용으로는 감점을 플래그 종류별 가중치로 나누거나 바닥을 없애는 편이 낫다.
3. 질문 소제목 비율 분모에 고정 소제목 3개가 들어가, 고정 소제목을 둔 채로는 질문 소제목 점수가 최대 약 15/20이다(의도된 동작일 수 있음).
