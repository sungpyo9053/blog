WordPress 글 생성 응답이 정상인지, 언제 재시도할지, 목록을 빠짐없이 가져왔는지 확인하는 작은 도구입니다. 서버 주소나 계정 없이 예제를 먼저 실행할 수 있습니다.

검사는 입력한 값만 사용합니다. 사이트에 접속하거나 글을 생성하지 않습니다. 민감한 응답을 그대로 붙여 넣지 말고 비밀번호·토큰·개인정보를 제거하세요.

응답 검사를 쓸 때

글 생성·수정 요청 직후 HTTP 상태와 Content-Type, 본문을 각각 복사합니다. HTML 200 예제는 JSON이 아닌 성공 응답을 거절하고, JSON 201 예제는 양의 정수 ID와 공개 상태를 확인합니다. 수정 요청이면 예상 ID도 넣어 다른 글의 응답을 잡아내세요.

초안 저장이 목적이었다면 draft는 올바른 결과일 수 있습니다. 이 도구는 공개 발행을 확인하므로 draft·pending·future를 통과시키지 않습니다. 통과 후에도 글 ID를 다시 조회하고 비로그인 공개 페이지의 제목과 본문을 확인해야 합니다. 브라우저 버전은 공개 상태까지 검사하며, 저장소의 오프라인 Python 명령은 글 객체의 ID 검증까지만 수행합니다.

목록 검사에서 건수만 맞으면 끝인가요?

아닙니다. WordPress REST 목록의 페이지당 최대 개수는 100이며, 응답 헤더의 X-WP-Total과 X-WP-TotalPages로 조회 범위를 확인할 수 있습니다. 공개 글과 초안은 같은 인증·상태·검색 조건으로 각각 모아야 합니다. 수집 도중 글이 추가·수정되면 중복이나 누락이 생길 수 있으므로 고유 ID와 수집 시점도 기록하세요. 이 도구는 입력 목록의 건수와 중복을 확인할 뿐 서버의 전체 목록을 알고 있지는 않습니다.

대기 시간을 계산한 다음

Retry-After는 정수 초 또는 HTTP 날짜일 수 있습니다. 이 계산기는 GMT의 표준 날짜 형식을 받으며, 브라우저 기준 시각을 사용합니다. 값이 잘못됐다고 즉시 반복 호출하지 말고 제한된 재시도 정책을 정하세요. 글 생성 POST가 타임아웃됐다면 이미 저장됐을 수 있으므로 기존 ID·slug 확인이 먼저입니다.
