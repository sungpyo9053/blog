When the callback is the problem, the error usually comes from inside rclcpp instead:

/opt/ros/humble/include/rclcpp/rclcpp/any_subscription_callback.hpp:394:25: error: no match for ‘operator=’ (operand types are ‘rclcpp::detail::AnySubscriptionCallbackHelper<std_msgs::msg::String_<std::allocator<void> >, std::allocator<void>, false>::variant_type’ {aka ‘std::variant<std::function<void(const std_msgs::msg::String_<std::allocator<void> >&)>, ...

Short answer: pass the message type as a template argument, a QoS (a depth like 10 is enough) as the second argument, and a callback whose parameter is one of the forms rclcpp accepts. This line compiled on Humble, Jazzy and Lyrical:

sub_ = create_subscription<std_msgs::msg::String>(
  "chatter", 10,
  [this](const std_msgs::msg::String & msg) { cb(msg); });

A lambda was the one callback form that fixed every failing case I tried. That includes passing an extra argument to the callback. std::bind(&N::cb, this, _1, 1) did not compile on any of the three distros.

If it points into any_subscription_callback.hpp or functional, the callback itself is wrong. Every row below gave the same first error on Humble, Jazzy and Lyrical. Missing QoS or template argument

Some older code calls create_subscription<T>(topic, callback) or create_publisher<T>(topic). On all three distros I tested, a QoS argument is required, and its place is right after the topic name. The fix in the accepted answer to the Foxy question is the same as mine: add a depth. 10 compiled on all three distros. The note candidate expects N arguments, 2 provided is the clue. You gave two arguments and the function needs at least three.

The message type must be given explicitly. rclcpp doesn't deduce it from the callback. Without <String> the error has no template argument in the function name (N::create_subscription(const char [8], int, ...)). Check that first if you copied the code from a web page, where text between angle brackets is easy to lose.

rmw_qos_profile_t is not a QoS

Older examples pass rmw_qos_profile_sensor_data straight to create_subscription, as in this Eloquent question. That is the C struct from rmw, and current rclcpp wants an rclcpp::QoS object. Two replacements compiled everywhere. The short one is rclcpp::SensorDataQoS(). If you need a specific rmw profile, wrap it: rclcpp::QoS(rclcpp::QoSInitialization::from_rmw(profile), profile). The error mentions const rmw_qos_profile_t& in the argument list, so this case is easy to spot.

Callback parameter forms that compile

rclcpp keeps the callback in a std::variant of std::function types, one per supported signature. If your callable doesn't match any of them, the assignment in any_subscription_callback.hpp fails with no match for ‘operator=’. I tested each parameter form with a lambda on a std_msgs/msg/String subscription:

The one that catches people is const String::SharedPtr &. It looks like a harmless way to avoid copying a shared pointer, but it is const std::shared_ptr<String> &, and that form isn't in the list. const String::ConstSharedPtr &, a reference to a pointer to a const message, is in the list. This matches the results in this 2024 question, which found that every form with a non-const & fails, and so does const SharedPtr&. The accepted answer there explains the list in terms of ownership. const Msg & means you only read the message, UniquePtr means you take ownership, and a shared pointer means you may keep a copy.

A generic lambda (auto msg) fails for a related reason. rclcpp needs one concrete parameter type to pick the variant entry, and a generic lambda's operator() is a template. The error is ‘decltype’ cannot resolve address of overloaded function in function_traits.hpp. Write the type out.

If you use std::bind with a member function, the same rules apply to that function's parameter list. void cb(const Int32::SharedPtr) bound for a String subscription gave no match for ‘operator=’, and the aka part of the message showed both message types.

Passing an extra argument to the callback

This is the most common question in the group (907 views, 434 views). People want one callback for several topics and an extra value to tell them apart. I tried three ways with void cb(const String & msg, int src):

  • std::bind(&N::cb, this, _1) failed. The standard library's own check fires first: static assertion failed: Wrong number of arguments for pointer-to-member.
  • std::bind(&N::cb, this, _1, 1) also failed, on all three distros, with no match for ‘operator=’ in any_subscription_callback.hpp. The call is correct C++ and the bind object takes one argument. The error shows the callback type rclcpp worked out from the bind expression, and it isn't one of the accepted forms. Don't spend time on std::bind for this case.
  • The lambda [this](const String & m) { cb(m, 1); } compiled everywhere.

To check that the lambda version also works at run time, I built a node with two subscriptions, chatter_1 passing 1 and chatter_2 passing 2 to the same cb, and sent one message to each with ros2 topic pub --once. On all three distros the log showed:

[INFO] [1793667092.560565545] [listener]: RT heard 'one' from 1
[INFO] [1793667093.640659970] [listener]: RT heard 'two' from 2

That is the Humble output. Jazzy and Lyrical printed the same two lines with their own timestamps.

For the topic name itself, capture it in the lambda the same way: [this, topic](const String & m) { cb(m, topic); }. I tested the int version only.

std::bind pitfalls

Two more std::bind mistakes showed up as compile errors. Forgetting _1 (std::bind(&N::cb, this)) gives the Wrong number of arguments for pointer-to-member static assertion, 89 lines of output on Humble and 202 on Lyrical. You need using std::placeholders::_1; or std::placeholders::_1 written out. With two overloads of cb (one for String, one for Int32), &N::cb is ambiguous and the error comes from std::bind itself: <unresolved overloaded function type>. A lambda that calls cb(msg) with a typed parameter compiled, because normal overload resolution picks the right one. A static_cast to the member function pointer type should also work, but I didn't test it.

The 2018 question about std::bind errors says "using lamdas as a callback function is ok in this case". In my run that held for every case.

Version notes

Every variant compiled or failed the same way on Humble (rclcpp 16.0.21, GCC 11.4), Jazzy (rclcpp 28.1.22, GCC 13.3) and Lyrical (rclcpp 32.0.3, GCC 15.2). Three things in the messages differed:

  • The argument count in the note. For a missing QoS, Humble said candidate expects 5 arguments, 2 provided and Jazzy and Lyrical said candidate expects 3 arguments, 2 provided. For create_publisher it was 3 on Humble and 2 on Jazzy and Lyrical, with 1 provided.
  • The header line. The operator= error was at any_subscription_callback.hpp:394 on Humble, :396 on Jazzy and :444 on Lyrical. Leave the line number out when you search.
  • Output length. The same callback error printed 69 lines on Humble, 60 on Jazzy and 171 on Lyrical. The bind-without-placeholder case printed 89, 85 and 202 lines.

FAQ

What causes "no matching function for call to create_subscription"?

In my run, one of three things: no QoS argument after the topic name, no message type in angle brackets, or an rmw_qos_profile_t passed where an rclcpp::QoS is expected. Add a depth such as 10, write create_subscription<T>, or use rclcpp::SensorDataQoS().

Why do I get "no match for operator=" in any_subscription_callback.hpp?

The callback's parameter isn't one rclcpp accepts, or it takes a different message type than the subscription. Forms that compiled are const T &, T, T::SharedPtr, T::ConstSharedPtr, const T::ConstSharedPtr & and T::UniquePtr, optionally with const rclcpp::MessageInfo &. T &, const T::SharedPtr & and raw pointers failed.

How do I pass an extra argument to a ROS 2 C++ subscription callback?

Use a lambda: [this](const T & msg) { cb(msg, 1); }. It compiled and ran on Humble, Jazzy and Lyrical. std::bind(&N::cb, this, _1, 1) failed to compile on all three.

Is const SharedPtr & allowed as a callback parameter?

No. const T::SharedPtr & failed on all three distros. const T::ConstSharedPtr & compiled, and so did T::SharedPtr by value.

Can I use an auto parameter in the subscription lambda?

No. A generic lambda failed with ‘decltype’ cannot resolve address of overloaded function in function_traits.hpp, because rclcpp needs a concrete parameter type to pick the callback form.
