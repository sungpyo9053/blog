This is what ros2 run printed for a Python script in an ament_cmake package when the script had no #! line. The C++ node in my mixed test package ran fine. Other mistakes in the same setup give No executable found, ModuleNotFoundError, or /usr/bin/env: ‘python3\r’: No such file or directory instead.

Short answer: ros2 run executes the installed file directly. The file must be in install/<pkg>/lib/<pkg>/, it must be executable, and its first line must be a working shebang. Any module the script imports must also be installed. This layout worked on Humble, Jazzy and Lyrical:

find_package(ament_cmake REQUIRED)
find_package(ament_cmake_python REQUIRED)

ament_python_install_package(${PROJECT_NAME})     # installs my_pkg/__init__.py, my_pkg/helper.py

install(PROGRAMS scripts/talker.py                # PROGRAMS, not FILES
  DESTINATION lib/${PROJECT_NAME})                # not bin

ament_package()
#!/usr/bin/env python3
import rclpy
from my_pkg.helper import greeting

Then run it with the file name, including .py: ros2 run my_pkg talker.py. If the script really can't have a shebang, ros2 run --prefix python3 my_pkg talker.py also worked.

What I ran

On 2026-11-16 I ran one script in the official ros:humble-ros-base, ros:jazzy-ros-base and ros:lyrical-ros-base images, one distro after another, with no network. It creates 13 ament_cmake packages. Each has a scripts/talker.py node that imports a function from its own Python module (<pkg>/helper.py), logs one line and exits. mix_good is the correct version and also has a C++ node, cpp_node. Every other package changes one thing.

For each package the script runs colcon build --packages-select, lists what landed in install/, and runs ros2 pkg executables and ros2 run. Five packages also go through ros2 launch with a Node(package=..., executable='talker.py') action. Then it repeats three packages with --symlink-install in a fresh workspace. Finally it applies the fix to each broken package, rebuilds it, and runs it again. All nine fixed packages printed their hello from ... v1 line on all three distros.

Builds were short. The mixed package with the C++ node took 6.7 s on Humble, 6.9 s on Jazzy and 7.2 s on Lyrical. A Python-only ament_cmake package took 1.3 to 2.7 s. A successful ros2 run of the Python node took 0.67 s, 0.95 s and 1.04 s. No executable found came back in 0.20 to 0.44 s.

Cause 1: the first line of the script

In an ament_python package, setuptools writes a small wrapper script for each entry point, and that wrapper has its own shebang. In an ament_cmake package nothing writes a wrapper. install(PROGRAMS ...) copies your file as it is and sets the execute bit. ros2 run then calls subprocess.Popen([path]) on that file, so the kernel has to know how to run it. Without a #! line it doesn't, and you get Exec format error. That is the error in both Robotics Stack Exchange questions linked at the end, from Foxy and Jazzy.

The same file behaved differently depending on how I started it:

CommandResult
ros2 run py_noshebang talker.pyOSError: [Errno 8] Exec format error

So if python3 file.py works and ros2 run doesn't, look at line 1. The shebang has to be the very first line, before any comment or blank line.

Two other first-line problems gave confusing messages. With Windows line endings the shebang reads python3\r. od -c on the installed file showed p y t h o n 3 \r \n, and env reported that python3\r doesn't exist. Stripping the \r (what dos2unix does) fixed it. With #!/usr/bin/python, the interpreter didn't exist: none of the three images had /usr/bin/python. Python then raised FileNotFoundError and named the script. The script was there. The missing file was the interpreter in its first line. #!/usr/bin/env python3 fixed it on all three distros.

Cause 2: the file isn't where ros2 run looks, or isn't executable

ros2 run <pkg> <name> looks only in install/<pkg>/lib/<pkg>/, and only at files with the execute bit. Four of my packages failed that check, and all four printed the same No executable found:

  • No install() rule. The build still succeeded and installed the Python module, but lib/py_noinstall/ was never created.
  • DESTINATION bin. The file went to install/py_bin/bin/talker.py. After sourcing the workspace, plain talker.py ran from PATH, but ros2 run didn't find it.
  • install(FILES ...). The file landed in the right folder as -rw-r--r--, with no execute bit, even though the source file was 755.
  • Wrong name. ros2 run mix_good talker failed because the installed name is talker.py. To drop the extension, install with RENAME: install(PROGRAMS scripts/talker.py DESTINATION lib/${PROJECT_NAME} RENAME talker) made ros2 run py_rename talker work, and then talker.py stopped working.

The quickest check is ros2 pkg executables <pkg>. It printed mix_good cpp_node and mix_good talker.py for the good package, and nothing at all, with exit code 0, for the first three cases above. If your script isn't in that list, ros2 run can't start it. The scripts with no shebang, CRLF and the wrong shebang were all listed, because the list only checks location and the execute bit.

One leftover to clean up. After I changed DESTINATION bin to lib/${PROJECT_NAME} and rebuilt, the old install/py_bin/bin/talker.py was still there. Colcon doesn't remove files that a rule no longer installs. Delete install/<pkg> if you don't want the stale copy on your PATH.

The same "No executable found" also happens in ament_python packages, for different reasons: a missing entry point or a missing setup.cfg. Those are covered in "No executable found" for ament_python.

Cause 3: the script runs but can't import its own module

Without ament_python_install_package(${PROJECT_NAME}) the build succeeded, the script was installed and executable, and it failed at its import:

Traceback (most recent call last):
  File "/ws/install/py_nomodule/lib/py_nomodule/talker.py", line 3, in <module>
    from py_nomodule.helper import greeting
ModuleNotFoundError: No module named 'py_nomodule'
[ros2run]: Process exited with failure 1

The installed script lives in lib/<pkg>/, away from your source tree, so the module has to be installed too. Running the source file from the package folder didn't help either. cd src/py_nomodule && python3 scripts/talker.py gave the same ModuleNotFoundError, because Python puts scripts/ on the path, not the package folder. Adding ament_python_install_package(${PROJECT_NAME}) and rebuilding fixed it.

The function installs the folder with the same name as its argument. That folder needs an __init__.py. Without one, CMake stopped with the Python package folder '/ws/src/py_noinit/py_noinit' doesn't contain an '__init__.py' file on all three distros. That was the only build failure in the whole run. Since the package was never installed, ros2 run then said Package 'py_noinit' not found. An empty __init__.py fixed it.

Where the module went depends on the distro. On Humble it was install/<pkg>/local/lib/python3.10/dist-packages/<pkg>. On Jazzy and Lyrical it was install/<pkg>/lib/python3.12/site-packages and lib/python3.14/site-packages. Sourcing install/setup.bash put the right one on the path in all three, so you don't need to set PYTHONPATH yourself.

--symlink-install hides one mistake and creates another

With --symlink-install, the installed script is a symlink to your source file, so the source file's permissions are what count:

PackagePlain build--symlink-install
install(FILES ...), source file 755No executable foundworked
install(PROGRAMS ...), source file 644workedNo executable found

So a package that works on your machine with --symlink-install can fail in a plain build in CI, and the reverse. Use PROGRAMS and also chmod +x the source file. For the second row, chmod +x on the source file fixed it at once, with no rebuild, because the symlink points at that file.

Edits to the Python module behaved as you'd expect. After a plain build, editing helper.py in src/ changed nothing until I rebuilt (1.0 to 1.1 s). With --symlink-install the edit showed up on the next ros2 run without a rebuild.

Two things that didn't matter

Several answers say to add find_package(ament_cmake_python REQUIRED) and <buildtool_depend>ament_cmake_python</buildtool_depend>. In my run, a package without the find_package line and a package without the buildtool_depend both built, installed the module and ran, on all three distros. I didn't look into why. I'd keep both lines anyway. They cost nothing, the ament_cmake_python documentation asks for the dependency, and rosdep and build ordering in a larger workspace use package.xml, which I didn't test here. Just don't expect adding them to fix any of the errors above.

Version notes

The behavior was the same on Humble, Jazzy and Lyrical in every case. The differences were in the wording and line numbers:

  • The CRLF message came from env in a different format on Lyrical (env: $'python3\r': No such file or directory) than on Humble and Jazzy (/usr/bin/env: ‘python3\r’: No such file or directory). All three added use -[v]S to pass options in shebang lines.
  • The __init__.py error was at ament_python_install_package.cmake:66 on Humble and Jazzy and at line 77 on Lyrical.
  • On Lyrical (CMake 4.2.3), every package printed CMake Deprecation Warning at CMakeLists.txt:1 (cmake_minimum_required): Compatibility with CMake < 3.10 will be removed because my files said VERSION 3.8. The build still passed. Raising the minimum to 3.10 should remove it. I didn't test that.
  • The Python module path was local/lib/python3.10/dist-packages on Humble and lib/python3.X/site-packages on Jazzy and Lyrical.

FAQ

Why does ros2 run give OSError: [Errno 8] Exec format error for my Python node?

The installed script has no shebang. In an ament_cmake package your file is installed as it is and executed directly, so line 1 must be #!/usr/bin/env python3. Adding it and rebuilding fixed the error on Humble, Jazzy and Lyrical. ros2 run --prefix python3 also worked without a rebuild.

Why does ros2 run say No executable found for a Python script in a C++ package?

The file isn't an executable in install/<pkg>/lib/<pkg>/. In my run that came from a missing install rule, DESTINATION bin, install(FILES ...) instead of install(PROGRAMS ...), or running the name without .py. ros2 pkg executables <pkg> shows what ros2 run can find.

Why do I get ModuleNotFoundError for my own package's module?

The module wasn't installed. Add ament_python_install_package(${PROJECT_NAME}) and put an __init__.py in the folder with the package's name. Running the source file from scripts/ failed the same way.

What does /usr/bin/env: ‘python3\r’: No such file or directory mean?

The script has Windows line endings, so the shebang asks for an interpreter named python3 followed by a carriage return. Convert the file to LF and rebuild. The node then ran on all three distros.

Do I need find_package(ament_cmake_python) and the buildtool_depend?

A package without either one still built and ran on Humble, Jazzy and Lyrical in my test. They are still the documented setup, so keep them, but they won't fix the errors in this article.
