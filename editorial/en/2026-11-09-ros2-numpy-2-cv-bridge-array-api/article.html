Short answer: on Humble and Jazzy, the apt-built cv_bridge and python3-opencv were compiled against NumPy 1.x. A pip NumPy 2 earlier on the path breaks them. The fix that worked every time was to remove pip's NumPy so Python falls back to the apt one:

pip uninstall numpy        # add --break-system-packages on Jazzy
python3 -c "import numpy; print(numpy.__version__, numpy.__file__)"
# want: /usr/lib/python3/dist-packages/numpy/__init__.py

If another package needs a pip NumPy, use pip install "numpy<2". If you also need a pip OpenCV, pin it to "opencv-python-headless<4.12", because every OpenCV wheel from 4.12 on requires NumPy 2. Current OpenCV 5 wheels break cv_bridge with KeyError: 16 even when NumPy is 1.x. Lyrical is different. Its apt NumPy is 2.3.5, its cv_bridge works with NumPy 2, and numpy<2 has no wheel for its Python 3.14.

I ran the Humble script twice, and both runs gave the same table, including the segfault.

Cause 1: the apt cv_bridge and cv2 were built against NumPy 1.x

The NumPy message is misleading in one way. For cv_bridge it is printed with a traceback, but the import doesn't fail. In every NumPy 2 run, import cv_bridge exited 0, and cv_bridge.getCvType from the boost module was still there. The process dies a few lines later, when CvBridge() runs import cv2 and the apt cv2 raises ImportError: numpy.core.multiarray failed to import. That's why many tracebacks show both errors. The first comes from cv_bridge_boost, and the one that stops you comes from cv2.

If a pip OpenCV built for NumPy 2 replaces the apt cv2, the ImportError goes away and things get worse. With NumPy 2.2.6 and opencv-python 4.14.0.94, CvBridge() and cv2_to_imgmsg worked. Then imgmsg_to_cv2, which calls into the NumPy 1.x boost module, crashed the interpreter with exit code 139. There was no Python exception. That is the "may crash" in the warning. It happened in both Humble runs and on Jazzy.

The fix is to make the process load the NumPy that cv_bridge was built with:

  • pip uninstall numpy worked on Humble and Jazzy. pip only removes its own copy. On Humble it said Not uninstalling numpy at /usr/lib/python3/dist-packages, outside environment /usr and left the apt NumPy in place, which is what you want.
  • pip install "numpy<2" gave 1.26.4, and cv_bridge plus the apt cv2 worked again. It's the right choice when another pip package needs a newer NumPy than apt's 1.21.5.

After either fix, check which file is loaded. Then check it again with the interpreter your node actually runs.

Cause 2: OpenCV wheels from 4.12 on require NumPy 2, and 5.0 breaks cv_bridge

On Humble, plain pip install opencv-python printed Successfully installed numpy-2.2.6 opencv-python-5.0.0.93. NumPy 2 often arrives this way. Nobody asked for it, and it comes in as a dependency. I asked pip's resolver (a dry run with pip 26.2.2) what each OpenCV version needs:

The bridge then failed with KeyError: 16 in cv2_to_imgmsg. That error has nothing to do with NumPy. cv2.CV_8UC3 is 16 in OpenCV 4.x and 64 in the 5.0.0 wheel, while the C++ side of cv_bridge still returns OpenCV 4 type codes. It failed the same way on Lyrical, where NumPy wasn't an issue at all.

The combination that worked on Humble and Jazzy was pip install "opencv-python-headless<4.12" "numpy<2", which gave 4.11.0.86 with 1.26.4. Or don't pip-install OpenCV at all, and use the apt cv2.

Cause 3: tf_transformations depends on an old transforms3d

tf_transformations imports transforms3d, and the apt versions use NumPy names that are gone. On Humble, apt transforms3d 0.3.1 calls np.maximum_sctype(np.float). It worked only with NumPy 1.21.5 and 1.23.5. With 1.26.4 it failed on np.float, and with 2.2.6 on np.maximum_sctype. So on Humble numpy<2 fixes cv_bridge but not tf_transformations. Two things worked here: pip install transforms3d (0.4.2, ok with NumPy 2.2.6 and with 1.26.4), or numpy<1.24. Jazzy's apt 0.4.1 worked with 1.26.4 and failed with NumPy 2.5.4. Lyrical's apt 0.4.2 worked with NumPy 2.

Cause 4: pip on Jazzy and Lyrical won't replace the apt NumPy

On Jazzy and Lyrical, plain pip install stops with PEP 668's externally-managed-environment error. With --break-system-packages, pip install -U numpy and pip install opencv-python both stopped at ERROR: Cannot uninstall numpy 1.26.4, RECORD file not found. Hint: The package was installed by debian. and installed nothing. So on a stock Jazzy the system NumPy is hard to break by accident. NumPy 2 got in two ways in my runs: a venv, or --ignore-installed. Both broke things exactly as on Humble. With --ignore-installed NumPy 2.5.4, import cv2 failed with the ImportError. With opencv-python<5 the round-trip segfaulted, and with opencv-python 5.0.0.93 it raised KeyError: 16.

Be careful with uninstall on Jazzy. pip uninstall --break-system-packages transforms3d printed Successfully uninstalled transforms3d-0.4.1, and that was the apt copy. Afterwards import transforms3d failed, while dpkg still listed python3-transforms3d as installed. apt-get install --reinstall python3-transforms3d brought it back. Before you uninstall anything, check that numpy.__file__ points into /usr/local/lib or your venv.

venvs: --system-site-packages vs isolated

A venv doesn't protect you here. source /opt/ros/$DISTRO/setup.bash puts the ROS Python packages on PYTHONPATH, so every venv sees the apt-built cv_bridge. For how ROS picks the interpreter at all, see ros2 run, conda and venv: which Python your node really uses.

  • python3 -m venv --system-site-packages, nothing installed: uses the apt NumPy, and the CvBridge round-trip, point cloud and message checks passed on all three distros. After pip install -U numpy inside it (2.2.6 on Humble, 2.5.4 on Jazzy), it broke the same way as the system install. pip install "numpy<2" inside it fixed cv_bridge again.
  • Isolated venv (no system site packages): it sees ROS but not the apt NumPy, cv2 or transforms3d. Importing sensor_msgs.msg failed with No module named 'numpy'. With pip NumPy 2.2.6, cv_bridge printed the same _ARRAY_API not found message. On Humble, pip install "numpy<2" "opencv-python-headless<4.12" transforms3d made all eight checks pass. On Jazzy, the message checks also needed PyYAML (No module named 'yaml' from rclpy/parameter.py). On Lyrical, even import cv_bridge needed em (No module named 'em' from rosidl_pycommon). I didn't chase those further.

If you need a venv for something like PyTorch, --system-site-packages plus numpy<2 was the shortest setup that worked.

Which pip packages pull in NumPy 2

These come from the resolver dry run in a --system-site-packages venv that already had the apt NumPy:

  • opencv-python and opencv-python-headless: 5.0.0.93, which needs numpy>=2. Resolved NumPy: 2.2.6 on Humble, 2.5.4 on Jazzy.
  • ultralytics 8.4.191: by itself it asks for numpy>=1.23.0 on Linux. But it pulls opencv-python 5.0.0.93, so the plan included NumPy 2.2.6 on Humble and 2.5.4 on Jazzy.
  • torch 2.14.1: no NumPy requirement, and the dry run installed no NumPy.

So in these runs, "I installed ultralytics and cv_bridge broke" was really OpenCV 5 and the NumPy 2 it requires. Installing ultralytics with "opencv-python-headless<4.12" "numpy<2" in the same command is the obvious next step, but I didn't run it.

Version notes

  • Humble (Ubuntu 22.04, Python 3.10.12, pip 22.0.2): apt NumPy 1.21.5, no PEP 668. pip install -U numpy as root put NumPy 2.2.6 in /usr/local/lib/python3.10/dist-packages, ahead of apt. This is the easiest distro to break.
  • Jazzy (Ubuntu 24.04, Python 3.12.3, pip 24.0): apt NumPy 1.26.4. The breakage is the same once NumPy 2 is loaded. numpy<2 was already satisfied by apt. numpy<1.24 had no wheel for Python 3.12 (the oldest offered was 1.26.0).
  • Lyrical (Ubuntu 26.04, Python 3.14.4, pip 25.1.1): apt NumPy 2.3.5. Every check passed with apt NumPy, and also with NumPy 2.5.4 in a venv. numpy<2 found no wheel (from versions: 2.3.2, 2.3.3, ...). Don't downgrade NumPy on Lyrical. opencv-python 5.0.0.93 still gave KeyError: 16, and opencv-python<5 (4.14.0.94) worked.

FAQ

How do I fix "AttributeError: _ARRAY_API not found" when importing cv_bridge?

On Humble and Jazzy, a pip NumPy 2 is shadowing the apt NumPy 1.x that cv_bridge was built with. Run pip uninstall numpy so Python falls back to apt, or pip install "numpy<2". Then confirm with python3 -c "import numpy; print(numpy.__file__)".

Why does cv_bridge import fine but my node dies at CvBridge()?

The boost module prints the NumPy 1.x message but still loads. CvBridge() then imports cv2, and the apt cv2 raises ImportError: numpy.core.multiarray failed to import. With a pip OpenCV 4.14 instead, the process segfaulted in imgmsg_to_cv2.

I pinned numpy below 2 and still get KeyError: 16 from cv2_to_imgmsg. Why?

You have opencv-python 5.x. In it cv2.CV_8UC3 is 64 instead of 16, so cv_bridge's type table doesn't match. Uninstall it and use the apt cv2, or install "opencv-python-headless<4.12" (4.11.0.86). This happened on Humble, Jazzy and Lyrical.

Which opencv-python versions require NumPy 2?

Those I checked: 4.12.0.88 (numpy>=2,<2.3), 4.14.0.94 and 5.0.0.93 (numpy>=2). 4.10.0.84 and 4.11.0.86 accept NumPy 1.x. Asking pip for opencv-python "numpy<2" resolved to 4.11.0.86.

Does ROS 2 Lyrical have this problem?

Not with NumPy. Lyrical's apt NumPy is 2.3.5, and cv_bridge, point clouds, messages and tf_transformations all worked with NumPy 2.3.5 and 2.5.4. numpy<2 has no wheel for its Python 3.14. OpenCV 5 wheels still break cv_bridge there.
