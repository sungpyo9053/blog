Short answer: ros2 bag convert -i my_bag -o out.yaml, where out.yaml sets storage_id: mcap. On Humble you first need sudo apt install ros-humble-rosbag2-storage-mcap. Without it, the convert fails and leaves an empty output folder behind, and that folder blocks your next try. If the bag came from Jazzy, Humble can't read its metadata.yaml. Point Humble at the .mcap file itself and pass a QoS override file.

What happened when I ran it

I recorded a small bag (/chatter, std_msgs/msg/String at 10 Hz for about 5 seconds) in the official ros:humble-ros-base and ros:jazzy-ros-base Docker images on 2026-10-26. Then I converted it in both directions and opened the Jazzy bag from Humble.

1. Humble: sqlite3 → MCAP

Humble records to sqlite3 by default. Its help text says so:

-s {sqlite3,my_test_plugin}, --storage {sqlite3,my_test_plugin}
                      storage identifier to be used, defaults to 'sqlite3'

The output YAML I used:

output_bags:
- uri: h_mcap
  storage_id: mcap
  all_topics: true

On the stock image the convert fails:

$ ros2 bag convert -i h_sqlite -o to_mcap.yaml
[ERROR] [rosbag2_storage]: Could not load/open plugin with storage id 'mcap'
No storage could be initialized. Abort

The MCAP plugin is a separate package on Humble. Install it:

sudo apt install ros-humble-rosbag2-storage-mcap

(The version I got was 0.15.17.) After that, mcap shows up in --storage. But running the same convert again failed in a new way:

Database directory already exists (h_mcap), can't overwrite existing database

The first failed run had already created an empty h_mcap/ directory. Delete it (rm -rf h_mcap) and the convert works:

$ ros2 bag info h_mcap
Files:             h_mcap_0.mcap
Bag size:          5.5 KiB
Storage id:        mcap
Duration:          4.672787243s
Messages:          48
Topic information: Topic: /chatter | Type: std_msgs/msg/String | Count: 48 | Serialization Format: cdr

All 48 messages came through. The data file went from 24,576 bytes (.db3) to 4,674 bytes (.mcap). That ratio comes from a tiny test bag, so don't expect the same on a real one.

2. Jazzy: MCAP is already the default

-s {sqlite3,mcap}, --storage {sqlite3,mcap}
                      Storage identifier to be used, defaults to 'mcap'.

The MCAP plugin ships with ros:jazzy-ros-base, so there's nothing to install. Converting back to sqlite3 with storage_id: sqlite3 worked on the first try (42 of 42 messages). Bags recorded on Jazzy are already MCAP.

3. Opening a Jazzy bag in Humble

Jazzy writes metadata.yaml as version: 9. Humble writes version: 5. Pointing Humble at the bag directory fails for both info and play:

$ ros2 bag info j_mcap
Exception on parsing info file: yaml-cpp: error at line 15, column 11: bad conversion

Line 15 is offered_qos_profiles. Jazzy writes it as a YAML list with history: unknown. Humble expects it as a string. The plain info problem goes away if you pass the .mcap file instead of the directory, which skips the file Humble can't read:

$ ros2 bag info j_mcap/j_mcap_0.mcap
Files:             j_mcap/j_mcap_0.mcap
Bag size:          6.1 KiB
Storage id:        mcap

Playing it was a different story. Each of these failed with yaml-cpp: error at line 1, column 12: bad conversion and published nothing (a recorder running alongside caught 0 messages):

  • ros2 bag reindex on a copy of the .mcap. It writes a fresh version: 5 metadata.yaml and info works, but play still fails.
  • A sqlite3 bag converted from the Jazzy .mcap inside Humble. The convert reports 42 messages, but the bad QoS string comes along with them.

What worked is overriding the recorded QoS at play time:

# qos.yaml
/chatter:
  reliability: reliable
  durability: volatile
  history: keep_last
  depth: 10
ros2 bag play j_mcap/j_mcap_0.mcap --qos-profile-overrides-path qos.yaml

With that, a recorder on the Humble side got all 42 messages, both from the .mcap file directly and from the reindexed copy. If your bag has many topics, the override file needs an entry for each topic you want to play.

Gotchas

  • Delete the output folder after a failed convert. Otherwise you get "Database directory already exists" and it looks like a new problem.
  • Set all_topics: true anyway. The rosbag2 README warns that the output bag is empty if no topic selection is given. In my Humble run, a YAML with only uri and storage_id still copied all 48 messages. Your version may follow the README, so don't rely on that.
  • The -i second value is the input storage. -i bag.mcap mcap tells convert how to read the input. The output format always comes from the YAML.
  • Not tested: Humble bags played on Jazzy, Iron or Rolling, compressed bags, and multi-GB bags.

Copy-paste version

# Humble only: add the plugin
sudo apt install ros-humble-rosbag2-storage-mcap

cat > to_mcap.yaml <<'EOF'
output_bags:
- uri: my_bag_mcap
  storage_id: mcap
  all_topics: true
EOF

rm -rf my_bag_mcap          # leftovers from a failed run block the write
ros2 bag convert -i my_bag -o to_mcap.yaml
ros2 bag info my_bag_mcap
