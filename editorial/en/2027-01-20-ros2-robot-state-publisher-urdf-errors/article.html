That's Jazzy. Humble prints the same lines with line 206. Lyrical logs the middle line as a warning from the [urdf] logger. Run it with ros2 run instead of a launch file and the last line reads [ros2run]: Aborted.

Short answer: robot_state_publisher got a string it couldn't build a robot from, and it exits right away. The first Error: line names the real problem. Failed to parse robot description and Unable to initialize urdf::model come after it every time, so they don't tell you anything. "No link elements found" almost always means the parser never saw a <link>. Either the xacro file was passed in without running xacro, or the links sit inside a macro that is never called. This launch setup worked on Humble, Jazzy and Lyrical:

from launch import LaunchDescription
from launch.substitutions import Command
from launch_ros.actions import Node
from launch_ros.parameter_descriptions import ParameterValue

def generate_launch_description():
    desc = ParameterValue(Command(['xacro ', '/path/to/robot.urdf.xacro']), value_type=str)
    return LaunchDescription([Node(
        package='robot_state_publisher', executable='robot_state_publisher',
        parameters=[{'robot_description': desc}], output='screen')])

Before you change anything, run xacro robot.urdf.xacro > /tmp/out.urdf and then check_urdf /tmp/out.urdf. In my runs check_urdf printed the same Error: line as robot_state_publisher for each of the seven broken models I gave it. An empty file was the exception: robot_state_publisher checks for an empty string before it parses.

What I ran

On 2026-11-15 I used ros:humble-ros-base, ros:jazzy-ros-base and ros:lyrical-ros-base on a 2 vCPU Linux host, one distro at a time. In each container I installed robot_state_publisher, xacro and liburdfdom-tools (for check_urdf) from apt. I started from one valid URDF with three links (base_link, laser, wheel), a fixed joint and a revolute joint. Then I broke it one way at a time.

Each of 36 cases per distro ran robot_state_publisher for up to 6 seconds. Most passed the URDF through a params file written with yaml.safe_dump, so YAML quoting couldn't interfere. Others used -p, a positional argument, or one of seven launch files. I also ran check_urdf on ten files. For the valid URDF I also checked what the node publishes: /tf_static, /robot_description and /tf after a /joint_states message. Finally I changed robot_description while the node was running.

No link elements found: xacro was not run, or the macro was not called

I got this error from three inputs, on all three distros:

  • The raw .xacro file text passed as robot_description. The links in my file sat inside a xacro:macro. To the URDF parser a macro body is just an unknown element, so it found no top-level <link>.
  • A xacro file where the links are inside a macro that is never called. xacro exited with 0 and wrote a <robot> with zero <link> lines. Then robot_state_publisher failed. Running xacro didn't help here, because the output really has no links.
  • The same file through Command(['xacro ', path]) in a launch file. xacro succeeded, and the node died with exit code -6.

check_urdf on the raw .xacro file also printed No link elements found in urdf file, which is the confusing case in check_urdf fails stating no link elements found. check_urdf doesn't expand xacro, so run xacro first and check its output. A quick test: xacro robot.urdf.xacro | grep -c '<link'. In my runs that printed 0 for the uncalled macro and 2 once the macro was called.

Error document empty: you passed a path, not the URDF

Setting robot_description to a file path is a common mistake, either '/w/n_humble/valid.urdf' in a params file or {'robot_description': path} in a launch file. The parser tries to read the path itself as XML. Humble printed Error document empty.. Jazzy and Lyrical printed Error=XML_ERROR_PARSING_TEXT ErrorID=8 (0x8) Line number=1. Both then printed Unable to initialize urdf::model from robot description.

Pass the contents instead. Both of these launch files started the node and logged Robot initialized (on Humble, got segment base_link and so on) on every distro:

# plain URDF
desc = open('/path/to/robot.urdf').read()
# xacro
desc = ParameterValue(Command(['xacro ', '/path/to/robot.urdf.xacro']), value_type=str)
...
parameters=[{'robot_description': desc}]

Humble and Jazzy have an older way to do this. If robot_description isn't set, robot_state_publisher treats its first plain argument as a file name. ros2 run robot_state_publisher robot_state_publisher valid.urdf and arguments=[path] in a launch file both worked there. Both printed No robot_description parameter, but command-line argument available. Assuming argument is name of URDF file. This backwards compatibility fallback will be removed in the future.

On Lyrical that fallback is gone. The same command died with robot_description parameter must not be empty, and so did the launch file with arguments=[path].

robot_description parameter must not be empty

Four inputs gave this message:

  • no parameter at all (ros2 run robot_state_publisher robot_state_publisher)
  • robot_description: ''
  • the output of a xacro run that failed. I wrote xacro bad_include.xacro > out.urdf, the include was missing, xacro exited with code 2 and left a 0-byte file.
  • on Lyrical only, the positional file argument described above

Humble and Jazzy printed the message twice, once as a log line and once in what():. Lyrical printed only the what(): line.

In a launch file a failing xacro never gets that far. With Command(['xacro ', path]) and the missing include, ros2 launch stopped before starting any process with Caught exception in launch (see debug for traceback): executed command failed. Command: xacro /w/n_humble/bad_include.xacro. The next line was the xacro error: No such file or directory: /opt/ros/humble/share/robot_state_publisher/urdf/missing.xacro. It exited with 1. In a shell script, check xacro's exit code yourself. A redirect hides the failure and leaves an empty file.

Joint and link errors

When the XML parses but the model is wrong, urdfdom names the joint or link. It also prints joint xml is not initialized correctly, which you can skip. The case from robot_state_publisher Error: joint limit: no effort reproduced exactly. With <limit><lower>...</lower><effort>100</effort>...</limit> I got joint limit: no effort on Humble and Jazzy, and joint [wheel_joint]: limit has no effort on Lyrical. In my run the child elements were ignored. urdfdom wants lower, upper, effort and velocity as attributes.

A revolute joint with no <limit> at all gave a different message: Joint [wheel_joint] is of type REVOLUTE but it does not specify limits. Missing velocity gave joint limit: no velocity. The other model errors are in the table above, and their text matched on all three distros.

Failed to parse global arguments with -p robot_description

Passing the URDF on the command line usually worked. These four all started the node on every distro:

ros2 run robot_state_publisher robot_state_publisher --ros-args -p robot_description:="$(xacro good.xacro)"
ros2 run robot_state_publisher robot_state_publisher --ros-args -p robot_description:="$(cat valid.urdf)"
# the same URDF joined into one line
# and a URDF with package://bot/meshes/laser.stl in a mesh filename

A colon followed by a space in an XML comment broke it. I added <!-- note: wheel radius is 0.05 --> to the valid URDF. With "$(cat colon_comment.urdf)" the node didn't start on any distro:

[rcl]: Failed to parse global arguments
terminate called after throwing an instance of 'rclcpp::exceptions::RCLInvalidROSArgsError'
  what():  failed to initialize rcl: Couldn't parse parameter override rule: '-p robot_description:=<?xml version="1.0"?>
...
</robot>'. Error: Error parsing an event, at ./src/parse.c:914, at ./src/rcl/arguments.c:343

That's the Humble output. Lyrical showed parse.c:1240 and arguments.c:352. The value after := is read as YAML, and note: wheel looks like a YAML mapping. package:// has no space after its colon, and that file worked. This matches the answer on Unable to parse URDF using command line but can do it in launch file. Two fixes worked on all three distros. One is single quotes inside the rule, -p "robot_description:='$(cat colon_comment.urdf)'", which makes YAML read the value as a string. The other is a params file or a launch file, and both loaded the same URDF without complaint. I didn't test a URDF that contains a single quote itself. For other -p and params-file parse errors, see Failed to parse global arguments and params YAML errors.

It starts, but /tf stays empty

With the valid URDF, the node published the fixed joint on /tf_static right away (base_link to laser, x 0.1, z 0.2). It also published the whole URDF on /robot_description. Both use transient local durability, so ros2 topic echo needed --qos-durability transient_local to see them.

The revolute wheel frame comes only from /joint_states. In 5 seconds with no joint states, /tf carried 0 messages. Then I published one JointState for wheel_joint at 0.5 rad:

  • With the header stamp left at zero (ros2 topic pub without a header), nothing reached /tf within 12 seconds, on all three distros.
  • With header: {stamp: now} the transform arrived at once: child_frame_id: wheel, rotation z 0.2474, w 0.9689.

If you test with ros2 topic pub or your own publisher, give the message a real stamp.

Changing robot_description while it runs

robot_description can be set at runtime. ros2 param set /robot_state_publisher robot_description "<robot name='x'></robot>" returned Setting parameter failed: Unable to initialize urdf::model from robot description. The node logged No link elements found in urdf file and kept running on the old model. Setting it back to the valid URDF returned Set parameter successful. A bad runtime update gets rejected. A bad description at startup kills the node.

Version notes

  • Humble (robot_state_publisher 3.0.3, urdfdom 3.0.2): XML errors read like Error document empty. and Error reading end tag. On startup it logs got segment base_link for each link instead of Robot initialized.
  • Jazzy (3.3.4, urdfdom 4.0.2): XML errors use TinyXML2 codes, such as XML_ERROR_PARSING_TEXT ErrorID=8 and XML_ERROR_PARSING ErrorID=15. The path fallback still works.
  • Lyrical (3.5.6, urdfdom 6.0.0): the limit messages name the joint (joint [wheel_joint]: limit has no effort). Failed to parse robot description is logged as a warning from the [urdf] logger. The positional URDF file fallback was removed.
  • The urdf_parser source line numbers in the messages differ between distros (206, 207, 216 for the same check). Search for the message text, not the line number.

Not tested

  • URDFs with real meshes, Gazebo tags or ros2_control tags. robot_state_publisher doesn't load meshes, so I only checked that a package:// filename didn't affect parsing.
  • joint_state_publisher, joint_state_publisher_gui, RViz and MoveIt.
  • Reading the description from a topic instead of the parameter, which newer docs mention.
  • A URDF that contains a single quote, passed with the single-quote -p fix.
  • RMW implementations other than the default Fast DDS, and non-amd64 hosts.

FAQ

What does No link elements found in urdf file mean?

The parser didn't find a single top-level <link>. In my runs that happened when raw .xacro text was passed in without running xacro, and when the links were inside a xacro:macro that was never called. Check with xacro file.urdf.xacro | grep -c '<link'.

Why does robot_state_publisher say Error document empty when my file is not empty?

On Humble that is what you get when robot_description holds a file path instead of the URDF text. Jazzy and Lyrical print XML_ERROR_PARSING_TEXT for the same mistake. Read the file in the launch file, or use Command(['xacro ', path]) with ParameterValue(..., value_type=str).

How do I fix joint limit: no effort?

Write the limit as attributes: <limit lower="-3.14" upper="3.14" effort="100" velocity="10"/>. Child elements like <effort>100</effort> are ignored, and the joint then has no effort. Lyrical words it as joint [name]: limit has no effort.

Why does -p robot_description:="$(xacro ...)" fail with Failed to parse global arguments?

The value is parsed as YAML. In my test, a colon followed by a space inside an XML comment broke it on Humble, Jazzy and Lyrical, while the same URDF without that comment worked. Put single quotes inside the rule, or pass the URDF through a params file or a launch file.

Does ros2 run robot_state_publisher robot_state_publisher my.urdf still work?

On Humble and Jazzy yes, with a warning that the fallback will be removed. On Lyrical no. It died with robot_description parameter must not be empty. Set the robot_description parameter instead.
