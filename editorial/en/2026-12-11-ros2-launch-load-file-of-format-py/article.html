[ERROR] [launch]: Caught exception in launch (see debug for traceback): Caught multiple exceptions when trying to load file of format [py]:
 - PackageNotFoundError: "package 'gazebo_ros' not found, searching: ['/opt/ros/humble']"
 - InvalidFrontendLaunchFileError: The launch file may have a syntax error, or its format is unknown

Older posts quote a one-line form of the same error: Caught exception when trying to load file of format [py]: "package 'gazebo_ros' not found. Humble, Jazzy and Lyrical all printed the multi-line form above.

Short answer: "Caught exception when trying to load file of format [py]" is a wrapper. ros2 launch imported your launch file and called generate_launch_description(), and some ordinary Python exception came out of it. The real error is the first bullet line under the message. Ignore the InvalidFrontendLaunchFileError bullet. That one only says the XML and YAML parsers couldn't read a Python file either, and it showed up in every failing .launch.py I ran. Fix the first bullet as you would in any Python script. To find the error without launching anything, run the file the way the loader does:

python3 -c "
import runpy, sys
m = runpy.run_path(sys.argv[1])
ld = m['generate_launch_description']()
from launch import LaunchDescription
assert isinstance(ld, LaunchDescription), type(ld)
" my_robot.launch.py

In my run that check failed on all eight broken Python launch files it was given and passed on the good one. If you need the full stack, add -d: ros2 launch -d my_pkg my_robot.launch.py.

What I ran

On 2026-11-03 I used the official ros:humble-ros-base, ros:jazzy-ros-base and ros:lyrical-ros-base Docker images on a 2 vCPU Linux host, one distro after another. I didn't build a package. Every launch file sat in /l and was started by path with ros2 launch /l/<file>, with a 60-second timeout. The baseline file has one LogInfo action that prints LAUNCH-OK. Each broken file differs from it by one mistake. I wrote 18 launch files: 14 .launch.py files, the good Python file copied under two other extensions, one XML file and one YAML file. I also ran the path that doesn't exist, -d, -s and -p on some of the broken files, and two checks outside ros2 launch.

The good file ran in 275 to 283 ms on Humble, 321 to 326 ms on Jazzy and 409 to 427 ms on Lyrical (five runs each). The broken files failed in about the same time, 274 to 353 ms on Humble. So the error comes at load time, before any node or process is started. If your terminal shows other nodes starting and then this error, the error is in an included file or in a later step, not in the top-level file.

Why the message says "multiple exceptions"

The -d traceback shows where the wrapper comes from. get_launch_description_from_any_launch_file in launch/launch_description_sources/any_launch_file_utilities.py tries more than one loader. It collects each loader's exception, then raises InvalidLaunchFileError with all of them listed. For a .launch.py file the Python loader goes first, so its exception is the first bullet. The frontend (XML and YAML) attempt adds the second bullet. The order turns around for an XML file. A .launch.xml with a misspelled attribute printed:

Caught multiple exceptions when trying to load file of format [xml]:
 - ValueError: Unexpected attribute(s) found in `node`: {'nmae'}
 - SyntaxError: invalid syntax (c15_bad.launch.xml, line 1)

Here the first bullet is the real one again, and the SyntaxError is from the Python loader trying to read XML. A YAML file with a misplaced - gave format [yaml], a nested InvalidFrontendLaunchFileError, the real ParserError: while parsing a block mapping ... expected <block end>, but found '-' with line and column, then an XML ParseError and a Python SyntaxError. In all three formats the rule held: read the first error that names your file's real problem and skip the ones from the other parsers.

Trying more than one loader also means the extension isn't strict. A file with Python content named c13_python_as.launch ran and printed LAUNCH-OK, and so did the same Python content saved as c14_python_as.launch.xml, with exit code 0 on all three distros. A wrong extension didn't cause this error in my run.

Package not found

This is the cause behind the most-viewed question about this error, where a launch file needs gazebo_ros. get_package_share_directory() runs while the file is loading. If the package isn't in any sourced prefix, it raises PackageNotFoundError, and the message lists every prefix it searched. In my run that list was ['/opt/ros/humble'] (and the Jazzy and Lyrical paths). That list is the fastest clue. If your workspace's install folder isn't in it, you didn't source the workspace in this terminal. If the workspace is there but the package isn't, the package isn't installed or wasn't built. For gazebo_ros on Jazzy or Lyrical, keep in mind that the classic Gazebo packages are not part of those distros, so a launch file written for Gazebo Classic needs porting, not just an install. I didn't test installing Gazebo.

A helper module next to the launch file

A launch file that imports helper.py from its own folder fails with ModuleNotFoundError: No module named 'helper', even though plain python3 would find it. The loader doesn't put the launch file's folder on sys.path. Adding it yourself worked on all three distros and printed HELPER-IMPORTED:

import os, sys
sys.path.insert(0, os.path.dirname(os.path.realpath(__file__)))
from helper import MSG

Use realpath so the path still points to the real folder when --symlink-install links the launch file into install/. I only ran this from a plain folder, not from an installed package, so check that the helper is installed next to the launch file too (same data_files or install(DIRECTORY ...) entry). The other option is to move the helper into a real Python package that your setup.py installs, then import it by package name. I didn't test that.

NameError, ImportError and ROS 1 keywords

These are plain Python mistakes, and the bullet already names the line's problem. NameError: name 'launch_ros' is not defined means the file used launch_ros.actions.Node with only from launch_ros.actions import Node, or with no import at all. Use the same form in the import and in the call. ImportError: cannot import name ... is almost always a typo. The function is get_package_share_directory, singular. The TypeError ... unexpected keyword argument 'node_name' comes from old examples. The ROS 2 Node action takes name= and executable=, not node_name= or node_executable=. A ROS 1 dependency fails the same way, so No module named 'roslaunch' in a ROS 2 launch file means ROS 1 code got in. I didn't run that case.

No return, or the wrong return

If generate_launch_description() forgets return, or returns a list, the import itself succeeds. The failure comes one step later, and the message doesn't mention a file format: 'NoneType' object has no attribute 'get_launch_arguments_with_include_launch_description_actions'. The fix is return LaunchDescription([...]). A misspelled function name gives a clearer error, does not contain the required function 'generate_launch_description()', inside the usual wrapper.

If you build the description from LaunchConfiguration values, a type mix-up inside the function also lands here. The published post on LaunchConfiguration values as int covers why those values are strings at load time.

Version notes

Every error text in this post was identical on Humble (launch 1.0.15, launch_ros 0.19.14, Python 3.10.12), Jazzy (launch 3.4.12, launch_ros 0.26.13, Python 3.12.3) and Lyrical (launch 3.9.8, launch_ros 0.29.9, Python 3.14.4). FAQ

What does "Caught exception when trying to load file of format [py]" mean?

ros2 launch imported the Python launch file or ran its generate_launch_description(), and that raised an exception. The real error is the first bullet under the message, for example PackageNotFoundError, NameError or SyntaxError.

What is "InvalidFrontendLaunchFileError: The launch file may have a syntax error, or its format is unknown"?

For a .launch.py file it's noise. After the Python loader fails, launch also tries the XML and YAML parsers, and they fail too. It appeared in every failing Python launch file in my run, whatever the real cause was.

How do I fix "package 'gazebo_ros' not found" in a launch file?

Look at the searching: list in the message. If your workspace's install folder is missing from it, source the workspace in that terminal. If it's there, build or install the package. On Jazzy and Lyrical the classic gazebo_ros packages aren't part of the distro, so the launch file needs porting.

Why can't my launch file import a Python file from the same folder?

The launch loader doesn't add the launch file's folder to sys.path, so from helper import X fails with No module named 'helper'. Adding sys.path.insert(0, os.path.dirname(os.path.realpath(__file__))) before the import worked on Humble, Jazzy and Lyrical.

How do I check a launch file for errors without running it?

python3 -m py_compile found only the syntax and indentation errors. Loading the file with runpy.run_path and calling generate_launch_description() found all eight broken cases in my run, and it started nothing.
