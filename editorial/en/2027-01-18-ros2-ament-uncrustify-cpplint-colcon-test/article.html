Short answer: "Code style divergence" is not a compile error. It's the uncrustify test that ament_lint_auto adds to every ament_cmake package made with ros2 pkg create. The diff shows how ROS 2's uncrustify config wants the file laid out. Let the tool apply it, from the package folder:

source /opt/ros/humble/setup.bash
cd ~/ws/src/my_pkg
ament_uncrustify --reformat src include
ament_uncrustify src include      # should end with: No problems found

That fixed every uncrustify failure in my run, on Humble, Jazzy and Lyrical, in about 0.1 seconds. Two catches. Code reformatted on Jazzy or Lyrical still failed uncrustify on Humble, so if you test on Humble, format on Humble. And if xmllint fails next to it with failed to load external entity "http://download.ros.org/schema/package_format3.xsd", your code is fine. The test machine can't reach download.ros.org.

What I ran

One container per distro on a 2 vCPU Linux runner, run one after another: ros:humble-ros-base, ros:jazzy-ros-base and ros:lyrical-ros-base. In each container I installed ros-<distro>-ament-lint-auto, ros-<distro>-ament-lint-common and git, then disconnected the network. If your build stops at find_package(ament_lint_auto REQUIRED) instead, that is a missing package, which is a "Could not find a package configuration file" problem, not a style problem.

The steps, all in repro.sh:

  1. ros2 pkg create --build-type ament_cmake --dependencies rclcpp std_msgs --node-name my_node lintpkg, then colcon build and colcon test with nothing changed.
  2. Add a normal talker node: a header with #pragma once and a .cpp in 4-space, brace-on-the-same-line style, with one long RCLCPP_INFO line. It built on all three distros.
  3. Turn cpplint on, outside and inside a git repo.
  4. ament_uncrustify --reformat, then fix the cpplint errors by hand.
  5. Check each distro's reformatted files with the other distros' uncrustify.
  6. Try the ways to skip a linter, and run xmllint again with the network connected.

Before step 2, the untouched template passed cppcheck, lint_cmake and uncrustify on all three distros. Two linters never run on it. The template's CMakeLists.txt sets ament_cmake_copyright_FOUND and ament_cmake_cpplint_FOUND to TRUE, which tells ament_lint_auto to skip them:

if(BUILD_TESTING)
  find_package(ament_lint_auto REQUIRED)
  # the following line skips the linter which checks for copyrights
  # comment the line when a copyright and license is added to all source files
  set(ament_cmake_copyright_FOUND TRUE)
  # the following line skips cpplint (only works in a git repo)
  # comment the line when this package is in a git repo and when
  # a copyright and license is added to all source files
  set(ament_cmake_cpplint_FOUND TRUE)
  ament_lint_auto_find_test_dependencies()
endif()

So a fresh package runs four tests: cppcheck, lint_cmake, uncrustify and xmllint. After adding the talker, uncrustify failed on all three distros. lint_cmake still passed.

uncrustify: reading the diff, then --reformat

Lines starting with - are your file. Lines starting with + are what the ROS 2 config wants. On Humble the diff for my two files had 51 changed lines. On Jazzy and Lyrical it had 47. The changes fell into four groups:

  • Function bodies open on their own line: void Talker::timer_callback(), then {.
  • The constructor's initializer list moves to its own line, starting with : Node("talker"), count_(0).
  • Indent is 2 spaces, not 4.
  • Lines over 100 characters are wrapped. The RCLCPP_INFO call was split over three lines.

ament_uncrustify --reformat src include rewrote both files in place. It took 103 ms on Humble, 126 ms on Jazzy and 135 ms on Lyrical. It exits with code 1 even when it works, because it still reports what it found:

2 files with code style divergence
Code style divergence in file 'include/lintpkg/talker.hpp': reformatted file
No code style divergence in file 'src/my_node.cpp'
Code style divergence in file 'src/talker.cpp': reformatted file

A second run without --reformat printed No problems found and exited 0. In colcon test the uncrustify test then passed on all three distros. One --reformat pass was enough every time.

The tool only changes layout. It never touched #pragma once, the include order or the using namespace std::chrono_literals; line. It also has no idea about cpplint. More on that below.

Code formatted on Jazzy or Lyrical fails on Humble

This is the trap for anyone who develops on Jazzy and tests on Humble, or who supports both in one branch. Humble ships uncrustify 0.72.0 (uncrustify_vendor 2.0.2). Jazzy and Lyrical ship 0.78.1 (uncrustify_vendor 3.0.1 and 3.2.0). The configs do not agree.

I took the files that each distro's --reformat produced and checked them with the other distros' uncrustify:

Jazzy's and Lyrical's reformatted talker.cpp were identical. Humble rejected three things in them:

-class Talker : public rclcpp::Node {
+class Talker : public rclcpp::Node
+{
-  RCLCPP_INFO(this->get_logger(),
+  RCLCPP_INFO(
+    this->get_logger(),
-  if(count_ > 10) {

Jazzy left if(count_ > 10) without a space and kept the class brace on the same line. Humble wants a space after if and the brace on its own line. The newer config accepts both forms, so Humble's output passes everywhere. If one branch has to pass on Humble and newer distros, run --reformat in a Humble container. The open-rmf pull request that turned uncrustify off by default ran into this between Jammy and Noble.

cpplint: off by default, and what it flagged

The template comment says cpplint "only works in a git repo". I commented out the set(ament_cmake_cpplint_FOUND TRUE) line and ran ament_cpplint src include twice: once in a plain folder and once after git init at the workspace root. The output was byte-for-byte the same on all three distros. ament_cpplint passed its own --root for each folder:

Using '--root=/ws/src/lintpkg/include' argument

So git made no difference in my run. The copyright part of the comment is what matters. Before the reformat, cpplint found 4 errors in 3 files:

/ws/src/lintpkg/include/lintpkg/talker.hpp:0:  No copyright message found.  You should have a line: "Copyright [year] <Copyright Owner>"  [legal/copyright] [5]
/ws/src/lintpkg/src/my_node.cpp:0:  No copyright message found.  You should have a line: "Copyright [year] <Copyright Owner>"  [legal/copyright] [5]
/ws/src/lintpkg/src/talker.cpp:0:  No copyright message found.  You should have a line: "Copyright [year] <Copyright Owner>"  [legal/copyright] [5]

On Lyrical the same errors came out with prefixes: INFO: Total errors found: 4 for the summary and DEBUG: on the --root line.

Note what it did not flag. #pragma once instead of an include guard, the project header included before <chrono>, std::bind without <functional> and using namespace std::chrono_literals; gave no errors. All three distros report the same bundled cpplint version, 1.5.5.

After --reformat, the line length error was gone, because uncrustify had wrapped the line. The 3 copyright errors stayed. After I added an Apache license header to talker.hpp and talker.cpp, one error was left, in the file I never wrote:

/ws/src/lintpkg/src/my_node.cpp:0:  No copyright message found.  You should have a line: "Copyright [year] <Copyright Owner>"  [legal/copyright] [5]
Total errors found: 1

The my_node.cpp that ros2 pkg create --node-name generates has no copyright line. Enabling cpplint on a generated package fails until you add a header to it too, or delete it.

This cpplint check is separate from the copyright test that the template also skips. I left that one skipped. I didn't test it here.

xmllint fails without network

The unchanged template failed one test from the start: xmllint. My containers had no network, and package.xml points at a schema on the internet:

<?xml-model href="http://download.ros.org/schema/package_format3.xsd" schematypens="http://www.w3.org/2001/XMLSchema"?>

On Humble and Jazzy the failure read:

File 'package.xml' is invalid:
error : Resource temporarily unavailable
warning: failed to load external entity "http://download.ros.org/schema/package_format3.xsd"
Schemas parser error : Failed to locate the main schema resource at 'http://download.ros.org/schema/package_format3.xsd'.
WXS schema http://download.ros.org/schema/package_format3.xsd failed to compile

1 files are invalid

Lyrical tried to download the schema itself first and printed one more line before the same failure:

Warning: failed to download schema from 'http://download.ros.org/schema/package_format3.xsd': <urlopen error [Errno -3] Temporary failure in name resolution>

It failed fast, in 0.16 to 0.24 seconds. When I connected the same containers to the network, the same file passed with File 'package.xml' is valid. ament_xmllint took 655 ms on Humble, 490 ms on Jazzy and 530 ms on Lyrical, and the xmllint test took 0.55 to 0.59 seconds. So if xmllint fails in an offline CI job, a Docker build with --network none or behind a proxy, check the network before you edit package.xml. I didn't test a slow or partly reachable server. An Autoware pull request reports that case ending in the 60-second CTest timeout.

cppcheck is skipped on all three

cppcheck "passed" on every distro, but it checked nothing. Each file was marked skipped in cppcheck.xunit.xml:

cppcheck 2.7 has known performance issues and therefore will not be used, set the AMENT_CPPCHECK_ALLOW_SLOW_VERSIONS environment variable to override this.

Jazzy printed the same with cppcheck 2.13.0, and Lyrical with 2.19.0. If you see this line, nothing failed. I didn't run cppcheck with AMENT_CPPCHECK_ALLOW_SLOW_VERSIONS set.

FAQ

How do I fix "Code style divergence in file" in colcon test?

Run ament_uncrustify --reformat src include in the package folder, then ament_uncrustify src include to confirm. It should end with No problems found. One pass fixed every case in my run on Humble, Jazzy and Lyrical.

Why does uncrustify pass on Jazzy but fail on Humble?

Humble ships uncrustify 0.72.0 and Jazzy ships 0.78.1, with different configs. In my run, Jazzy accepted if( and a class brace on the same line, and Humble rejected both. Code reformatted on Humble passed on Jazzy and Lyrical, so format on Humble if you test on both.

Is there an automatic fix for cpplint errors?

Not in ament_cpplint. In my run, ament_uncrustify --reformat fixed the only layout error cpplint reported, a line over 100 characters. The copyright errors needed a license header in each file, including the my_node.cpp that ros2 pkg create generates.

Why does xmllint fail on a package.xml I didn't change?

The schema in package.xml is a URL on download.ros.org. Without network, xmllint printed failed to load external entity and failed to compile, then 1 files are invalid. The same file passed once the container had network.

How do I skip uncrustify or cpplint in ROS 2?

Add list(APPEND AMENT_LINT_AUTO_EXCLUDE ament_cmake_uncrustify ament_cmake_cpplint) before ament_lint_auto_find_test_dependencies(). To skip only some files, use set(AMENT_LINT_AUTO_FILE_EXCLUDE ...). For one local run, use colcon test --ctest-args -E "uncrustify|cpplint".
