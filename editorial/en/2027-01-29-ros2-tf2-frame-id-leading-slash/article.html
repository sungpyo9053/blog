tf2.InvalidArgumentException: Invalid argument "/map" passed to lookupTransform argument target_frame - in tf2 frame_ids cannot start with a '/'

That is the exact text from rclpy on Humble, Jazzy and Lyrical. ROS 1 printed the same check with a trailing like:. In ROS 2 the message ends right after the slash. The empty-name version reads Invalid argument "" passed to lookupTransform argument target_frame - in tf2 frame_ids cannot be empty. Tools that call canTransform, such as tf2_echo, print Invalid frame ID "/map" passed to canTransform argument target_frame - in tf2 frame_ids cannot start with a '/' instead.

Short answer: tf2 accepts a leading slash when a transform comes in, but not when you ask for one. A publisher can send /map, and the buffer stores it as map. A lookup that passes /map is rejected before tf2 even checks whether the frame exists. So strip the slash from the name you pass to lookup_transform or can_transform, and remove it at the source if you can:

from tf2_ros import TransformException

def tf_name(frame):
    return frame.lstrip('/')   # "/map" -> "map", "//map" -> "map"

try:
    t = tf_buffer.lookup_transform(tf_name(target), tf_name(msg.header.frame_id), rclpy.time.Time())
except TransformException as e:   # InvalidArgumentException is a subclass
    node.get_logger().warn(str(e))

Two details make this error harder to find than it should be. can_transform('/map', ...) doesn't raise. It returns False, so a "wait until the transform is available" loop just waits forever. And lookup_transform with a timeout waited the full timeout (2.0 s in my runs) before raising the error, even though the name could never be valid.

What I ran

On 2026-11-17 I ran one script in the official ros:humble-ros-base, ros:jazzy-ros-base and ros:lyrical-ros-base images, one distro after another, with --network none and ROS_DOMAIN_ID=88. It had three parts:

  1. tf2_ros.Buffer used directly, no DDS. I called set_transform with ten different frame strings (plain, slash in the parent, slash in the child, both, //map, map/, empty parent, empty child, same frame twice, " map"). After each one I printed all_frames_as_string() and tried three lookups. Then I ran nine lookups and four can_transform calls on a plain map to base_link buffer.
  2. Real traffic: static_transform_publisher with /map or /base_link, the old positional form, a Python /tf publisher sending /odom to /base_link 40 times, tf2_echo with good, slashed and empty names, ros2 topic echo on /tf_static to see the bytes on the wire, and a timing test of lookup_transform and can_transform with timeout=2.0, three runs each.
  3. robot_state_publisher with a two-link URDF and frame_prefix set to robot1/, /robot1/ and unset.

Publishing a slash works, asking for one doesn't

This asymmetry causes most of the confusion. On all three distros, static_transform_publisher --frame-id /map --child-frame-id base_link printed from '/map' to 'base_link'. ros2 topic echo on /tf_static showed frame_id: /map and child_frame_id: /base_link on the wire when both had a slash. A Python TransformListener then reported Frame base_link exists with parent map., and lookup_transform('map', 'base_link') returned x=1.0 with header map -> base_link. The Python /tf publisher sending /odom to /base_link behaved the same way. The listener stored odom and base_link and returned x=2.0 for odom.

So a slash in a publisher doesn't break tf2-based listeners. The listener strips one leading slash when the transform goes in. What breaks is code that takes the name it was given and asks for it back with the slash still on. That name usually comes from one of these places:

  • a sensor message with header.frame_id = "/laser", where your callback passes msg.header.frame_id straight to lookup_transform;
  • a parameter or launch argument written ROS 1 style, such as global_frame: /map;
  • a frame_prefix or namespace string glued onto a frame name;
  • a tf2_echo or RViz fixed frame typed with a slash (RViz was not tested).

The listener cleans up incoming transforms, but nothing cleans up the copies of that name in your own messages. A LaserScan sent with /laser still carries /laser to every subscriber.

Per cause

Slash in lookup_transform or lookup_transform_full

Target and source are both checked, and the target is reported first when both are wrong. lookup('/map', '/base_link') named only "/map" in its message. lookup_transform_full('/map', ...) raised the same InvalidArgumentException. In Python the class hierarchy was InvalidArgumentException, TransformException, Exception. So except TransformException catches it, and except LookupException does not. If your code only catches LookupException, which is common in tutorials, the slash error escapes and kills the callback.

For C++ I didn't measure an uncaught throw. One ROS 2 report linked below shows the result anyway: terminate called after throwing an instance of 'tf2::InvalidArgumentException', followed by process has died [pid ..., exit code -6 ...].

can_transform returns False, with no exception

On the plain buffer, can_transform('map', 'base_link', Time()) returned 1. For '/map', '' and a missing 'odom' it returned 0, and nothing in the return value tells those three apart. With return_debug_tuple=True you get the reason:

(0, 'Invalid frame ID "/map" passed to canTransform argument target_frame - in tf2 frame_ids cannot start with a \'/\'')
(0, 'Invalid frame ID "" passed to canTransform argument target_frame - in tf2 frame_ids cannot be empty')
(0, 'Invalid frame ID "odom" passed to canTransform argument target_frame - frame does not exist')

If a node sits in a "waiting for transform" loop and you know the transform is being published, print this tuple once.

The timeout runs out before the error

With a TransformListener on a spin thread and map to base_link published, I timed lookup_transform(target, 'base_link', Time(), timeout=Duration(seconds=2.0)) three times for each target:

TargetElapsed (9 runs, 3 distros)Result

can_transform with the same timeout also took about 2.0 s and returned 0 for the last three. A slashed name can never succeed, but the Python buffer still waited as if the frame might show up later. Any callback that makes this call blocks for the whole timeout each time. I didn't time calls without a timeout.

Empty frame IDs

Lookups with an empty target or source raised InvalidArgumentException with frame_ids cannot be empty. A transform published with an empty parent or child is not stored at all. The buffer logs TF_NO_FRAME_ID or TF_NO_CHILD_FRAME_ID and drops it. The usual source is a message built in code where header.frame_id was never set. The default is an empty string, and a subscriber that passes it to lookup_transform gets this error. tf2_echo '' base_link printed Waiting for transform -> base_link: Invalid frame ID "" passed to canTransform argument target_frame - in tf2 frame_ids cannot be empty about every 2 s.

Double, trailing and padded names

Only one leading slash is removed. //map was stored as /map, map/ as map/ and " map" with its space. None of them could be found as map, and the error is the ordinary "map" passed to lookupTransform argument target_frame does not exist. If all_frames_as_string() shows a name that looks right but lookups fail, check for an extra slash or a stray space. Names are also case sensitive: Map was not found.

robot_state_publisher frame_prefix

With frame_prefix:=robot1/, /tf_static carried robot1/base_link and robot1/laser, and the lookup returned x=0.3. With frame_prefix:=/robot1/, the wire carried /robot1/base_link and /robot1/laser. The Python listener still stored robot1/base_link and robot1/laser, and the same lookup worked. In both cases, lookup('/robot1/base_link', 'robot1/laser') raised the slash error. A slashed prefix didn't break tf2 listeners in my test. It did put slashed names on the wire for anything else that reads /tf_static. Use robot1/. I didn't test RViz, Nav2 or message_filters against slashed names.

A note on lstrip('/'): it fixes the slash, not the name. In my run, robot1/base_link still failed with "does not exist" in a buffer that only had map and base_link, because that frame really wasn't there. FAQ

Why does tf2 reject a frame ID that starts with a slash?

tf2 treats frame names as plain strings. It doesn't resolve them like topic names. Incoming transforms get one leading slash stripped, so /map is stored as map. Lookups are validated instead, and a leading slash raises InvalidArgumentException on Humble, Jazzy and Lyrical.

My publisher uses /map. Do I have to change it?

For tf2 listeners, not strictly. In my runs, a /map publisher was found as map. But the slash stays on the wire and in your message headers, and any code that copies header.frame_id into a lookup will fail. Remove it at the source when you can.

Why does can_transform return False when the transform is being published?

If the name has a slash or is empty, can_transform returns False instead of raising. Call it with return_debug_tuple=True. The second item said frame_ids cannot start with a '/' in my test.

Why does the error take exactly as long as my timeout?

In rclpy, lookup_transform with timeout=2.0 waited 2.004 to 2.016 s before raising the slash error, the same as for a frame that doesn't exist. A longer timeout only makes the wait longer, so fix the name.

What does "frame_ids cannot be empty" mean?

The target or source name passed to the lookup was an empty string, usually a header.frame_id nobody set. A transform with an empty frame_id is dropped with TF_NO_FRAME_ID, so set the field in the publisher.
