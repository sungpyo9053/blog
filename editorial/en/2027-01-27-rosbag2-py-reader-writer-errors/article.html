RuntimeError: Database directory already exists (/tmp/bags/w_none), can't overwrite existing database

That is what rosbag2_py.SequentialWriter().open() raised on Humble. On Jazzy and Lyrical the same call fails with RuntimeError: Bag directory already exists (/tmp/bags/w_none), can't overwrite existing bag.

Short answer: SequentialWriter.open() only opens a path that doesn't exist yet. It refuses any folder that already exists, including an empty one, so give every run a new path or delete the old folder before you open the writer. The second half of the problem is finishing the bag. metadata.yaml is written only when the writer is closed: writer.close(), del writer, or a normal end of the Python process. If the process is killed first, the folder has no metadata.yaml and readers reject it. These are the calls that worked in my runs on Humble, Jazzy and Lyrical:

import time
import rosbag2_py
from rclpy.serialization import serialize_message
from std_msgs.msg import String

uri = f'/tmp/bags/run_{time.strftime("%Y%m%d_%H%M%S")}'   # a path that does not exist yet
writer = rosbag2_py.SequentialWriter()
writer.open(rosbag2_py.StorageOptions(uri=uri),           # default storage: sqlite3 on Humble, mcap on Jazzy/Lyrical
            rosbag2_py.ConverterOptions('cdr', 'cdr'))
try:
    topic = rosbag2_py.TopicMetadata(name='/chatter', type='std_msgs/msg/String',
                                     serialization_format='cdr')            # Humble
except TypeError:
    topic = rosbag2_py.TopicMetadata(id=0, name='/chatter', type='std_msgs/msg/String',
                                     serialization_format='cdr')            # Jazzy, Lyrical
writer.create_topic(topic)
try:
    writer.write('/chatter', serialize_message(String(data='hi')), time.time_ns())  # bytes, int nanoseconds
finally:
    writer.close()   # writes metadata.yaml (and, for MCAP, the data still in memory)

What I ran

On 2026-11-16 I used the official ros:humble-ros-base, ros:jazzy-ros-base and ros:lyrical-ros-base images on a 2 vCPU Linux host, one distro at a time, with --network none and domain 88. One Python script, bag.py, runs one case per process so a crash in one case can't hide another. repro.sh calls it about 60 times per distro. It writes bags of std_msgs/String with SequentialWriter and tries to open existing folders. It also passes bad arguments to write(), reads the bags back with SequentialReader under each storage id, and ends some writers with close(), del, a normal exit, os._exit(0) or SIGKILL. Then it runs ros2 bag info and ros2 bag reindex on the broken bags. Last, it runs an rclpy node that writes from a 20 Hz timer and stops it with SIGINT, SIGTERM or SIGKILL after 3 seconds. Jazzy ran twice, because the first pass didn't yet have the sqlite3 and 100,000-message kill cases. out_jazzy.txt is the second, complete pass.

Why the writer refuses an existing folder

The uri in StorageOptions is a folder that the writer creates. It is not a file name. If anything is already there, open() raises before it writes a byte. My run gave the same error for a finished bag and for an empty folder made with mkdir. That is why a script that worked once fails on the second run: the first run left the folder behind. The rosbag2 issue #1921 shows this case. A recorder node used a fixed path and failed on Humble with the "Database directory already exists" text.

Every write case in my script used a path that didn't exist yet, and none of them hit the error. So use one of these two patterns:

  • Put a timestamp or a counter in the path, as in the code above. ros2 bag record names its folders the same way.
  • If you really want to overwrite, delete the folder with shutil.rmtree(uri, ignore_errors=True) before open(). I didn't run this line. The run only shows that a missing path opens and an existing one doesn't.

The file names inside the folder changed in Lyrical. Humble and Jazzy wrote w_none_0.db3 or w_none_0.mcap. Lyrical wrote 0_w_none_2026_11_16-05_32_56.mcap. Scripts that build the file path by hand break on Lyrical. Pass the folder to the reader instead. Pointing the reader at the .db3 or .mcap file also worked on all three, as long as the bag was finished.

A normal exit finished the bag because the writer object is destroyed on the way out. Anything that skips Python's cleanup also skips the metadata. That includes os._exit, SIGKILL, a container stopped with docker kill and an out-of-memory kill. The MCAP column matters most. Small MCAP bags stay in memory until close. A 100-message bag killed early left a 0-byte file and nothing to recover. With 100,000 messages, 6,262,784 bytes were already on disk at the kill (6,260,772 on Lyrical). The finished file is 6,492,281 bytes.

In one run per distro on Jazzy and Lyrical, spin() ended with RCLError: failed to initialize wait set: the given context is not valid instead of ExternalShutdownException. The bag was still finished. Catch both, and close the writer in finally instead of trusting the exit. Humble recorded 53 messages in each 3-second run. Jazzy recorded 44 to 51 and Lyrical 47 to 49.

Reading: storage id, filters and close()

The question How to read a bag file in ROS2? asks for the basic loop. This worked on all three:

from rclpy.serialization import deserialize_message
from rosidl_runtime_py.utilities import get_message
import rosbag2_py

reader = rosbag2_py.SequentialReader()
reader.open(rosbag2_py.StorageOptions(uri='/tmp/bags/run_x'),   # folder; storage_id left empty
            rosbag2_py.ConverterOptions('', ''))
types = {t.name: t.type for t in reader.get_all_topics_and_types()}
while reader.has_next():
    name, data, t_ns = reader.read_next()
    msg = deserialize_message(data, get_message(types[name]))
  • Leave storage_id empty. An empty id opened sqlite3 and MCAP bags on every distro that had the plugin. A wrong id failed even when the right plugin was installed.
  • reader.set_filter(rosbag2_py.StorageFilter(topics=['/chatter'])) returned all 1,000 messages, and a filter on /other returned 0. After reset_filter() and seek(0) the reader returned 1,000 again.
  • SequentialReader.close() doesn't exist on Humble (hasattr was False). It does on Jazzy and Lyrical. SequentialWriter.close() existed on all three. rosbag2 issue #1934 reported the missing reader close().
  • Lyrical prints a DeprecationWarning on every read_next(): Use read_next_ext() which returns both send and receive timestamps. read_next() still returned the same three values.
  • A reader can't open a bag while the writer is still writing it (Is it possible in ROS2 to concurrently RW a bag file?). Opening the reader failed while the writer was alive, for sqlite3 on all three and for MCAP on Jazzy and Lyrical. After del writer, all 50 messages were read.

Version notes

  • Humble (rosbag2_py 0.15.17): default storage sqlite3, no MCAP plugin in ros-base, TopicMetadata without id, no SequentialReader.close(), error text "Database directory already exists". get_registered_writers() also listed my_test_plugin, a test plugin that ships in the image.
  • Jazzy (0.26.11): default storage MCAP, TopicMetadata requires id, error text "Bag directory already exists", write() has a second overload with a fourth int argument.
  • Lyrical (0.33.4): like Jazzy, plus new file names (0_<folder>_<timestamp>.mcap), named write() arguments (topic_name, message, time_stamp, sequence_number=0) and the read_next() deprecation warning.
  • To convert or replay bags across distros, see Convert a ROS 2 .db3 bag to MCAP (and play Jazzy bags in Humble).

Not tested

  • shutil.rmtree before open(), and installing ros-humble-rosbag2-storage-mcap on Humble.
  • Custom message types, compression, split bags (max_bagfile_size), seek() to a time and read_next_ext().
  • The C++ rosbag2_cpp::Writer, the ros2 bag record CLI, Windows and macOS.
  • Large messages such as images or point clouds. All timings use small String messages from one run each.
  • Out-of-memory kills and docker stop. I expect them to act like SIGKILL and SIGTERM, but I didn't run them.

FAQ

How do I fix "Database directory already exists, can't overwrite existing database"?

Open the writer on a path that doesn't exist yet, for example with a timestamp in the folder name, or delete the old folder first. The writer refused both a finished bag and an empty folder. Jazzy and Lyrical say "Bag directory already exists" instead.

Why is there no metadata.yaml in my rosbag2_py bag?

The writer was never closed. metadata.yaml was written on writer.close(), del writer or a normal end of the script. It was missing after os._exit and SIGKILL. Run ros2 bag reindex on the folder to rebuild it.

Why is my .mcap file 0 bytes?

MCAP keeps data in memory until close. With 1,000 messages the file was 0 bytes until del writer, then 65,393 bytes. A small MCAP bag that is killed before close can't be recovered. The reindex reported "file too small".

Why does TopicMetadata give "incompatible constructor arguments"?

Jazzy and Lyrical require an id as the first argument, and Humble rejects it. Pass id=0 on Jazzy and Lyrical and leave it out on Humble, or try one form and fall back to the other.

Do I need to set storage_id when reading?

No. An empty storage_id opened sqlite3 and MCAP bags on every distro that had the plugin. A wrong id failed with "No storage could be initialized". Humble ros-base can't read MCAP at all without the MCAP storage plugin.
