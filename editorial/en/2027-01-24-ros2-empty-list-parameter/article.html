# rclcpp node started with names: [] in a params file (or -p 'names:=[]')
rclcpp::exceptions::InvalidParameterValueException: parameter_value_from failed for parameter 'names': No parameter value set

# rclpy node, same file, after declare_parameter('names', ['a', 'b'])
rclpy.exceptions.ParameterUninitializedException: The parameter 'names' is not initialized

On Lyrical the C++ text after the colon is Invalid parameter value: rcl parameter structureContains no value (the missing space is in the original). On Jazzy and Lyrical the Python message ends with : names.

Short answer: an empty list has no element type, and ROS 2 parameters are typed. A params file or -p rule with [] reaches the node as a value with no type. rclcpp throws inside the Node constructor, before your code declares anything. rclpy doesn't throw at startup. It drops your default, and the first get_parameter() raises "is not initialized". The fix that worked on Humble, Jazzy and Lyrical is to keep [] out of params files, launch dictionaries and the command line, and to create the empty list in code with an explicit type:

# rclpy
from rclpy.parameter import Parameter
from rclpy.exceptions import ParameterUninitializedException

self.declare_parameter('names', Parameter.Type.STRING_ARRAY)   # no default value
try:
    names = list(self.get_parameter('names').value)
except ParameterUninitializedException:
    self.set_parameters([Parameter('names', Parameter.Type.STRING_ARRAY, [])])
    names = []
// rclcpp: the template type is what makes {} a string array
auto names = node->declare_parameter<std::vector<std::string>>("names", std::vector<std::string>{});

If the list should be empty, leave the key out of the YAML file. If a file really must say "empty", names: [""] parsed on every distro, and your code then has to drop the empty string.

What I ran

On 2026-11-15 I used the official ros:humble-ros-base, ros:jazzy-ros-base and ros:lyrical-ros-base images on a 2 vCPU Linux host, one distro at a time. Each container ran with --network none, ROS_DOMAIN_ID=88 and a 1.5 CPU limit. One ament_cmake package held two nodes. pnode.py (rclpy) declares a parameter names in one of seven ways. cnode (rclcpp) declares it in one of three ways. Each node prints the declared type and value, tries a few set_parameters calls and exits.

Every rclpy declaration ran against six inputs: no override, names: [], names: [ ], -p 'names:=[]', names: [""] and names: [a, b]. The rclcpp declarations ran against the same inputs except [ ]. That was 42 rclpy runs and 15 rclcpp runs per distro. Then I started nodes that kept spinning and ran ros2 param get, set, describe, dump and load against them. Last, a launch file passed [], [''], ['a', 'b'] and a params file to both nodes. The package built in 5.4 s on Humble, 5.6 s on Jazzy and 7.0 s on Lyrical, and each full run took under two minutes.

Humble and Jazzy behaved the same in every case. Lyrical behaved the same too, and only its messages were different. The results below hold for all three unless I name a distro.

[] in a params file or -p has no type

YAML gives [] no element type. The rcl parser passes it on as a value with nothing set. The two client libraries handle that differently.

rclcpp throws before your code runs. The exception came from the Node constructor in all 6 runs with [] or -p 'names:=[]'. It didn't matter how the node declared names: template with {}, template with {"a", "b"}, or rclcpp::PARAMETER_STRING_ARRAY. The overrides are converted inside the constructor, so my declaration lines never ran. I caught the exception to print it. My node then exited with code 3. With a /**: key, every node that reads the file gets the same override.

rclpy loses your default. For a node that declared names with ['a', 'b'], [''], or Parameter.Type.STRING_ARRAY, the empty override didn't raise anything at declare time. The parameter ended up uninitialized, and get_parameter('names') raised ParameterUninitializedException. So names: [] in a file doesn't give you an empty list. It replaces your default with "no value". This is the same exception as a parameter declared with only a type and never given a value. The params YAML errors post covers the parser errors that happen before this point. Here the file parses fine.

In rclpy, writing [ ] with a space changed nothing. names: null isn't a way out either. The parser read it as the string null, and a node with a list default rejected it with InvalidParameterTypeException.

declare_parameter('names', []) is a byte array in rclpy

rclpy picks the type from the default value. An empty Python list came out as BYTE_ARRAY on all three distros, and ros2 param describe printed Type: byte array. After that, only byte arrays fit. Setting ['x', 'y'] from code returned (False, "Wrong parameter type, expected 'Type.BYTE_ARRAY' got 'Type.STRING_ARRAY'"). ros2 param set /pnode names "['c']" failed with the same text. A params file with names: [a, b] made declare_parameter itself raise InvalidParameterTypeException. After that the parameter wasn't declared at all, and every later call raised ParameterNotDeclaredException.

Adding ParameterDescriptor(type=ParameterType.PARAMETER_STRING_ARRAY) didn't help. It's the case in rclpy issue 912. In my runs the descriptor's type was ignored with no warning. The parameter was still BYTE_ARRAY, and every result matched the plain [] case.

The same inference also affects setting an empty list later. With a STRING_ARRAY parameter, Parameter('names', value=[]) failed with expected 'Type.STRING_ARRAY' got 'Type.BYTE_ARRAY'. Parameter('names', Parameter.Type.STRING_ARRAY, []) succeeded. Pass the type whenever the list can be empty.

rclcpp doesn't have this problem in code. declare_parameter<std::vector<std::string>>("names", std::vector<std::string>{}) gave string_array with size 0. set_parameter(rclcpp::Parameter("names", std::vector<std::string>{})) returned success on a string array that held [a, b]. The C++ type carries the element type, even when the vector is empty. That's the point made in rclcpp issue 1955: the API works, and files and the command line don't.

ros2 param set and ros2 param load turn [] into a bool array

The CLI has the same problem as YAML. It also guesses the type from the value, and an empty list became BOOL_ARRAY. Against a running rclpy node with names set to ['a', 'b']:

$ ros2 param set /pnode names '[]'
Setting parameter failed: Wrong parameter type, expected 'Type.STRING_ARRAY' got 'Type.BOOL_ARRAY'
$ ros2 param get /pnode names
String values are: ['a', 'b']

Against the rclcpp node the message was Wrong parameter type, parameter {names} is of type {string_array}, setting it to {bool_array} is not allowed. ros2 param load with a file holding names: [] failed the same way, per parameter: Set parameter names failed: .... Both commands exited with code 0. A script that checks $? will think the change worked.

A non-empty list set from the CLI worked: ros2 param set /pnode names "['c']" printed Set parameter successful. I found no CLI form that set an empty string array. If you need to empty a list at runtime, do it from inside the node, or expose a service that does it.

ros2 param dump writes a file you can't load back

Older ros2 param dump versions had trouble with empty lists (ros2 issue 1517, fixed by ros2cli PR 881). With the current packages, dump worked on all three distros. For both nodes it wrote:

/pnode:
  ros__parameters:
    names: []

That output has the problem from the first section. I started the nodes again with the dumped file as --params-file. The rclcpp node threw InvalidParameterValueException from its constructor. The rclpy node, declared with Parameter.Type.STRING_ARRAY, came up with names uninitialized. ros2 param load of a file with the same names: [] line into the running nodes failed with the bool array message. If you save parameters with dump to reuse them, delete or edit the [] lines first.

Launch files: a Python [] stops the launch

Node(parameters=[{'names': []}]) never started a process. The message shows that launch_ros had turned the list into an empty tuple, and it rejected that with Expected 'value' to be one of [...], but got '()' of type '<class 'tuple'>'. ros2 launch exited with code 1. That happened for all four node setups I tried (rclpy with a list default and with a typed declaration, rclcpp with {"a", "b"} and with {}), on all three distros. It fails while launch evaluates the parameters, before any node runs.

Passing a params file from launch (parameters=['/y/empty.yaml']) got past launch and failed in the node, exactly as in the first section. The rclpy node started with names uninitialized. The rclcpp node died, and launch printed process has died [pid ..., exit code 3, ...]. ros2 launch itself still exited with code 0. parameters=[{'names': ['']}] and [{'names': ['a', 'b']}] both worked.

[""] works, but C++ prints it as []

A one-element list holding an empty string is a real string array, so every path accepted it. names: [""] in a file, [''] in a launch dictionary and declare_parameter('names', ['']) all gave STRING_ARRAY with one element in rclpy and string_array with size 1 in rclcpp. Your code has to treat [''] as empty, for example with [n for n in names if n].

One trap with this workaround: rclcpp::Parameter::value_to_string() printed that one-element array as []. In my log the line was string_array [] size=1. Without the size I couldn't tell [""] from a real empty list. If you log parameters in C++, log the size as well.

dynamic_typing in rclpy

With ParameterDescriptor(dynamic_typing=True) and a default of [], rclpy declared a BYTE_ARRAY, but later string lists were accepted. With names: [] or -p 'names:=[]', it came up as NOT_SET with value None, and nothing raised. That makes "empty" easy to detect (value is None), but the parameter no longer has a fixed type, so nothing checks what a file puts in it. I would use it only when the parameter must stay dynamic anyway.

Version notes

  • Behavior was the same on Humble (rclpy 3.3.22, rclcpp 16.0.21), Jazzy (rclpy 7.1.12, rclcpp 28.1.22) and Lyrical (rclpy 10.0.11, rclcpp 32.0.3). None of them accepted [] from a file, -p, the CLI or a launch dictionary.
  • rclcpp message: Humble and Jazzy say No parameter value set. Lyrical says Invalid parameter value: rcl parameter structureContains no value. Search for parameter_value_from failed for parameter to match both.
  • rclpy messages: Humble prints ('Invalid access to undeclared parameter(s)', 'names') as a tuple. Jazzy and Lyrical print Invalid access to undeclared parameter(s): names and add : names to the other exceptions.
  • rclpy on Lyrical prints type numbers in Wrong parameter type: expected '5' got '9' where Humble and Jazzy print expected 'Type.BYTE_ARRAY' got 'Type.STRING_ARRAY'.
  • ros2 param dump also writes start_type_description_service: true on Jazzy and Lyrical. The names: [] line was the same on all three.
  • When my script stopped the spinning rclpy node with kill (SIGTERM), rclpy.spin raised ExternalShutdownException. One Lyrical run raised RCLError instead. That had nothing to do with parameters, but it may show up in your logs.

Not tested

Integer, double and bool arrays (all tests used strings), XML and YAML launch files, composable nodes and component containers, generate_parameter_library, Nav2 or ros2_control parameter files, allow_undeclared_parameters, RMWs other than Fast DDS, Foxy, Iron, Kilted and Rolling. I also didn't measure timing, since none of these failures depends on it.

FAQ

Can a ROS 2 parameter be an empty list?

Yes, from code. rclcpp declared and set an empty std::vector<std::string> without errors, and rclpy accepted an empty list when the type was passed (Parameter('names', Parameter.Type.STRING_ARRAY, [])). No params file, -p rule, ros2 param set or launch dictionary with [] worked on Humble, Jazzy or Lyrical.

What does "parameter_value_from failed for parameter: No parameter value set" mean?

An override for that parameter had no type, which is what [] in a params file or -p turns into. rclcpp throws it from the Node constructor, before your declarations run. Remove the [] line, or use [""] and filter it in code. On Lyrical the text is rcl parameter structureContains no value.

Why is my rclpy parameter a byte array?

declare_parameter('names', []) can't see an element type, and rclpy made it BYTE_ARRAY on all three distros, even with a ParameterDescriptor that said PARAMETER_STRING_ARRAY. Declare it with Parameter.Type.STRING_ARRAY instead.

Why does ros2 param set with [] say BOOL_ARRAY?

The CLI reads [] as a bool array. A string array parameter then rejects it, in rclpy and rclcpp. The command still exits with code 0. Set the empty list from inside the node.

Can I load the file that ros2 param dump wrote?

Not if it has names: [] in it. At startup the rclcpp node threw and the rclpy node came up with the parameter uninitialized. ros2 param load into a running node failed with the bool array message. Delete or edit those lines before you reuse the file.
