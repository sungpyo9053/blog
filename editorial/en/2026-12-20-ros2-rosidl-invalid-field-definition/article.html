The same build step also stops with NameError: 'maxSpeed' is an invalid field name. It should have the pattern '^(?!.*__)(?!.*_$)[a-z][a-z0-9_]*$', with InvalidResourceName, or with InvalidServiceSpecification: Could not find separator. All of these come from one parser reading your .msg, .srv or .action file.

Short answer: InvalidFieldDefinition means a line in your interface file has a type but no field name. Every line needs both, type first, then a name:

# msg/TwistAccel.msg
geometry_msgs/Twist twist
geometry_msgs/Accel accel

Write the type as geometry_msgs/Twist, not geometry_msgs/msg/Twist. Use lowercase snake_case for field names, and use the ROS primitive names (float64, int32), not C names (double, int). If you use a type from another package, add find_package(geometry_msgs REQUIRED) and DEPENDENCIES geometry_msgs to rosidl_generate_interfaces(). With those changes the package built and imported on Humble, Jazzy and Lyrical.

InvalidFieldDefinition: the line has a type but no name

This is the Stack Overflow case. The file had two lines, geometry_msgs/Twist and geometry_msgs/Accel, with no names after them. The parser splits each line into a type and a name. If there is only one token, it raises InvalidFieldDefinition and prints that line. The Error with: v_no_name TwistAccel geometry_msgs/Twist line above it gives the package, the message and the line.

One answer there blamed missing dependencies. In my run, a missing dependency fails later and with a different error (see below), so InvalidFieldDefinition always means the file itself. The asker also tried geometry_msgs/msg/Twist. That doesn't help. Inside a .msg file the type is package/Type. The /msg/ part belongs to the C++ include path and the Python import, not to the interface file. Even with a name added, geometry_msgs/msg/Twist twist failed with InvalidResourceName: geometry_msgs/msg/Twist.

The fix is a name after each type: geometry_msgs/Twist twist. The interface docs (About ROS 2 interfaces) say: "Each field consists of a type and a name, separated by a space".

"is an invalid field name": lowercase snake_case only

Field names must match ^(?!.*__)(?!.*_$)[a-z][a-z0-9_]*$. In words, a name starts with a lowercase letter and then uses only lowercase letters, digits and underscores. It can't contain two underscores in a row, and it can't end with an underscore. All six names I tried that break one of these rules failed with the same NameError: Speed, maxSpeed, max__speed, speed_, 2d_speed and max-speed. A ROS 1 message with maxSpeed needs max_speed when you port it.

The same error appeared for float64 [] values. The space before [] made [] the second token, so the parser read it as the field name. Write float64[] values, with no space.

Two fields with the same name gave ValueError: the fields iterable contains duplicate names: count. The message names the field but not the line, so search the file for that name.

"is an invalid message name" on a field line: the type is wrong

This one is easy to misread. float speed failed with 'float' is an invalid message name, even though the file was named Speed.msg, which is valid. The parser didn't know float as a primitive. It treated it as the name of another message and then rejected it because message names must start with a capital letter. int and double failed the same way. Use float32 or float64, and int32 or int64. The full list of primitives is on the interfaces page linked above.

A lowercase type from another package, geometry_msgs/twist twist, failed with the same error for 'twist'. Type names keep their CamelCase form in the file, even though the generated C++ header is twist.hpp.

When the error quotes a word that isn't your file name, look for that word as a type on one of your lines. Whether the file name itself is valid is a separate check. This post doesn't cover it.

Constants and default values

A constant is type NAME=value, and the name must be uppercase. It has to match ^[A-Z]([A-Z0-9_]?[A-Z0-9]+)*$. int32 max_count=10 failed with 'max_count' is an invalid constant name, and int32 MAX_COUNT=10 built. A default value has no =. It is a third token: int32 count 5. The value has to fit the type. int32 count 1.5 failed with InvalidValue: value '1.5' can not be converted to type 'int32'. Above that line the log has two Python ValueError: invalid literal for int() lines. They are part of the same failure, not separate problems. String defaults in double quotes worked, and so did the string constant NAME="robot".

Services and actions: the --- separators

A .srv file needs exactly one line that is exactly ---, between the request and the response. With none I got Could not find separator '---' between request and response. That is the error in CMake Error could not find Seperator. Four dashes (----) gave the same message, because the line has to match exactly. Two --- lines gave Could not find unique separator.

An .action file needs two separators, for goal, result and feedback. With one I got InvalidActionSpecification: Number of '---' separators nonconformant with action definition.

A field named class: the parser accepts it, the compiler doesn't

int32 class matches the field-name pattern, so rosidl_adapter accepted it. The build then failed in the generated C header: speed__struct.h:23:16: error: expected identifier before ‘;’ token on Humble, and the same error at line 25 on Jazzy and Lyrical. More errors followed in the generated C and C++ code, such as expected unqualified-id before ‘class’. The reserved words question hit the same thing with a field named register. Renaming the field fixed it there. The parser let class through, and only the compiler rejected it. In my run a field named type was fine, and Python read it as m.type. If you get compiler errors in a __struct.h file under build/, look at the field named on that line and rename it.

Missing dependency: a different error on each distro

When geometry_msgs/Twist was used without find_package(geometry_msgs REQUIRED) and DEPENDENCIES geometry_msgs, the parser had no complaint. On Humble the compiler then failed with fatal error: geometry_msgs/msg/detail/twist__struct.h: No such file or directory. On Jazzy and Lyrical it failed earlier, in the type description generator, with only KeyError: 'geometry_msgs'. Leaving out just DEPENDENCIES geometry_msgs gave the same results. find_package alone isn't enough. The fixed CMakeLists.txt part looked like this:

find_package(rosidl_default_generators REQUIRED)
find_package(geometry_msgs REQUIRED)
rosidl_generate_interfaces(${PROJECT_NAME}
  "msg/TwistAccel.msg"
  DEPENDENCIES geometry_msgs
)

My package.xml had <depend>geometry_msgs</depend>, <buildtool_depend>rosidl_default_generators</buildtool_depend>, <exec_depend>rosidl_default_runtime</exec_depend> and <member_of_group>rosidl_interface_packages</member_of_group>. I didn't test those tags one at a time.

What did not cause errors

Three suspects turned out fine. Comments, both full-line and inline, built. A tab between type and name built. A file with Windows CRLF line endings built, and the field names came out clean (speed, count, no trailing \r). If your file came from Windows and fails, the line endings aren't the cause. Look for one of the errors above.

FAQ

What does rosidl_adapter.parser.InvalidFieldDefinition mean?

A line in your .msg or .srv file has a type and no field name, for example geometry_msgs/Twist on its own. Add a name: geometry_msgs/Twist twist. The error prints the line it couldn't parse.

Why is my field name invalid in a ROS 2 message?

Field names must be lowercase snake_case: a lowercase first letter, then lowercase letters, digits and underscores, with no double underscore and no trailing underscore. Speed, maxSpeed, max__speed, speed_, 2d_speed and max-speed all failed. max_speed works.

Why does float speed give "'float' is an invalid message name"?

float isn't a ROS primitive, so the parser treated it as a message type and rejected the lowercase name. Use float32 or float64. int and double failed the same way.

How do I fix "Could not find separator" in a .srv file?

Put one line containing exactly --- between the request and response fields. Four dashes gave the same error. Two separator lines gave "Could not find unique separator". An .action file needs two separators.

Should I write geometry_msgs/msg/Twist in a .msg file?

No. Inside interface files the type is geometry_msgs/Twist. geometry_msgs/msg/Twist twist failed with InvalidResourceName on Humble, Jazzy and Lyrical. Declare the package with find_package and DEPENDENCIES in rosidl_generate_interfaces().
