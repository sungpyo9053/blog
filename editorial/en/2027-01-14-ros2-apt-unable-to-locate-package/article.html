$ apt-get install -s ros-humble-joint-state-publisher-gui
Building dependency tree...
Reading state information...
E: Unable to locate package ros-humble-joint-state-publisher-gui

The same line shows up for any ROS 2 package: ros-jazzy-desktop, ros-humble-joint-state-publisher-gui, ros-humble-gazebo-ros2-control during rosdep install, ros-kilted-ros-base on a new Ubuntu. apt exits with code 100 and installs nothing.

Short answer: apt only knows the names in the package lists it downloaded during the last apt-get update. "Unable to locate" means the name isn't in any of them. Check four things, in this order:

# 1. Is the ROS 2 repository configured?
ls /etc/apt/sources.list.d/        # look for ros2.sources (or ros2.list)

# 2. Did you update after adding it?
sudo apt-get update                # the output must contain a packages.ros.org line

# 3. Does this Ubuntu release carry this ROS distro?
. /etc/os-release; echo $VERSION_CODENAME   # jammy = Humble, noble = Jazzy/Kilted, resolute = Lyrical
apt-cache pkgnames ros- | cut -d- -f2 | sort | uniq -c | sort -rn | head -5

# 4. Is the name spelled the way apt spells it?
apt-cache search --names-only joint.state.publisher

If all four look right, the package may simply not exist for your distro or your CPU. Gazebo Classic packages are gone from Jazzy and Lyrical, and they were never built for arm64 on Humble. I measured each of these causes in the official Humble, Jazzy and Lyrical Docker images and in a plain ubuntu:22.04 container.

What I ran

On 2026-11-13 I used the official ros:humble-ros-base (Ubuntu 22.04), ros:jazzy-ros-base (24.04) and ros:lyrical-ros-base (26.04) images and ubuntu:22.04, all amd64. Every test used apt-get install -s, which resolves the full dependency set and prints the result without installing anything. "Inst lines" below counts the packages apt would have installed. On each distro I ran:

  • A fresh container with no apt-get update, then one with it.
  • The right name, the same name with underscores, and three names in one command where one doesn't exist.
  • ros-<X>-ros-base for Foxy, Humble, Iron, Jazzy, Kilted, Lyrical and Rolling, to see which distros each Ubuntu release carries.
  • Gazebo Classic packages (gazebo-ros-pkgs, gazebo-ros2-control, gazebo-ros) and their replacements (ros-gz, gz-ros2-control).

Cause 1: no apt-get update, or no ROS repository

The official ROS images ship with the ROS 2 repository configured (/etc/apt/sources.list.d/ros2.sources) but with no package lists. All three images had 0 index files under /var/lib/apt/lists. So in a fresh container even a correct name fails, and one apt-get update (under 8 seconds here) fixes it. This is the usual cause in Dockerfiles: put apt-get update in the same RUN line as the install.

On plain Ubuntu the ROS repository isn't there at all. ubuntu:22.04 after a normal apt-get update still said Unable to locate package ros-humble-ros-base, because Ubuntu's own archive has no ros-humble-* packages. The current install guides add the repository with the ros2-apt-source package. I fetched the latest release tag from GitHub, which was 1.3.0:

sudo apt-get update
sudo apt-get install -y curl
export ROS_APT_SOURCE_VERSION=$(curl -s https://api.github.com/repos/ros-infrastructure/ros-apt-source/releases/latest | grep -F "tag_name" | awk -F\" '{print $4}')
curl -L -o /tmp/ros2-apt-source.deb "https://github.com/ros-infrastructure/ros-apt-source/releases/download/${ROS_APT_SOURCE_VERSION}/ros2-apt-source_${ROS_APT_SOURCE_VERSION}.$(. /etc/os-release && echo $VERSION_CODENAME)_all.deb"
sudo dpkg -i /tmp/ros2-apt-source.deb
sudo apt-get update
sudo apt-get install ros-humble-ros-base

Installing the .deb isn't enough by itself. Right after dpkg -i, before the update, I got the same Unable to locate package ros-humble-ros-base. After apt-get update printed Get:1 http://packages.ros.org/ros2/ubuntu jammy InRelease, the simulated install resolved 439 packages. That packages.ros.org line is what to look for. If your update output has no such line, or has an error on it, apt never got the ROS list, and every ros-* name will fail. One of the questions below (116862) has exactly that: The repository 'http://packages.ros.org/ros2/ubuntu noble InRelease' is not signed before the "Unable to locate" error. That case is the expired signing key, which I measured separately in the EXPKEYSIG F42ED6FBAB17C654 fix.

Cause 2: this Ubuntu release doesn't carry that ROS distro

Each ROS 2 distro is built for specific Ubuntu releases, and the repository keeps a separate index per release. The ROS 2 sources file uses your Ubuntu codename as the suite, so a 20.04 machine downloads the focal index, and the focal index has no Humble in it. These are the counts of ros-<distro>- packages I found in each amd64 index on 2026-11-13 (distros with more than 20 packages):

I reproduced the 20.04 case by pointing the working jammy setup at the focal suite. The update succeeded (Get:1 http://packages.ros.org/ros2/ubuntu focal InRelease), and ros-humble-ros-base went straight back to "Unable to locate". Nothing in the update output warns you. In the Jazzy image, ros-humble-desktop failed the same way, and in the Lyrical image so did ros-humble-desktop, ros-jazzy-ros-base and ros-kilted-ros-base. That matches the Kilted on 26.04 question below. Of the four indexes I checked, Kilted was only in noble.

The fix is to match the distro to the OS: Humble on 22.04, Jazzy or Kilted on 24.04, Lyrical on 26.04. If you need an older distro on a newer OS, run it in the matching ros:<distro> Docker image. Before you change anything, run this to see which distros your index actually has:

apt-cache pkgnames ros- | cut -d- -f2 | sort | uniq -c | sort -rn | head -5

On 22.04 this also lists a few names like ros-desktop and ros-base with no distro in them, and apt-cache search showed joint-state-publisher-gui without the ros-humble- prefix. They aren't Humble packages. Keep the full ros-humble- prefix.

Cause 3: the name is spelled the ROS way, not the apt way

ROS package names use underscores (joint_state_publisher_gui). Debian package names can't, so the apt name swaps every underscore for a dash and adds ros-<distro>- in front. ros-humble-joint_state_publisher_gui failed on all three distros, and the dashed name worked. If you're not sure of the name, search with a dot in place of the separator, since apt-cache search takes a regular expression:

$ apt-cache search --names-only joint.state.publisher
ros-humble-joint-state-publisher - This package contains a tool for setting and publishing joint state values for a given URDF.
ros-humble-joint-state-publisher-gui - This package contains a GUI tool for setting and publishing joint state values for a given URDF.
...

One bad name blocks the whole command. apt-get install -s ros-humble-joint-state-publisher-gui ros-humble-xacro ros-humble-not-a-package exited with code 100 and 0 Inst lines, even though two of the three names were fine. The error names only the bad package. rosdep install passes the apt names to apt-get install, so one missing name there ends in apt: command [...] failed, as in the Raspberry Pi question below.

Cause 4: the package isn't built for your distro or your CPU

Here the repository, the update and the spelling can all be right. Gazebo Classic (gazebo-ros-pkgs, gazebo-ros2-control, gazebo-ros) was available for Humble on amd64 and missing everywhere else I looked. On Jazzy, ros-jazzy-gazebo-ros2-control and ros-jazzy-gazebo-ros gave "Unable to locate". ros-jazzy-gazebo-ros-pkgs gave a different message:

Package ros-jazzy-gazebo-ros-pkgs is not available, but is referred to by another package.
This may mean that the package is missing, has been obsoleted, or
is only available from another source
E: Package 'ros-jazzy-gazebo-ros-pkgs' has no installation candidate

apt knows that name only because another package in the index still lists it as a dependency. apt-cache showpkg named ros-jazzy-dolly-gazebo. On Lyrical all three were "Unable to locate". The replacements, ros-<distro>-ros-gz and ros-<distro>-gz-ros2-control, were available on all three distros.

The arm64 indexes are nearly as large as amd64 (jammy: 3679 Humble packages vs 3786), but they aren't identical. On jammy arm64, ros-humble-gazebo-ros2-control and ros-humble-gazebo-ros-pkgs are absent, while ros-base, desktop, rviz2, ros-gz and joint-state-publisher-gui are there. That explains the Raspberry Pi 4 rosdep failure below. A GUI package like joint-state-publisher-gui was present on arm64 for Humble, Jazzy, Kilted and Lyrical, so on a 64-bit Pi an "Unable to locate" for it points back to causes 1 to 3. The armhf indexes for jammy, noble and resolute had no ROS 2 packages at all. Focal armhf had only 23 Foxy packages. On a 32-bit OS, install a 64-bit one.

To check a package for another architecture without that machine, download the index and search it. This is what my script did:

curl -s http://packages.ros.org/ros2/ubuntu/dists/jammy/main/binary-arm64/Packages.gz | gunzip | grep -c "^Package: ros-humble-gazebo-ros2-control$"

Not this error: universe disabled

The install guides tell you to enable Ubuntu's universe component. With the ROS repository working and universe removed, ros-humble-ros-base was found, but apt couldn't resolve it:

 ros-humble-ament-cmake-pytest : Depends: python3-pytest but it is not installable
 ros-humble-ament-flake8 : Depends: python3-flake8 but it is not installable
 ros-humble-class-loader : Depends: libconsole-bridge1.0 (>= 1.0.1+dfsg2) but it is not installable

If you see "but it is not installable" for ordinary Ubuntu packages, the ROS side is fine. Run sudo add-apt-repository universe and update.

FAQ

Why does apt say "Unable to locate package ros-humble-desktop" on Ubuntu 20.04 or 24.04?

Humble packages are only in the Ubuntu 22.04 (jammy) index. The focal index had Foxy, Galactic and Rolling, and the noble index had Jazzy, Kilted and Rolling. On 20.04 or 24.04 the name doesn't exist. Use Jazzy on 24.04, or run Humble in the ros:humble Docker image.

I added the ROS 2 repository and still get Unable to locate package. Why?

Run sudo apt-get update after adding it, and check that the output has a packages.ros.org line without errors. Right after installing ros2-apt-source the install still failed. It worked only after the update downloaded the jammy index.

Why does apt-get install fail in a fresh ros:humble Docker container?

The official images have the repository configured but no package lists: 0 index files on Humble, Jazzy and Lyrical. Run apt-get update in the same RUN line as the install.

How do I install gazebo_ros2_control on Jazzy or on a Raspberry Pi?

You can't from apt. ros-jazzy-gazebo-ros2-control doesn't exist, and on Humble the arm64 index has no Gazebo Classic packages. Use ros-<distro>-gz-ros2-control and ros-<distro>-ros-gz with the new Gazebo. Both were available on amd64 for all three distros, and ros-gz was in every arm64 index I checked.

Do I use underscores or dashes in ROS 2 apt package names?

Dashes, with ros-<distro>- in front: ros-humble-joint-state-publisher-gui. The underscore version failed on all three distros. apt-cache search --names-only joint.state.publisher lists the real names.
