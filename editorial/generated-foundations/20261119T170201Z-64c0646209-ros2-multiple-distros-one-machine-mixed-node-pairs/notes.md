# Purpose-built educational example

제한된 산술 교육 모델이다. 로봇 벤치마크도 통신 성공률 예측도 아니다. 실행할 노드를 (배포판, RMW) 묶음으로 분류하고 노드 쌍의 개수를 센다. 근거는 Releases 문서의 'Nodes are not guaranteed to be able to communicate across distributions'와 'cross-vendor (single-distro) communications are also not guaranteed' 두 문장, 그리고 설치 문서의 'The default middleware that ROS 2 uses is Fast DDS, but the middleware (RMW) can be replaced at runtime' 문장이다. 같은 배포판·같은 RMW 묶음 안의 쌍은 '보장 범위', 나머지는 '보장 밖'으로 센다. 단위는 노드 쌍의 수(무차원)이고 비율은 0~1이다. 최악의 경우를 보려고 모든 노드 쌍이 서로 통신한다고 가정했다. 입력은 세 상황으로 골랐다. (A) 같은 배포판·Fast DDS 노드 4개에 같은 배포판·다른 RMW 노드 1개와 다른 배포판·Fast DDS 노드 1개를 섞은 6노드 그래프, (B) 모두 같은 묶음인 대조군, (C) 다른 배포판 노드를 하나만 섞은 경계 사례다. 마지막 두 사례는 Releases 표의 EOL(Kilted 2026년 12월, Lyrical 2031년 5월)과 확인 시점인 2026년 11월로 두 번째 배포판의 남은 지원 개월을 센다. 같은 Ubuntu에 두 배포판의 deb가 모두 있는지는 이 계산이 전제하지 않는다. 본문 실험은 공존 자체를 측정할 질문으로 다룬다. 하나의 Ubuntu 코드네임 컨테이너에서 먼저 두 배포판 ros-base 패키지의 apt 후보가 있는지 확인한다. 둘 다 있으면 설치하면서 apt 종료 코드와 제거·충돌 보고를 기록한다. 설치가 되면 네 경우(A만 source, B만 source, A 다음 B, source 안 함)에서 ROS_DISTRO, AMENT_PREFIX_PATH 항목 수, ros2 pkg list 개수를 기록하고, 서로 다른 배포판의 talker·listener 사이에서 정해진 수의 메시지 가운데 몇 개가 수신되는지 5회 센다. 후보가 없거나 설치가 충돌하면 그 사실을 결과로 기록한다. 측정값은 실행 후에만 적는다.

여러 배포판을 '같은 컴퓨터에 설치'하는 일과 '한 그래프에서 통신'시키는 일은 따로 판단해야 한다. 앞쪽은 공식 문서가 답하지 않으므로 내 Ubuntu에서 apt 후보와 충돌 여부를 직접 확인한다. 뒤쪽은 노드를 (배포판, RMW) 묶음으로 나눠 세면 된다. 6노드 그래프에서 다른 배포판 노드 하나만 섞여도 15쌍 중 5쌍(약 33%)이 공식 문서상 보장 밖이고, RMW까지 하나 더 섞이면 9쌍(60%)이다. 모두 같은 묶음일 때만 0이 된다. 독자가 할 일은 세 가지다. 첫째, 보장 밖 쌍이 1 이상이면 그 노드를 같은 배포판으로 다시 빌드하거나 따로 떼어 실행한다. 둘째, 시험용 배포판을 고르기 전에 남은 지원 개월을 계산한다. Kilted라면 1개월뿐이다. Rolling은 제자리 업데이트로 호환을 깨는 변경이 들어올 수 있고 지원 플랫폼도 달라질 수 있다. 셋째, 터미널마다 setup.bash를 하나만 source한다. 이것은 문서가 정한 규칙이 아니라 이 글의 운용 선택이며, 두 번 source했을 때 무엇이 남는지는 실험으로 확인한다.

'보장되지 않음'은 공식 문서가 밝힌 지원 범위를 말할 뿐, 통신이 실패한다는 예측이 아니다. 이 산술로는 수신률이나 지연을 알 수 없다. 모든 노드 쌍이 통신한다는 최악의 가정을 썼으므로, 실제로 토픽을 공유하는 쌍만 세면 수가 줄어든다. 제공된 문서는 두 배포판을 apt로 함께 설치할 수 있는지, Ubuntu 코드네임별로 어떤 배포판의 deb가 있는지, setup.bash를 두 번 source하면 환경 변수가 어떻게 되는지를 말하지 않는다. 그래서 이 글은 이 셋을 주장하지 않고 측정 항목으로만 다룬다. 남은 지원 개월은 Releases 표의 연·월 단위 EOL로 계산했으며 일 단위 날짜는 반영하지 않았다. ROS 1과 ROS 2를 함께 설치하는 경우, ROS_DOMAIN_ID로 그래프를 나누는 방법, 소스 빌드와 디스크 사용량은 제공된 출처로 뒷받침할 수 없어 범위에서 뺐다. 실물 로봇과 시뮬레이터는 다루지 않는다.
