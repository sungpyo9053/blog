# Purpose-built educational example

교육용 산술 모델이다. tf_transformations README에 따르면 tf 계열은 쿼터니언을 x,y,z,w 순서로, transforms3d는 w,x,y,z 순서로 돌려준다. 여기서는 x,y,z,w 순서를 기대하는 소비자 코드가 transforms3d 출력을 순서 변환 없이 받는 상황을 가정한다. 단위 쿼터니언을 회전 행렬로 바꾸는 표준 식 가운데 몇 원소만 사칙연산으로 계산한다. r00 = 1 − 2(y² + z²)는 전방 축 (1,0,0)이 회전 후 갖는 x 성분, r11 = 1 − 2(x² + z²)는 좌측 축 (0,1,0)이 회전 후 갖는 y 성분, r10 = 2(xy + wz)다. 입력값은 0, 1, 0.5처럼 이진 부동소수점으로 정확히 표현되는 값만 골라 반올림 오차를 없앴다. 쿼터니언 성분은 단위가 없고, 행렬 원소는 단위 벡터의 성분이라 역시 단위가 없다. 각도 차이만 도(°) 단위로 쓴다. 고른 사례는 다음과 같다. yaw 180°(tf 순서 (0,0,1,0))는 방향이 정반대로 바뀌어 차이가 눈에 띄는 대표 사례다. 항등 회전(tf (0,0,0,1), transforms3d (1,0,0,0))은 '회전 없음'이 x축 180° 뒤집힘으로 바뀌는 경계 사례다. 네 성분이 같은 쿼터니언은 순서 실수가 보이지 않는 반례다.

순서 변환 없이 transforms3d 출력을 x,y,z,w 소비자에 넘기면 yaw 180° 자세가 회전 없음으로 읽힌다. 전방 축의 x 성분은 −1에서 +1로 바뀌고, 방향 차이는 180°다. 거꾸로 항등 회전은 x축 180° 뒤집힘이 되어 좌측 축의 y 성분이 1에서 −1로 바뀐다. 그런데 두 경우 모두 쿼터니언 크기 제곱은 1이라 정규화 검사는 통과한다. 성분이 모두 같은 쿼터니언은 순서를 바꿔도 차이 제곱합이 0이라 테스트 입력으로 쓸모가 없다. 따라서 tf_transformations를 apt로 설치해 import만 바꾸는 경로라면 순서는 기존 tf와 같은 x,y,z,w로 유지된다. transforms3d로 옮긴다면 변환 지점마다 순서를 명시적으로 바꾸고, 성분이 서로 다른 기준 쿼터니언과 그 회전 결과의 기대 좌표로 단위 테스트를 둔다.

이 모델은 사칙연산으로 회전 행렬 원소 몇 개만 계산하는 교육용 산술이다. 쿼터니언→회전 행렬 식은 표준 수학식이며 README나 REP-103에 실린 식이 아니다. transforms3d와 tf_transformations 함수를 실제로 실행하거나 apt 설치를 검증하지 않았다. 따라서 배포판별 패키지 제공 여부, 함수별 인자·반환 형식(euler 축 순서 지정 포함), README가 '아직 통합되지 않았다'고 밝힌 함수의 동작은 이 계산으로 알 수 없다. yaw 90°처럼 성분이 무리수인 일반 각도와 3D 자세, ROS 메시지(geometry_msgs/Quaternion) 필드 대입 코드, 실물 로봇의 방향 오차와 안전 영향도 다루지 않았다.
