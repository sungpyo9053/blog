# Purpose-built educational example

REP-103에 따르면 6차원 공분산은 행 우선으로 저장한 float64[36] 배열이고, 파라미터 순서는 (x, y, z, X축 회전, Y축 회전, Z축 회전)입니다. 선가속도 공분산은 x, y, z 순서의 3×3 행 우선 float64[9] 배열입니다. 인덱스는 0부터 세며, n×n 행렬의 (행 r, 열 c) 원소는 n×r+c 칸에 들어갑니다. yaw는 Z축 회전이므로 행·열 번호 5입니다. 단위는 REP-103의 SI 규약을 따라 각도를 radian으로 두므로 각도 분산의 단위는 rad²입니다. 입력값은 역할별로 골랐습니다. 목표 칸(35), 대각 원소 간격(7), 대칭 원소 쌍(5와 30), 3×3 배열에 같은 공식을 적용한 경우(8)를 보여 줍니다. 여기에 흔한 실수 세 가지, 즉 1부터 센 인덱스(42), 표준편차를 분산 칸에 넣은 경우(10배), 도 단위를 쓴 경우(약 3283배)를 반례로 넣었습니다. 표준편차 0.1 rad와 5도는 설명용 값이며 특정 센서의 사양이 아닙니다.

yaw 표준편차 0.1 rad는 float64[36] 배열의 35번 칸에 분산 0.01로 넣습니다. 대각 원소는 0, 7, 14, 21, 28, 35번에 있고, 비대각 원소는 5번과 30번처럼 대칭 쌍으로 같은 값을 가져야 합니다. 1부터 세면 인덱스가 배열 범위를 벗어납니다. 표준편차나 도 단위 값을 그대로 넣으면 불확실성이 10배나 약 3283배로 부풀려진 채 전달되고, 받는 쪽에서는 이것을 형식 오류로 알아챌 수 없습니다. 독자가 할 일은 공분산을 채우는 코드 옆에 두 가지 테스트를 두는 것입니다. 인덱스 35의 값이 0.1×0.1과 같은지, 그리고 5번과 30번이 같은 값인지 확인합니다.

이 계산은 REP-103이 정한 저장 순서와 SI 단위 규약을 산술로 확인한 것입니다. ROS 노드나 메시지 직렬화, 추정 필터는 실행하지 않았습니다. REP-103은 공분산이 어느 좌표 프레임 기준인지, 알 수 없는 값을 어떻게 표시하는지, 어떤 메시지 필드가 이 배열을 쓰는지는 이 부분에서 정하지 않습니다. 따라서 그런 규칙은 이 예제로 판단할 수 없습니다. '대각 원소는 분산'이라는 해석은 일반 통계 정의이며 REP-103의 문장이 아닙니다. REP-103에 따르면 자세 자체는 쿼터니언을 선호하지만 공분산의 회전 파라미터는 고정축 회전 표현을 씁니다. 그래서 쿼터니언 성분의 불확실성을 이 칸에 그대로 옮길 수는 없습니다. 분산 값이 맞는다고 해서 추정 불확실성이 실제 오차와 맞는다는 뜻도 아니고, 실물 로봇의 동작이나 안전과도 무관합니다.
