상태: PROPOSED. 글 50·96·290·373·698·699의 본문만 대상으로 한다. 132·301·749의 별도 manifest는 수정하지 않았다. 자체 승인·새 글·WordPress 쓰기·원격 쓰기·commit/push는 없다. 전체 점수나 AdSense 결과를 이 제안의 통과 여부로 대신하지 않는다.

## 조사에서 수정으로 연결한 내용

- **96:** 백업의 다섯 필드와 `targets`가 정수 ID 배열인 구조를 `scripts/backfill_internal_links.py`와 대조했다. 독자가 자신의 백업에서 원문 부재와 잘못된 변경 계획을 먼저 걸러낼 수 있도록 완전한 표준 라이브러리 검사 하나를 추가한다. 기본 실행은 메모리 안의 정상/빈 원문 대조이며, 첫 줄에 파일 인자를 넣으면 10MB 이하 로컬 JSON을 읽는다. 파일과 네트워크에 쓰지 않는다. 복원 성공·URL 도달성·원문 진위는 검사하지 않으며 빈 본문을 바꾸는 계획도 보류하는 좁은 정책임을 본문에 적었다. 과거 11건 조사와 이번 합성 대조를 구분한다.
- **50·290:** 기존 준비 문단을 하나로 합치고 공개 검증 revision `170c6ba70c419501171ae741b318a2fb6f4ac38d`를 checkout하도록 한다. 기존 작업 폴더를 바꾸지 않도록 빈 별도 디렉터리를 명시한다. 새 venv와 requirements 설치 뒤 50의 3테스트, 290의 성공/실패 2테스트를 수행했다. 기존 역사 로그의 시간과 수치는 바꾸지 않는다.
- **373:** 환경/재현 안내가 인접 두 문단에서 반복되던 부분을 하나로 합쳤다. 출력과 실행 코드는 보존했다. 추가로 과거 로그 발췌용 sed 명령 안에 남아 있던 운영 절대경로를 비식별한 발췌 설명으로 바꿨다. 이는 실행용 Bash가 아니라 과거 text 로그 블록이다. 로그 본문과 실제 실패 결과는 바꾸지 않았다.
- **698:** 상태 코드 목록을 좁히려 했다는 내면 경험 대신 ‘목록만 좁혀도 HTML 200은 구분되지 않는다’는 객관적 비교로 바꿨다. 과거 4테스트와 현재 ID 검사 보강 후 5테스트의 차이를 재실행 명령 바로 앞에서도 명확히 했다.
- **699:** ‘완료 표시를 하려다 발견했다’, ‘처음에는 메타 검사만 두려 했다’는 경험 서술을 fixture에 실제 들어 있는 값과 검사 간 차이로 바꿨다. URL 충돌 1→0, 통제 실험, 검색엔진/AdSense 보장 아님이라는 기존 사실은 유지한다.

## 고정 버전 검증

첫 HTTPS 새 clone 시점에는 로컬 최신 UI commit `8ddc7dd`가 원격에 없어 해당 checkout이 실패했다. 이를 성공으로 처리하지 않았고, 공개 원격에 존재하는 `170c6ba70c419501171ae741b318a2fb6f4ac38d`를 선택했다. 관련 publisher 구현·두 테스트 파일·requirements는 로컬 현재 코드와 바이트 비교한다. 정확 파일 해시는 `verification.json`에 남긴다.

두 글의 제안 준비 블록은 동일하다. 검증기는 해당 HTML에서 코드를 unescape하여 그대로 추출하고, 빈 임시 디렉터리에서 HTTPS clone → 고정 revision → 새 venv → requirements 설치를 실행한다. 이어서 각 글의 실제 테스트 블록을 실행한다. Python 3.12.9를 `python3`로 선택한 환경이며 기존 venv를 재사용하지 않는다. 다운로드는 네트워크를 사용하지만 테스트는 fake/고정 입력이다. 의존성 범위까지 영구 동결한 lockfile은 아니므로 향후 패키지 변경 시 재검증이 필요하다.

## 확인 산출물과 남은 검수

`verification.json`은 실제 실행이 모두 끝나야 생성된다. 이 파일에 최종 manifest/body/block SHA, 시각, 각 명령의 종료 코드와 정제된 출력, 전체 인벤토리 해시가 들어간다. 이전 버전 검사 로그를 새 실행 결과로 바꾸지 않는다.

96의 실행에는 두 내장 대조 외에 실제 파일 인자 경로의 정상·빈 원문·ID 중복·bool ID·타깃 중복·자기 참조·변경 없는 본문·빈 목록·타깃 부재·잘못된 JSON을 사용한다. 입력 파일의 바이트와 파일 수가 실행 전후 같은지도 확인한다. 이것은 운영 11건 백업의 복원 검증이 아니라 새 독자 예제의 동작 검증이다.

373은 변경하지 않은 전체 예제를 새 checkout에서 실행하고, 698은 보강된 진단 테스트 5개를 같은 환경에서 확인한다. 전체 123건(공개10/초안113) 비교에는 2차 6편과 별도 1차 3편의 최종 제안 본문을 함께 반영한다. 기본 편집 게이트 통과는 의미적 중복·문체의 독립 Reviewer 검수를 대신하지 않는다.

인벤토리는 `redact_text`를 거쳐 저장되므로, 373 원문의 과거 명령 경로는 원시 GET과 그대로 같지 않다. 원문 백업은 정확 REST `content.raw`로 유지하고 비교할 때만 동일한 redaction을 적용했다. 다른 산문 차이를 허용한 비교가 아니다. 이 구분을 숨기고 ‘모든 원문이 인벤토리와 바이트 동일’이라고 주장하지 않는다.

최종 적용은 Reviewer의 정확 manifest 해시 승인 이후 Publisher가 최신 원문을 다시 읽고 수행해야 한다. 이 단계에서는 승인 파일을 만들거나 updater apply를 실행하지 않았다.
