## 독자가 해결할 질문과 조사 결론

독자 질문은 “로봇이 카메라로 본 뒤 움직인다는 말에서, 정확히 무엇이 입력이고
무엇이 출력이며 왜 다시 관측해야 하는가?”다. 프로그래밍의 변수와 조건문,
사칙연산만 전제한다. 강화학습 수식·행렬·미분·특정 프레임워크 설치는 요구하지 않는다.

조사 결과를 Writer가 사용할 때는 다음 세 구분을 유지한다.

1. 관측은 이용 가능한 측정 정보이지 언제나 완전한 상태가 아니다.
2. 행동 명령을 내린 것과 원하는 물리적 결과가 나온 것은 다르다.
3. 결과를 다시 보고 행동을 바꾸는 피드백과 정책 자체를 학습하는 과정은 다르다.

이 글의 자체 기여는 위 구분을 **단일 1차원 이동 예제와 센서 편향 반례**로 함께
설명하는 데 있다. 로봇 구동 성능을 비교하거나 최신 모델을 추천하는 글이 아니다.

## 용어의 범위와 초보자 설명 재료

### 피지컬 AI: 이 글이 사용할 범위

작업 정의는 “물리 환경을 관측하고, 그 정보로 행동을 결정하며, 결과를 다시
관측하는 AI 시스템을 이해하는 관점”으로 한정한다. S1은 카메라와 스마트 공간까지
포함하므로 휴머노이드만의 이름도, 특정 라이브러리 이름도 아니다. **이 작업 정의를
보편적으로 합의된 표준이라고 주장하지 않는다.** 이번 조사에서 표준기관이 정한
단일 규격 정의를 확인한 것은 아니다. [S1](https://www.nvidia.com/en-us/glossary/generative-physical-ai/)

S1의 “과거 자율 기계는 주변을 인식하지 못했다”는 취지의 일반화는 그대로 쓰지
않는다. 제어·센서 기술과 최근 학습 모델을 정확히 구분하는 데 도움이 되지 않는
홍보성 문장이다. 입문 글의 수학적 근거는 S2~S5에 두고 제품 홍보는 배제한다.

### 관측·상태·행동·정책

- **관측(observation):** 지금 시스템이 입력으로 얻는 정보. 카메라 영상이나
  측정 위치 등이 예다. 가려짐·누락·오차가 있을 수 있다.
- **상태(state):** 선택한 모델에서 현재 상황을 기술하는 정보. 일반 역학에서는
  위치뿐 아니라 속도도 필요할 수 있다. “우주 전체의 모든 진실”이라는 비유는 피한다.
- **행동(action):** 정책이 선택해 환경/하위 시스템에 전달하는 입력. “물체 잡기
  성공”은 결과이고, 목표 위치 또는 구동 명령은 행동의 표현일 수 있다.
- **정책(policy):** 주어진 정보로 행동을 선택하는 규칙. 반드시 신경망이거나
  강화학습으로 얻어진 규칙일 필요는 없다. 관측 이력이나 내부 기억을 쓰는 구조도
  있으므로 모든 정책을 단일 현재 관측만의 함수로 고정하지 않는다.

정의의 출발점은 [S2의 상태·관측·정책 절](https://spinningup.openai.com/en/latest/spinningup/rl_intro.html)이다.
위치/속도와 모델 범위 주의는 [S4의 Definitions](https://underactuated.mit.edu/intro.html)에 대응한다.

### 제어기·센서·액추에이터와 용어가 겹치는 곳

- **센서(sensor):** 환경이나 장치의 물리량을 읽는 장치. 값이 있다고 정확한 것은 아니다.
- **액추에이터(actuator):** 명령을 물리 작용으로 바꾸는 구동 장치. 모터가 예다.
- **제어기(controller):** 원하는 목표와 측정 정보를 이용해 시스템 입력을 정하는
  구성요소. “정책은 똑똑한 AI, 제어기는 단순 부품”처럼 서열화하지 않는다.

상위 정책이 목표를 정하고 하위 제어기가 모터를 다루는 설계가 가능하지만, 항상
두 별도 모듈이어야 하는 것은 아니다. 수학적으로 같은 피드백 법칙을 정책 또는
제어기로 부르는 맥락도 있다. [S5 Architecture](https://control.ros.org/jazzy/doc/getting_started/getting_started.html)와
[S4 Feedback Equivalence](https://underactuated.mit.edu/intro.html)의 용어 사용을 대조한 편집적 설명이다.

## 자체 구성한 작은 예제와 검산

### 문제와 가정

**종이 위 1차원 이동 모델**이다. 시작 위치 0m에서 목표 1m로 움직이는 점을 생각한다.
로봇 실험도, 물리 엔진 시뮬레이션도, 신경망 학습도 아니다. 예제의 숫자와 규칙은
이번 설명을 위해 직접 정했다.

- `x_t`: t번째 단계의 실제 위치(m).
- `o_t`: 위치를 관측한 값(m). 첫 경우에는 이상적으로 `o_t = x_t`라고 가정한다.
- `r = 1m`: 목표 위치.
- `a_t`: 한 단계 동안 요청하는 위치 변화(m). 속도/가속도/토크와 혼동하지 않는다.
- 규칙: `a_t = clamp(0.5 × (r - o_t), -0.2m, +0.2m)`.
- `clamp(z, lo, hi)`는 값을 아래·위 경계 안으로 잘라 넣는 연산이다.
- 상태 변화는 이 예제에 한해 `x_(t+1) = x_t + a_t`가 정확히 성립한다고 가정한다.
- 성공 기준은 `|r - x_t| ≤ 0.025m`. 독자에게 정확한 1m 도달과 허용 오차 내 도달을 구분시킨다.

“명령한 만큼 바로 이동”은 강한 가정이다. 관성·힘·속도 제한·충돌·시간 지연·접촉·
측정 오차를 첫 표에서는 제외했다. 0.2m 제한은 설명용 숫자이지 안전한 로봇 설정값이 아니다.
학습 기반 피지컬 AI 전체를 구현한 예제가 아니라, 그 안에서도 중요한 관측–행동
관계를 분리해 보기 위한 고전적 피드백 규칙이다.

### 수치 결과: 손계산과 정확한 유리수 검산

| 단계 t | 관측 위치 o_t(m) | 남은 거리 r-o_t(m) | 행동 a_t(m) | 다음 위치 x_(t+1)(m) |
| --- | ---: | ---: | ---: | ---: |
| 0 | 0 | 1 | 0.2 | 0.2 |
| 1 | 0.2 | 0.8 | 0.2 | 0.4 |
| 2 | 0.4 | 0.6 | 0.2 | 0.6 |
| 3 | 0.6 | 0.4 | 0.2 | 0.8 |
| 4 | 0.8 | 0.2 | 0.1 | 0.9 |
| 5 | 0.9 | 0.1 | 0.05 | 0.95 |
| 6 | 0.95 | 0.05 | 0.025 | 0.975 |

직접 검산: 처음은 `0.5×1=0.5`지만 상한으로 0.2다. 0.8m에서는
`0.5×0.2=0.1`이므로 0.9m로 간다. 7번 갱신 후 실제 오차는
`1-0.975=0.025m`여서 위 기준을 충족한다. 1m에 정확히 도달했다고 말하면 틀리다.
매 단계 관측을 다시 쓰지만 계수 0.5와 상한 0.2는 바뀌지 않는다.

아래는 Research가 실제로 실행한 **산술 검산 코드**다. 로봇/센서/ROS/Gymnasium은
실행하지 않았다. 현 프로젝트의 Python으로 표 값을 확인했으며 독자용 설치 튜토리얼이
아니다. 블로그에서 실행 명령을 제공하려면 Writer가 별도의 준비 절차와 함께 재검증한다.

```python
from fractions import Fraction as F
x = F(0)
target, limit, k = F(1), F(1, 5), F(1, 2)
rows = []
for t in range(7):
    a = max(-limit, min(limit, k * (target - x)))
    nxt = x + a
    rows.append((t, str(x), str(a), str(nxt)))
    x = nxt
assert [r[3] for r in rows] == [
    "1/5", "2/5", "3/5", "4/5", "9/10", "19/20", "39/40"
]
assert target - x == F(1, 40)
bias = F(1, 10)
x = F(9, 10)
o = x + bias
a = max(-limit, min(limit, k * (target - o)))
assert o == target and a == 0 and x != target
```

실행 기록:

- verification_date: 2026-09-16
- environment: Darwin 23.0.0 x86_64, Python 3.12.9, 표준 라이브러리 fractions.
- method: 프로젝트 Python의 `-c`로 위와 같은 유리수 계산 및 assert 실행.
- observed_result: 정상 종료 0. 7단계 위치 39/40, 오차 1/40. 편향 반례의 관측 1,
  행동 0, 실제 오차 1/10을 확인.
- 정제한 핵심 출력(시스템 경로·계정 정보 없음):

```text
gap_after_7 1/40
biased_observation 1 action 0 actual_gap 1/10
ARITHMETIC_CHECK_PASS; no robot or physics simulator used
```

### 반례: 센서가 계속 0.1m 크게 읽는다면

관측만 `o_t = x_t + 0.1m`로 바꾸자. 실제 위치가 0.9m일 때 관측은 1m이다.
동일 규칙은 `0.5×(1-1)=0`을 출력해 정지한다. 관측 오차는 0이지만 실제 위치
오차는 0.1m다. 목표를 확인했다는 판단과 실제 성공이 갈라진다.

이것은 센서가 그렇게 고장났다는 관측 보고가 아니라 **직접 정한 편향 가정에서
계산되는 반례**다. 폐루프가 있다는 사실만으로 정확성이나 안전이 보장되지 않는다는
설명에 쓴다. 이 예제만으로 교정법·잡음 강건성·실물 제어 성능을 제안하지 않는다.

### 관측 하나에 모든 상태가 들어 있지 않을 수 있다는 추가 논리

장난감 모델에서는 위치만으로 다음 위치를 계산할 수 있도록 정했다. 실제 관성 있는
이동체 두 개가 같은 0.9m에 있어도 하나는 정지 중이고 하나는 빠르게 전진 중일 수
있다. “둘 다 0.9m”라는 측정만 같다고 다음 움직임도 같지는 않다. 위치와 속도를
상태로 두는 [S4 Definitions](https://underactuated.mit.edu/intro.html)와 연결해 설명한다.
추가 수치나 제동거리는 계산하지 않았으므로 안전 정지 제어법으로 확장하지 않는다.

## 이해 확인 질문 3개와 답의 이유

1. **이상적 표에서 위치가 0.8m일 때 다음 행동과 다음 위치는?**
   행동은 0.1m, 다음 위치는 0.9m. 남은 거리 0.2m의 절반이며 상한 0.2m보다 작다.
   0.2m씩 끝까지 이동하는 규칙이 아니다.
2. **센서가 0.1m 크게 읽어 실제 위치 0.9m를 1m로 보고하면 성공인가?**
   실제 성공 기준으로는 아니다. 규칙은 멈추지만 실제 오차 0.1m가 허용 오차
   0.025m보다 크다. 관측과 상태, 판단과 결과를 구분해야 한다.
3. **매번 관측해 행동을 줄였으니 학습한 것인가?**
   아니다. 계수·규칙은 고정이고 입력이 바뀌어 출력이 바뀌었다. 이 예제에서
   확인한 것은 피드백 동작이지 정책 업데이트/훈련이 아니다.

## 최신 개념·도구로 연결할 때의 제한

RT-2 연구팀은 이미지·언어와 행동을 연결하는 VLA를 설명한다. 이는 후속 글에서
정책이 단순 수식 대신 학습 모델일 수 있음을 보여주는 역사적 연구 사례다.
[RT-2 프로젝트](https://robotics-transformer2.github.io/),
[2023년 원논문 초록](https://arxiv.org/abs/2307.15818)

첫 글에는 성능 수치나 “최신 최고의 모델” 평가를 넣지 않는다. 이번에 모델을
설치·실행하지 않았고, 2023년 논문을 2026년 신제품으로 소개하지 않는다. 후속 글
계획은 ‘관측 데이터의 모양’→‘피드백과 학습’→‘Gymnasium의 관측/행동 인터페이스’
순서가 자연스럽다. 아직 존재하지 않는 HuntLab 글에 내부 링크를 만들지 않는다.

- People Also Ask 예상 질문: 위 이해 확인 질문 외에 ‘정책은 반드시 AI 모델인가?’,
  ‘피드백과 강화학습은 같은가?’, ‘로봇 없이 원리를 배울 수 있나?’.
  실제 검색엔진 PAA 패널에서 수집한 질문이라고 주장하지 않는다.
- 검색자가 해결하려는 문제: 용어들을 연결해 동작 과정을 설명하고 간단한 규칙의
  다음 행동 및 한계를 계산하는 정보 탐색/기초 학습.
- 경쟁 문서 특징: 상위 순위·경쟁 사이트의 품질은 미평가. 직접 확인한 공식 자료는
  각각 산업 용어 설명(S1), RL 용어/수학(S2), API 사용(S3), 제어 이론(S4),
  프레임워크 구조(S5)에 초점이 다르다. 한 자료를 번역하는 대신 이 사이의 혼동을
  자체 숫자 예제로 풀어주는 방향이다.
- 공식 문서: S1~S6. 핵심 수학 정의는 S2/S4, 구현 연결은 S3/S5.
- 검색 의도 완료 조건: 독자가 관측/상태/행동을 분류하고, 표의 다음 값을 계산하며,
  관측상 성공이 실제 성공과 다를 수 있음을 설명한다.
- FAQ 후보: ‘모든 로봇이 피지컬 AI인가?’(명칭의 포괄 범위와 이 글의 한정 정의),
  ‘정책과 제어기는 다른가?’(맥락·설계별 겹침), ‘피드백이 있으면 안전한가?’(편향 반례).

## 고유 가치와 근거

- original_contribution: 한 가지 자체 이동 규칙의 숫자 표, 관측 편향 반례,
  ‘피드백은 학습이 아니다’ 확인 질문을 연결한 입문 학습 구성.
- verification_mode: not_directly_tested. **실물 로봇/물리 시뮬레이터/학습 모델을
  직접 검증하지 않았다는 뜻**이다. 문서 검토와 위 산술 검산은 실제 수행했다.
- evidence: S1~S6의 직접 원문 확인 범위, 예제 가정·수식, 정확한 유리수 계산 및
  assert 정상 종료 기록. 다른 연구팀 실험을 HuntLab 실험으로 쓰지 않는다.
- limitations: 모델의 즉시 위치 이동 가정, 관성·지연·접촉 미포함, 실물 안전성 미검증,
  자료의 일부 버전/게시일 미확인, 전체 WordPress 중복 검토 미완료.

## 작업 기록 및 Writer/Reviewer에게 남기는 조건

- evidence_origin: purpose_built_test. **산술 검산에만 해당**하며 운영 장애나 실제
  로봇 실험에서 출발한 Build Log가 아니다.
- work_trigger: 피지컬 AI의 용어·기초·원리부터 시작하라는 사용자 요청.
- actual_sequence: 편집/품질 지침 읽기→공식 자료 검색·원문 대조→예제 가정 설계→
  유리수 산술 검산→편향 반례 확인→한계와 미충족 발행 조건 기록.
- friction_or_surprise: RT-2 프로젝트의 Paper 링크 열기 실패. arXiv 초록·서지 확인으로
  범위를 한정했으며 논문 전체 읽기를 수행했다고 채우지 않았다.
- decision_log: 최신 모델 이름 나열보다 관측·행동·피드백의 구분을 먼저 다룬다.
  물리 안전을 암시하는 모터/속도 명령 대신 종이 위 위치 변화 모델을 선택했다.
- unfinished_edge: 실제 대상 독자의 이해도 검증과 독립 사실 검수는 아직 없다.
  전체 글/초안 inventory 검토 후 신규 글 적합성을 판단해야 한다.

Writer 전달 전에도 status는 INSUFFICIENT로 유지한다. 본 자료를 승인된 초안이나
발행 지시로 해석하지 않는다. 전체 중복 검토 등 부족 조건을 충족한 뒤 별도 후보
승인→Writer→독립 Reviewer의 실제 내용 판단→Publisher 계약을 거쳐야 한다.
