판정 시점: 2026-09-16 KST. 최신 전체 원문 인벤토리는 2026-09-15T22:20:53Z의 123건(공개 10, 초안 113)이다. 119건은 132번 글의 과거 감사 수치이며 현재 건수가 아니다. 아래 평가는 이 인벤토리의 공개 원문 기준이다. 별도 공개 GET 상태·시각·해시는 `all-post-public-get.json`에 보존한다. GET 성공은 명령 실행이나 시각 검수 성공을 의미하지 않는다.

## 남은 P1/P2와 우선순위

이번 독자 관점 재독만으로 **확정한 신규 P1은 없다**. 모든 글이 가치 없다는 결론도 아니지만 99점으로 종료할 근거 역시 없다. 실제 입력 수집과 명령의 버전 재현성, 문장 밀도에서 개선 여지가 보인다. 다음 항목을 수치 가산 없이 처리한다.

1. **P2 — 96의 마지막 실행 연결 부족.** 긴 한계 분석은 구체적이지만, 독자가 자신의 JSON에서 필수 필드/원문 차이를 검사하거나 공개 URL을 확인할 수 있는 안전한 완결 예제가 없다. 쓰기 스크립트를 곧바로 실행하라고 안내하지 않은 것은 적절하다. 읽기 전용 작은 검사와 기대 실패를 추가하면 가치가 커진다.
2. **P2 — 경험처럼 읽히는 사고과정의 출처 확인.** 698의 “처음에는 허용 상태 코드 목록만 더 촘촘하게 만들 생각이었다”, 699의 “작업이 끝났다고 표시하려다”, “처음에는 HTML의 robots 메타 검사만 배포 게이트로 두려 했다”는 fixture 전후 결과만으로는 입증되지 않는 작성자 내면·행동 서술이다. 거짓으로 확정할 근거도 없으므로, 원시 작업 기록과 연결되지 않으면 “상태 코드 목록을 좁혀도 HTML 200은 걸러지지 않는다”, “robots 검사만으로는 sitemap 포함 여부를 알 수 없다”처럼 객관적 대안 비교로 바꾸는 것이 좋다. 실제 하지 않은 경험으로 확인되면 P1로 상향한다. 132의 “처음 가설”과 749의 “버린 선택”도 역사 근거와 연결되는지 같은 기준을 적용한다.
3. **P2 — 버전과 실행 시점 안내를 한곳에 모으기.** 373은 환경/날짜 안내를 여러 번 하고, 698은 과거 4개와 현재 5개를 떨어진 절에서 설명한다. 기록을 삭제하거나 최신 숫자로 덮지 말고 ‘당시 결과 / 지금 실행할 코드’ 두 범위만 명확히 나눈다. 50·290의 새 clone 명령은 브랜치 HEAD를 받으므로 미래 회귀를 막으려면 검증한 revision을 함께 지정하는 편이 낫다.
4. **P2 — 전문용어의 첫 사용만 쉬운 말로 풀기.** 96의 idempotency guard/transaction, 290의 orchestration/schema/transport, 749의 manifest/snapshot은 기능 식별에는 필요하나 한국어 역할 설명 없이 밀집하면 진입 장벽이 된다. 예를 들어 ‘재삽입 방지 마커’, ‘여러 작업을 한 번에 확정하는 처리’, ‘기준 파일 목록’으로 먼저 말하고 정확한 코드 용어를 괄호로 남긴다. 코드 식별자 자체는 바꾸지 않는다.
5. **P2 — 템플릿 반복 압축.** 290·301·373의 무엇/왜/어떻게 요약과 도입, 여러 글의 ‘실제 운영 검증은 아니다’ 반복은 각기 필요한 경계지만 같은 글 안에서는 한 번의 범위 상자와 각 실패 조건으로 충분하다. 다른 글의 본문을 재활용하는 방식으로 고치지 않는다. 698·699의 실행 안내 문구가 같은 틀인 점은 작은 절차 공통점이지 전체 의도 중복은 아니다.

132/301의 완결 예제 보강과 749의 최소 문체 수정은 별도 manifest 심사 대상으로 남긴다. 이 문서는 읽기 전용 감사이며 추가 본문 변경·승인·원격 쓰기는 하지 않았다.
