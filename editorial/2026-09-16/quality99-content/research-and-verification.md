# 기존 글 3편 독자 완결성 보강 — 검수 인계

상태: PROPOSED. 독립 Reviewer 승인 전이며 WordPress 쓰기·배포·커밋·푸시·새 글 발행은 하지 않았다. 이 문서는 전체 블로그 99점이나 AdSense 승인 확률을 판정하지 않는다.

## 정확한 수정 범위

- 132: 기존 119건 감사 기록을 보존하고 2026-09-16 추가 검증을 별도 구획으로 삽입했다. 저장소·인증·패키지 설치 없이 공개 REST를 페이지별로 읽는 완전한 Python 표준 라이브러리 예제다. 현재 10건과 과거 119건을 구분했다.
- 301: 기존 97개 테스트/PHP 실행 불가 등 과거 기록을 그대로 두고 공개 HTML의 실제 요약 H2와 자동 상자 클래스를 세는 완전한 예제를 추가했다. 코드 예시 속 문자열을 실제 제목으로 세지 않도록 HTMLParser를 썼다. 이것은 PHP 정규식 회귀 테스트나 브라우저 렌더링 검증의 대체물이 아니다.
- 749: 도입에서 제목을 그대로 반복하는 한 문장을 바꾸고, 이미 전체 출력에 있는 단계별 종료 코드의 독립 중복 출력 블록 하나를 줄였다. 실행용 Bash 블록, 링크, 이미지 경로는 수정 전후 동일함을 기계 비교했다. 제목·슬러그·다른 메타데이터 변경을 요청하지 않는다.

## 근거 및 한계

[WordPress 공식 페이지네이션 문서](https://developer.wordpress.org/rest-api/using-the-rest-api/pagination/)의 페이지 크기, X-WP-Total/TotalPages, ID 정렬 계약을 확인했다. [Python HTMLParser 공식 문서](https://docs.python.org/3/library/html.parser.html)의 태그 이벤트와 문자 참조 처리를 기준으로 HTML 구조를 센다. 기존 역사적 커밋과 테스트 수치는 이번 추가 테스트의 결과로 재포장하지 않았다.

132의 질문은 ‘첫 페이지에서 멈추지 않고 공개 글을 모두 읽었는가’, 301은 ‘실제 응답 HTML에 작성 요약과 자동 상자가 겹쳤는가’, 749는 ‘DB 복원 후 원본 첨부파일의 존재와 해시를 따로 검증했는가’다. 세 독자 의도는 다르며 새 글로 분할하지 않는다. 최종 수정본들을 반영한 전체 123건(공개 10/초안 113) 본문 비교에서 각 글의 180자 이상 동일 산문 탐지 및 기본 편집 게이트가 모두 통과했다. 이는 모든 검색 의도의 의미적 중복 부재를 자동 증명하지 않으므로 독립 Reviewer의 의미 검토가 남아 있다.

예제는 공개 HTTPS GET만 사용한다. 고정 URL, 요청 제한 시간, 응답 크기 제한, 리다이렉트 거부, 형식 검사를 둔다. 132는 100페이지/300건 상한이 있고, 총수가 유지되는 동시 교체까지 검출하는 원자적 snapshot은 아니다. 301은 이 페이지의 작성 요약 1/자동 상자 0 기준만 검사한다. JS 후처리·CSS 가시성·fallback 내용·PHP 실행은 검사하지 않는다. 이러한 한계를 본문에 명시했다.

## 실제 독립 실행

`verification.json` 생성 시각: 2026-09-15T22:23:24Z (KST 2026-09-16 07:23). Python 3.12.9에서 제안 HTML의 Bash 코드 블록을 HTML unescape하여 추출했고, 예제 소스와 바이트 일치를 확인한 뒤 빈 임시 작업 디렉터리에서 그대로 실행했다. 저장소 파일을 가져오거나 인증값을 전달하지 않는 코드다. 예제 실행이 작업 디렉터리에 만든 파일은 0개다.

- 132: 실제 공개 GET 4회, 페이지 길이 3/3/3/1, 고유 ID 10, 전체 종료 0, passed true.
- 301: 실제 공개 GET 1회, summary_h2 1, automatic_boxes 0, 전체 종료 0, passed true.
- 제어 입력: unittest 메서드 2개 안의 12개 subtest 통과. 페이지 빈 결과·정확한 배수·중복 ID·중간 총수 변경·짧은 페이지·bool ID·잘못된 페이지 수 및 H2 인라인 강조·중복 제목·이스케이프된 코드·클래스 토큰·스크립트 제외를 확인했다.

재실행: 저장소에서 `.venv/bin/python editorial/2026-09-16/quality99-content/test_examples.py -v`, 이어서 `verify.py`를 같은 Python으로 실행한다. 이 명령은 내부 검수자용이며 독자 본문은 `.venv`나 저장소에 의존하지 않는다. `verify.py`는 최신 전체 인벤토리와 원문이 일치해야 통과하므로 다른 편집 후에는 실패하는 것이 정상이다.
