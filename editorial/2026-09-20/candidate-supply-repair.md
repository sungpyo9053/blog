# 피지컬 AI 후보 공급 누락 수정

## 원인

9월18·19일 10시 작업은 실행됐지만 READY0/WordPress쓰기0이었다. 등록된 기초 후보가
이미 공개된 좌표계 글 하나뿐이었고, 공식 자료 기반의 새로운 후보를 만드는 실행부가
없었다. DEV.to 설정도 참고용이지 자동 수집이 아니었다. 대기만 하면 글이 쌓인다는
설명은 당시 실제 구현 범위를 넘어섰다.

## 수정

- 기존 READY가 없고 일일 한도가 남은 실제 실행에서 후보 공급기를 한 번 호출한다.
- 날짜 순환 공식 원문 조회, 새 질문 제안, 제한된 산술 예제 실제 실행, 별도 후보 검수,
  공개 근거의 커밋·바이트 확인 후 기존 foundation/epoch/전체 중복 계약을 재적용한다.
- 모델은 도구 없는 별도 실행으로 분리한다. 임의 Python이나 장치 명령을 실행하지 않는다.
- 중복·편집 HOLD는 정상 무후보, 조회·모델·보안·공개 근거 실패는 공급 단계 오류다.
- 기존 일일1편·공개 확인·카톡 규칙을 유지한다. 최종 글 승인과 후보 승인은 별개다.
- 기초 해설 발행 기록을 카카오 심층글 집계에 포함하며 공급 실패와 무후보를 구분한다.
- 최종 품질 schema2는 자연스러움 다섯 항목과 항목17=5를 요구한다. 기존4편 윤문은
  별도 미완료 작업이며 이 수정으로 본문이 바뀌었다고 주장하지 않는다.

## 권한

서버에 GitHub 쓰기 인증이 없어 사전 dry-run이 실패했다. 사용자의 별도 승인 뒤
개인 토큰 대신 이 저장소에만 쓰기 가능한 서버 전용 배포 키를 등록했다.
개인키는 서버에만 보관하고 GitHub 공식 호스트 키로 SSH 대상을 검증한다.
자동 커밋은 생성한 명시적 근거 경로만 포함하며 다른 staged/dirty 파일은 보존한다.

## 검증 상태

로컬 회귀679개 통과,6개 건너뜀. 모의 오류 출력과 실제 운영 실패를 구분한다.
실제 서버 후보 생성·최종 발행 결과는 운영 검증 후 별도로 기록한다.
