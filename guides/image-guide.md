# 블로그 이미지 제작 가이드

> 사용 대상: `agents/image-maker.md`  
> 목적: HuntLab 7개 카테고리의 대표 이미지와 본문 이미지를 안전하고 정확하게 제작한다.

## 카테고리별 이미지 정책

이미지는 검색자의 이해를 실질적으로 돕는 경우에만 만든다. 안전하고 정확한 자료를 만들 수 없으면 이미지 0장을 허용한다.

| 카테고리 | 허용 이미지 | 금지 이미지 | 대표 이미지 | 본문 이미지 |
|---|---|---|---|---|
| Tech | 검증된 아키텍처·절차·코드 흐름 | 가짜 제품 UI, 실행하지 않은 성능 결과 | 기술명과 해결 과제의 중립적 구조도 | 단계도·구성도·검증된 비교표 |
| AI | 모델 평가·데이터 처리 구조 | 가짜 AI UI, 미확인 성능 차트 | 추상적 모델 평가 구조 | 평가 파이프라인·안전한 비교표 |
| Economy | 공식 통계 기반 표·차트 | 출처 없는 차트, 조작된 축·수치, 수익 암시 | 지표와 정책 관계 정보 그래픽 | 출처·기준일·단위가 있는 데이터 |
| Society | 공공 절차·법령 흐름·익명 통계 | 사건·피해자 재현, 개인정보 추정 | 중립적 공공 안내 그래픽 | 신청·적용 절차와 공식 통계 |
| Politics | 제도·의안·선거 절차·조사 방법론 | 실존 정치인, 정당 편향, 조작 여론조사 | 인물·정당 로고 없는 균형적 쟁점도 | 공식 절차도·방법론 정보표 |
| Hot Issue | 확인된 사실 타임라인·대응 절차 | 실제 사건 같은 생성 이미지, 가짜 뉴스 화면 | 중립적 사실 요약 그래픽 | 출처가 확인된 타임라인·체크리스트 |
| Build Log | 실제 프로젝트 구조·검증된 실행 흐름 | 가짜 성공 화면·성능 결과·배포 UI | 실제 변경 범위 구조도 | 재현 가능한 단계와 실제 측정 |

## 공통 안전 금지

- 실제 사건 사진처럼 보이는 생성 이미지
- 실존 인물 또는 실존 인물로 오인될 수 있는 얼굴
- 가짜 뉴스 기사·방송 화면
- 실제 제품으로 오인되는 가짜 UI
- 출처·기준일·단위 없는 차트
- 경제 수치 조작 또는 오해를 유도하는 축
- 정치적 편향을 강화하는 색·구도·상징
- 검증하지 않은 성공·성능·배포 결과

## 1. 대표 이미지 규격

### 캔버스

- 크기: **가로 1080px × 세로 1080px**
- 비율: **1:1 정사각형**
- 배경: 어두운 블루-퍼플 그라데이션

```css
background: linear-gradient(135deg, #1a1a2e 0%, #16213e 100%);
```

그라데이션 방향은 콘텐츠와 액센트 배치에 맞춰 미세하게 조정할 수 있지만 시작색과 끝색은 유지한다.

### 텍스트

- 메인 텍스트: 글 제목
  - 큰 글씨
  - 흰색
  - 굵은 두께
  - 2~4줄 이내
- 보조 텍스트: 카테고리 또는 부제
  - 메인 텍스트보다 작은 글씨
  - 연한 회색
  - 1~2줄 이내
- 모든 텍스트는 가로·세로 중앙 정렬한다.
- 메인 텍스트와 보조 텍스트를 하나의 중앙 정렬 그룹으로 묶는다.
- 텍스트가 캔버스 가장자리에 닿지 않도록 사방에 충분한 안전 여백을 둔다.

권장 색상:

```css
--text-primary: #ffffff;
--text-secondary: #b8c1d9;
```

### 폰트

- 1순위: Pretendard
- 2순위: 시스템 기본 한글 산세리프

```css
font-family:
  Pretendard,
  -apple-system,
  BlinkMacSystemFont,
  "Segoe UI",
  "Noto Sans KR",
  "Apple SD Gothic Neo",
  sans-serif;
```

### 액센트

- 우측 하단 또는 좌측 상단 중 한 곳에 작게 배치한다.
- 다음 중 글의 주제에 어울리는 하나를 선택한다.
  - 단순 기하 도형
  - 코드 심볼
  - 단순한 라인 아이콘
- 액센트는 제목보다 눈에 띄면 안 된다.
- 장식 요소를 여러 곳에 흩뿌리지 않는다.
- 외부 아이콘 파일이 없어도 재현할 수 있도록 CSS 도형, 짧은 문자, 인라인 SVG를 우선한다.

## 2. 본문 삽입 이미지 유형

글의 내용과 `[IMAGE: 설명]` 마커의 목적에 따라 다음 네 가지 중 하나를 선택한다.

### 2.1 비교 표

사용 시점:

- 제품, 기능, 방법, 요금제 또는 선택지를 나란히 비교할 때
- 항목별 차이를 한눈에 보여줘야 할 때

구성:

- 제목
- 2~5개의 비교 대상
- 3~6개의 핵심 비교 항목
- 중요한 차이에만 액센트 색상 사용

주의:

- 설명문을 셀 안에 길게 넣지 않는다.
- 열이 많아 글자가 지나치게 작아지면 카드형 비교로 바꾼다.
- 모바일에서도 읽을 수 있는 글자 크기를 유지한다.

### 2.2 단계별 다이어그램

사용 시점:

- 절차, 워크플로우, 시간 순서, 원인과 결과를 보여줄 때
- 여러 단계의 연결 관계를 설명할 때

구성:

- 제목
- 3~6개 단계
- 단계 번호 또는 짧은 단계명
- 화살표나 연결선
- 각 단계의 한 줄 보충 설명

주의:

- 흐름 방향을 왼쪽→오른쪽 또는 위→아래 중 하나로 통일한다.
- 선이 카드나 텍스트를 관통하지 않게 한다.
- 복잡한 분기는 꼭 필요한 경우에만 사용한다.

### 2.3 핵심 포인트 카드

사용 시점:

- 핵심 기능, 장점, 원칙, 체크 사항 3~5개를 요약할 때
- 긴 본문을 빠르게 복습하게 할 때

구성:

- 제목
- 3~5개의 균형 잡힌 카드
- 각 카드에 짧은 번호·아이콘
- 짧은 제목과 한 줄 설명

주의:

- 카드마다 문장 길이를 비슷하게 맞춘다.
- 카드 수에 맞춰 1열, 2열 또는 3열 그리드를 선택한다.
- 같은 의미의 문장을 제목과 설명에 반복하지 않는다.

### 2.4 인용·강조 박스

사용 시점:

- 글의 결론이나 가장 중요한 한 문장을 강조할 때
- 공식 문서의 짧은 핵심 문구를 출처와 함께 보여줄 때

구성:

- 짧은 핵심 문장
- 필요한 경우 출처 또는 맥락 한 줄
- 따옴표, 세로선 또는 코드 블록 형태의 시각적 액센트

주의:

- 긴 문단을 그대로 이미지화하지 않는다.
- 직접 인용이라면 초안과 리서치 파일에 확인된 문구만 사용한다.
- 출처가 없는 문장을 외부 인용처럼 꾸미지 않는다.

## 3. 공통 디자인 규칙

### 제작 방식

- 모든 이미지는 **HTML + CSS**로 제작한다.
- Python에서 Playwright를 실행해 PNG로 캡처한다.
- 결과를 재현할 수 있도록 이미지별 HTML 원본 또는 생성 스크립트를 작업 과정에서 유지할 수 있다.
- 최종 산출물은 에이전트 지침에 지정된 PNG와 수정된 `draft.md`다.

### 분위기

- 배경 톤은 본문과 어울리는 AI·테크 분위기로 한다.
- 대표 이미지의 블루-퍼플 계열을 본문 이미지에도 연결한다.
- 어두운 배경, 밝은 텍스트, 절제된 네온 액센트를 기본으로 한다.
- 너무 많은 그라데이션, 그림자, 광택 효과를 동시에 사용하지 않는다.

권장 팔레트:

```css
--bg-deep: #101426;
--bg-panel: #1a1f38;
--bg-panel-alt: #202844;
--line: #35405f;
--text-primary: #f7f8ff;
--text-secondary: #b8c1d9;
--accent-purple: #8b7cff;
--accent-blue: #55b7ff;
--accent-cyan: #52e0d1;
--accent-warn: #ffcc66;
```

### 텍스트

- 텍스트는 최대한 짧게 쓴다.
- 이미지는 본문을 대체하는 문서가 아니라 이해를 돕는 보조 수단이다.
- 한 카드에는 제목 1줄과 설명 1~2줄만 넣는 것을 기본으로 한다.
- 긴 설명이 필요하면 이미지가 아니라 본문에 남긴다.
- 작은 각주와 출처도 캡처 후 읽을 수 있는 크기를 유지한다.

### 코드 블록 스타일

- 코드 블록 형태를 디자인 요소로 사용할 수 있다.
- 모노스페이스 폰트, 어두운 패널, 짧은 명령어나 코드 심볼을 활용한다.
- 실제 명령어를 표시할 때는 `research.md` 또는 `draft.md`에서 검증된 내용만 사용한다.

```css
font-family:
  "SFMono-Regular",
  Consolas,
  "Liberation Mono",
  Menlo,
  monospace;
```

### 레이아웃

- 모든 요소에 의도적인 정렬 기준을 둔다.
- 캔버스 사방에 안전 여백을 유지한다.
- 카드 사이 간격과 내부 패딩을 일관되게 한다.
- 정보의 중요도에 따라 제목, 핵심어, 설명의 크기 차이를 분명하게 한다.
- 장식보다 읽기 쉬운 정보 구조를 우선한다.

## 4. 캡처 품질 기준

PNG를 만든 뒤 반드시 실제 이미지로 다시 열어 다음을 확인한다.

- 하단이나 한쪽에 과도한 빈 여백이 없는가?
- 텍스트가 잘리거나 박스 밖으로 튀어나오지 않았는가?
- 한글이 깨지거나 대체 글꼴 때문에 줄바꿈이 무너지지 않았는가?
- 표와 카드의 폭·높이가 불균형하지 않은가?
- 화살표나 선이 텍스트와 겹치지 않는가?
- 중심 정렬 또는 그리드 정렬이 눈으로 봐도 맞는가?
- 대비가 낮아 읽기 어려운 글자가 없는가?
- 대표 이미지가 1:1, 1080×1080으로 정확한가?
- 본문 이미지의 크기가 의도한 뷰포트와 일치하는가?

문제가 있으면 HTML/CSS를 고쳐 다시 캡처하고 다시 확인한다. 최대 3회까지 반복한다.

## 5. 이미지 설명 작성 원칙

이미지의 alt 텍스트는 `[IMAGE: 설명]`의 의도와 실제 결과를 바탕으로 짧고 구체적으로 쓴다.

좋은 예:

```markdown
![클로드 코드 핵심 기능 5가지 비교](./images/body-1.png)
```

피해야 할 예:

```markdown
![클로드코드 클로드코드기능 AI코딩도구 추천](./images/body-1.png)
```

- 핵심 키워드는 이미지 내용을 설명할 때 자연스러운 경우에만 한 번 사용한다.
- 보이지 않는 내용을 alt에 추가하지 않는다.
- 캡션이 필요하면 이미지 바로 아래에 한 문장으로 쓴다.
