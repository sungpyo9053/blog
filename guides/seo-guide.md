# HuntLab 검색 유입 SEO 운영 가이드

> 업데이트 기준: 2026-07-26  
> 적용 대상: 네이버 블로그 포스트 및 HuntLab WordPress 기술 블로그
> 원칙: 네이버가 공개하지 않은 ‘상위 노출 공식’을 사실처럼 단정하지 않는다.

# 적용 대상

이 문서는 HuntLab WordPress 기술 블로그의 공식 SEO 운영 정책이다. SEO 이론을 설명하는 문서가 아니라 Writer Agent, Reviewer Agent, Publisher Agent가 실제 콘텐츠 제작·검토·발행에 적용할 기준을 정의한다.

문서 전체의 최상위 원칙은 **검색엔진 최적화보다 사람에게 도움이 되는 콘텐츠를 우선한다**는 것이다.

검색엔진 우선순위는 다음과 같다.

**Primary SEO**

- Google Search

**Secondary SEO**

- Naver Search

**향후 지원**

- Bing
- Perplexity
- ChatGPT Search
- AI Search Engine

Google 검색 유입, 검색 의도 해결, CTR과 E-E-A-T를 중심으로 운영한다. Naver Search는 동일한 정확성·가독성·원문성 원칙을 공유하는 보조 검색엔진으로 유지한다.

네이버와 Google의 기준이 충돌하거나 특정 검색엔진을 위한 최적화가 문서 품질을 낮추는 경우 사람에게 자연스럽고 정확하며 도움이 되는 콘텐츠를 우선한다.

WordPress 발행 상태, Frontmatter, 카테고리, 태그, 대표 이미지, Validation 및 발행 안전성은 `publisher-guide.md`를 따른다. 문체와 표현은 `style-guide.md`를 따른다. 이 문서는 두 Guide의 책임을 대신하거나 변경하지 않는다.

# Google 검색 유입 핵심 계약

## 검색 의도

- Primary Keyword를 검색한 사람이 원하는 최종 결과를 한 문장으로 정의한다.
- 정보 탐색, 사용법, 문제 해결, 비교, 최신 사실 확인 중 주된 의도를 하나로 정한다.
- 첫 화면에서 핵심 답과 글의 범위를 제시하고 결론까지 같은 의도를 해결한다.
- 검색량만 높고 HuntLab이 정확한 답을 제공할 수 없는 주제는 선정하지 않는다.

## Primary Keyword와 Secondary Keyword

- Primary Keyword는 사람이 실제 검색할 자연스러운 표현 하나다.
- 제목, 첫 문단, 관련 H2와 Meta Description에 문맥상 필요한 만큼만 사용한다.
- Secondary Keywords는 동의어, 하위 문제와 후속 행동을 2~5개 선정한다.
- 검색량 수치가 확인되지 않았으면 수치를 창작하지 않는다.
- 키워드 밀도 목표와 기계적인 반복은 금지한다.

## Title과 CTR

- `Primary Keyword + 사용자가 얻는 결과` 구조를 기본으로 한다.
- 40~65자를 권장하되 정확성과 자연스러움을 우선한다.
- 숫자, 연도, 방법, 체크리스트는 본문에 실제로 제공할 때만 사용한다.
- 위기감, 과장, 미완성 문장과 낚시성 표현으로 클릭을 유도하지 않는다.
- 제목과 검색 결과가 약속한 답이 첫 화면에서 확인돼야 한다.

## Meta Description

- 110~160자를 권장한다.
- Primary Keyword, 해결할 문제, 독자가 얻을 결과를 자연스럽게 포함한다.
- 본문에 없는 결과, 성능, 공식성 또는 보장을 추가하지 않는다.
- 모든 글에 같은 템플릿 문장을 반복하지 않는다.

## Slug

- Primary Keyword의 핵심 단어를 사용해 짧게 작성한다.
- 소문자 영문, 숫자와 하이픈만 사용한다.
- 불필요한 날짜, 조사, 반복 단어와 긴 문장형 경로를 피한다.
- 공개 후 Slug를 자동 변경하지 않는다.

## Heading 구조

- H1은 WordPress 제목 하나만 사용한다.
- 본문은 H2부터 시작하고 하위 설명에 H3를 사용한다.
- 소제목만 읽어도 문제 해결 순서가 드러나야 한다.
- Heading 단계를 건너뛰거나 키워드를 모든 Heading에 반복하지 않는다.

## FAQ와 People Also Ask

- FAQ는 검색 의도에서 본문 뒤에 자연스럽게 이어지는 실제 후속 질문이 있을 때만 작성한다. 최소 개수를 두지 않으며 본문·결론을 반복하는 질문은 만들지 않는다.
- 질문은 실제 검색 문장에 가깝게 쓰고 답은 본문 근거 안에서 간결하게 제공한다.
- People Also Ask 예상 질문은 Research의 후보를 사용하되 확인되지 않은 전제를 포함하지 않는다.
- FAQ Schema를 사용한다면 화면에 보이는 질문·답변과 정확히 일치해야 한다.

## Featured Snippet

- 정의, 단계, 비교, 체크리스트처럼 질문에 맞는 형식을 선택한다.
- 핵심 질문 바로 아래에 짧고 독립적으로 이해되는 답을 둔다.
- Snippet 획득을 위해 사실을 단순화하거나 맥락을 삭제하지 않는다.

## 내부 링크 전략

- 같은 카테고리와 검색 여정의 이전·다음 단계 글을 우선한다.
- 앵커 텍스트는 목적지를 구체적으로 설명한다.
- 공개 상태와 URL을 확인할 수 없는 링크는 삽입하지 않는다.
- 적절한 내부 글이 없으면 억지로 추가하지 않는다.

## 외부 링크 전략

- 공식 문서, 법령, 통계, 공시, 연구 원문을 핵심 주장 가까이에 연결한다.
- 검색 결과 페이지, 출처 없는 요약과 제휴 목적 페이지를 핵심 근거로 사용하지 않는다.
- 링크 수보다 주장과 출처의 직접적인 대응을 우선한다.

## E-E-A-T

- Experience: 실제 수행·관찰한 경험만 경험으로 표현한다.
- Expertise: 용어, 조건, 버전과 한계를 정확히 설명한다.
- Authoritativeness: 공식 원문과 검증 가능한 전문 자료를 우선한다.
- Trustworthiness: 출처, 확인일, 불확실성, 이해관계와 수정 가능성을 투명하게 밝힌다.

## Schema

- 페이지에 실제 표시된 내용과 일치하는 Article, Breadcrumb, FAQ 등의 Schema만 허용한다.
- 작성자, 날짜, 이미지, canonical과 FAQ 데이터가 WordPress 표시 내용과 같아야 한다.
- Rich Result를 얻기 위한 허위 필드나 보이지 않는 콘텐츠를 만들지 않는다.

## Evergreen

- 일회성 발표를 정의, 적용 방법, 점검 절차와 변경 확인 방법으로 확장한다.
- 버전과 확인일을 기록하고 업데이트가 필요한 지점을 명시한다.
- 오래된 글을 날짜만 바꿔 다시 만들지 않는다.

## Google Helpful Content

- 검색엔진을 위한 대량 생산보다 특정 독자의 문제를 완결적으로 해결한다.
- 직접 검증하지 않은 경험, 얕은 재요약과 주제 밖 인기 키워드를 금지한다.
- 글을 읽은 뒤 다시 검색해야 할 핵심 질문이 남지 않도록 범위를 설계한다.
- 사람에게 도움이 되는 정확한 콘텐츠가 모든 SEO 판단보다 우선한다.
- Build Log·설치·튜토리얼·장애 해결은 테스트 결과·실패·로그·설정값 중
  하나 이상의 실제 근거를 포함한다.
- 그 밖의 글은 실제 근거 또는 최소 두 개의 1차 자료를 대조한 고유한
  차이·적용 조건·환경별 판단을 포함한다. 단순 재요약은 발행하지 않는다.

## 먼저 알아둘 것

네이버는 블로그 검색 순위를 하나의 고정 공식으로 공개하지 않는다. 공식 안내에 따르면 검색 결과는 C-Rank, D.I.A., 검색어 관련도, 작성 시점, 문서 품질, 인기도 등 다양한 신호를 자동으로 계산해 결정한다. 따라서 `제목 25자`, `키워드 정확히 5회`, `사진 15장` 같은 숫자는 공식 규칙이 아니라 실무상 테스트하기 좋은 **권장 범위**다.

이 문서는 아래처럼 신뢰 수준을 구분한다.

- **공식**: 네이버가 문서로 밝힌 원칙
- **실무 권장**: 가독성과 검색 의도를 고려한 운영 기준
- **근거 없음**: 상위 노출 보장 공식처럼 퍼진 주장

## 1. 제목 작성 규칙

### 공식 원칙

- 제목만 읽어도 실제 본문의 핵심을 정확히 예상할 수 있어야 한다.
- 관련 없는 인기 검색어와 화제성 키워드를 넣지 않는다.
- 같은 단어를 반복하지 않는다. 반복 삽입은 어뷰징 의심을 받을 수 있다.
- 낚시성 문구나 본문과 맞지 않는 제목을 피한다.
- 제목은 구체적이고 간결하게 쓴다.

### 실무 권장

- **길이:** 한글 기준 대체로 **20~40자** 안에서 핵심을 전달한다.
  - 네이버 서치어드바이저의 웹문서 제목 권장치는 40자 이하다.
  - 이는 블로그 제목의 절대 제한이 아니다. 모바일 검색 결과에서 잘리는 구간도 화면과 질의에 따라 달라진다.
- **핵심 키워드:** 제목 앞부분 또는 첫 절에 한 번 자연스럽게 둔다.
- **보조 키워드:** 검색자가 실제로 궁금해하는 한두 요소만 붙인다.
  - 장소 후기: `주차`, `웨이팅`, `메뉴`, `가격`
  - 제품 후기: `사용 후기`, `장단점`, `전후 변화`
  - 사용법: `설치`, `설정`, `오류 해결`
- 제목 안에서 같은 핵심어는 원칙적으로 한 번만 쓴다.
- 조사 생략이 너무 심해 읽기 어렵다면 검색어보다 자연스러운 문장을 우선한다.

형식 예:

```text
[핵심 대상] [검색 의도] [구체적 검증 요소]
클로드 코드 핵심 기능 5가지 직접 써보니 편했던 점
성수 맛집 토요일 웨이팅 주차 솔직 후기
```

### 피해야 할 단어와 표현

단어 자체가 금지되는 것이 아니라 **내용과 근거 없이 쓰는 방식**이 문제다.

- `무조건`, `100%`, `완벽`, `기적`, `한 번에`, `대박`
- `충격`, `실화?`, `안 보면 손해`, `모르면 바보`
- 본문과 무관한 연예인·사건·급상승 검색어
- `최저가`, `1위`, `유일`, `공식`처럼 입증이 필요한 표현
- 특수문자·이모지·대문자를 반복한 제목

## 2. 본문 구조

### 권장 비율

고정된 공식 비율은 없지만 정보 탐색형 포스트는 아래 범위가 읽기 편하다.

- 도입 10~15%
- 본론 70~80%
- 결론 10~15%

분량을 맞추기 위해 내용을 늘리지 않는다. 검색 의도를 충분히 해결하는 데 필요한 만큼만 쓴다.

### 도입

첫 화면 안에서 다음 세 가지를 알 수 있게 한다.

1. 어떤 문제나 궁금증을 다루는지
2. 작성자가 어떤 경험 또는 근거로 말하는지
3. 글에서 무엇을 확인할 수 있는지

핵심 키워드를 첫 1~2개 문단 안에 자연스럽게 한 번 포함한다. 인사말, 날씨 이야기, 키워드 나열로 첫 화면을 소모하지 않는다.

### 본론

- 검색자의 후속 질문 순서로 전개한다.
- 한 문단에는 하나의 장면이나 주장만 담는다.
- 직접 경험, 과정, 실패, 비교, 수치, 사진처럼 고유한 정보를 넣는다.
- 중요한 정보는 이미지에만 넣지 말고 본문 텍스트로도 적는다.
- 정책·가격·사양처럼 바뀔 수 있는 정보에는 확인일과 출처를 표시한다.
- 장단점을 균형 있게 쓴다.

### 소제목

- 긴 글은 3~6개의 설명형 소제목으로 나눈다.
- 소제목은 아래 문단의 질문에 바로 답하게 쓴다.
- 핵심 키워드를 모든 소제목에 반복하지 않는다.
- `1. 개요 / 2. 특징 / 3. 결론`보다 구체적인 문구가 낫다.

예:

```text
코드베이스를 읽고 직접 수정한다
테스트까지 실행해 결과를 검증한다
MCP로 외부 도구와 연결한다
```

### 결론

- 핵심 판단을 2~4문장으로 정리한다.
- 누구에게 적합한지, 어떤 경우에는 맞지 않는지 밝힌다.
- 본문에 없던 키워드를 마지막에 몰아서 넣지 않는다.
- 필요하면 다음 행동 하나만 제안한다.

## 3. 키워드 밀도와 배치

### 공식적으로 고정 밀도는 없다

네이버는 `1%`, `3%`, `정확히 5회` 같은 최적 밀도를 공개하지 않았다. 같은 단어를 반복해 넣는 행위는 오히려 어뷰징 의심 대상이 될 수 있다.

### 권장 배치

주요 키워드는 자연스럽게 필요한 곳에만 둔다.

- 제목: 1회
- 도입 첫 1~2문단: 1회
- 관련 소제목: 필요할 때 0~1회
- 본문: 의미상 필요한 문단에 분산
- 결론: 자연스러울 때 0~1회
- 해시태그: 핵심어와 관련어로 정리

### 작성법

- 정확히 같은 구절 대신 자연스러운 변형과 대명사를 쓴다.
- 지역명, 브랜드명, 문제명, 사용 목적 등 의미적으로 가까운 관련어를 문맥 안에서 사용한다.
- 먼저 사람에게 자연스럽게 쓰고, 발행 전 검색어가 빠지지 않았는지만 확인한다.
- 문장을 소리 내어 읽었을 때 키워드가 거슬리면 줄인다.

나쁜 예:

```text
클로드 코드 기능을 찾는 분께 클로드 코드 기능 중 좋은 클로드 코드 기능을 알려드립니다.
```

좋은 예:

```text
클로드 코드를 써보니 단순한 자동완성보다 프로젝트 전체를 다루는 기능이 특히 편했어요.
```

## 4. 이미지

### 몇 장이 적절한가

공식적인 최적 장수는 없다. 글의 길이와 검색 의도를 설명하는 데 필요한 만큼 쓴다.

실무 기준:

- 짧은 정보글: 3~6장
- 일반 후기·튜토리얼: 6~12장
- 여행·공간·과정 중심 후기: 10~20장도 가능

같은 구도의 사진을 장수 채우기용으로 반복하지 않는다. 사진마다 위치, 과정, 결과, 비교 등 새 정보를 줘야 한다.

### 이미지 품질과 구성

- 직접 촬영·제작한 고유 이미지를 우선한다.
- 흐릿한 사진, 워터마크가 과한 이미지, 무관한 스톡 이미지를 피한다.
- 핵심 결과를 보여주는 이미지는 글 앞부분에 둔다.
- 전후 비교는 촬영 조건과 보정 여부를 동일하게 유지하고 과장하지 않는다.
- 타인의 이미지를 쓸 때는 이용 권한과 출처를 확인한다.
- 핵심 정보는 이미지 속 글자로만 제공하지 않는다.

### alt 텍스트

- 네이버 블로그 에디터가 모든 게시 이미지에 웹사이트처럼 자유로운 `alt` 속성 입력을 제공한다고 가정하지 않는다.
- 직접 운영하는 웹사이트라면 각 이미지의 내용과 목적을 짧고 구체적으로 설명한다.
- 키워드를 나열하지 않는다.
- 네이버 블로그에서는 사진 설명(캡션)과 주변 본문으로 이미지의 의미를 명확하게 한다.

좋은 설명:

```text
VS Code 터미널에서 Claude Code가 테스트를 실행한 화면
```

나쁜 설명:

```text
클로드코드 클로드코드기능 AI코딩 추천 개발자
```

### 대표 이미지 규격

- 네이버 블로그 검색 썸네일의 고정 노출 규격이나 특정 대표 이미지의 노출 보장은 공식적으로 공개되지 않았다.
- **실무 권장 제작본:** 1:1 또는 4:3 비율, 최소 1200px 이상, 중앙 안전영역에 핵심 피사체 배치.
- 작은 화면에서도 알아볼 수 있도록 문구는 짧게 하고 가장자리에 중요한 요소를 두지 않는다.
- 낚시성 문구와 실제 본문에 없는 결과 이미지를 쓰지 않는다.

## 5. 네이버 수동 발행용 해시태그 활용법

해시태그 개수만으로 상위 노출이 보장되지 않는다.

이 절은 네이버 등 해시태그를 본문 요소로 사용하는 플랫폼에만 적용한다. WordPress 분류용 태그 수와 생성 규칙은 `publisher-guide.md`의 3~4개 재사용 원칙을 따르며, 두 개념을 혼용하지 않는다.

### 실무 권장

- **5~10개** 정도의 직접 관련 태그부터 시작한다.
- 핵심 주제 1~2개, 세부 의도 2~4개, 지역·대상·상황 태그를 조합한다.
- 본문에 없는 화제성 태그를 붙이지 않는다.
- 같은 의미의 철자 변형을 무더기로 넣지 않는다.
- 지나치게 넓은 태그보다 실제 검색 의도가 드러나는 구체적 태그를 우선한다.

예:

```text
#클로드코드 #AI코딩도구 #클로드코드기능 #개발자도구 #MCP
```

피해야 할 예:

```text
#일상 #소통 #맞팔 #핫플 #연예인 #오늘의뉴스
```

## 6. C-Rank와 D.I.A.가 선호하는 패턴

### C-Rank: 출처의 신뢰도와 주제성

네이버 공식 안내는 C-Rank를 **주제별 출처의 신뢰도와 인기도 중심**의 모델로 설명한다.

실행 원칙:

- 블로그 전체에서 핵심 분야를 일관되게 다룬다.
- 한 주제에 대해 단발성 요약이 아니라 경험과 지식을 꾸준히 축적한다.
- 프로필, 카테고리, 글의 주제가 서로 어긋나지 않게 한다.
- 오래된 정보는 수정하거나 새 글에서 변경점을 분명히 밝힌다.
- 댓글·반응을 인위적으로 만들지 말고 실제 독자에게 유용한 콘텐츠를 쌓는다.

### D.I.A.: 문서 자체의 경험과 정보성

공식 안내에 따르면 D.I.A.는 문서별 경험을 중심으로 보고, 주제 적합도, 경험 정보, 정보 충실성, 문서 의도, 어뷰징 척도, 독창성, 적시성 등이 복합적으로 반영된다.

실행 원칙:

- 직접 사용하거나 방문한 과정과 판단 근거를 구체적으로 쓴다.
- 남들도 적는 정보 뒤에 본인만의 실패, 비교, 팁, 결과를 넣는다.
- 검색 질문에 곧바로 답하고 관련 없는 이야기를 줄인다.
- 가격, 시간, 환경, 버전, 조건처럼 판단에 필요한 맥락을 제공한다.
- 광고·협찬 여부를 투명하게 밝히고 장단점을 균형 있게 쓴다.
- 최신 정보가 중요한 글은 확인 날짜와 버전을 적는다.

### 둘을 함께 만족시키는 발행 패턴

```text
일관된 분야를 꾸준히 다룸
→ 해당 주제에 대한 출처 신뢰 축적
→ 각 글에는 직접 경험과 독창적인 정보 포함
→ 독자가 검색한 문제를 실제로 해결
→ 오래된 정보는 관리하고 업데이트
```

## 7. 어뷰징으로 판정될 수 있는 행위

네이버가 공식적으로 안내하는 주요 스팸 유형을 블로그 운영에 맞게 풀면 다음과 같다.

- 제목·본문과 무관한 인기 키워드 삽입
- 같은 키워드 또는 문장을 의미 없이 반복
- 제목·썸네일과 실제 내용이 다른 낚시성 콘텐츠
- 동일 템플릿에서 단어만 바꾼 저품질 글 대량 발행
- AI로 만들었다는 이유 자체가 아니라, AI를 이용해 무의미한 유사 문서를 대량 생성하는 행위
- 타 블로그·기사·검색 결과를 복사하거나 기계적으로 바꿔 게시
- 링크만 가득한 페이지 또는 관련 없는 외부 링크 대량 삽입
- 사용자와 검색로봇에게 서로 다른 내용을 보여주는 클로킹
- 관련 없는 페이지로 강제 이동시키는 리다이렉트
- 허위 주소·전화번호·신청 링크, 사실로 오인시키는 합성 이미지
- 광고·대가성 관계를 숨기거나 객관적 체험처럼 위장
- 조작된 조회수·공감·댓글·체류를 상위 노출 공식처럼 이용
- 짧은 시간에 유사 게시물을 연속 발행해 검색 결과 점유 시도

## 8. 근거 없는 SEO 속설

아래 주장은 공식 규칙으로 확인되지 않는다.

- 핵심 키워드는 정확히 5번 써야 한다.
- 사진은 반드시 15장 이상이어야 한다.
- 글자 수가 2,000자 이상이면 무조건 상위 노출된다.
- 매일 같은 시간에 발행해야 블로그 지수가 오른다.
- 외부 링크를 하나라도 넣으면 누락된다.
- AI로 작성한 글은 모두 자동으로 저품질 처리된다.
- 특정 금칙어 하나만 써도 노출이 차단된다.

숫자는 자체 실험의 기준으로는 쓸 수 있지만 검색엔진의 공식으로 표현하지 않는다.

# 기술 블로그 SEO 원칙

HuntLab 기술 블로그는 검색엔진을 위한 문서가 아니라 사용자의 기술적 문제를 해결하는 문서를 만든다.

- 검색 의도를 먼저 해결한다. 검색자가 원하는 것이 개념 이해, 설치, 설정, 비교, 오류 해결 또는 의사결정 중 무엇인지 파악하고 그 순서에 맞춰 답한다.
- 첫 화면에서 질문에 대한 핵심 답을 제공한다. 긴 배경 설명이나 키워드 나열보다 결론, 적용 조건 또는 해결 방향을 먼저 보여준다.
- 코드 예제는 문서에 명시한 환경에서 실제 실행 가능한 예시를 사용한다.
- 모든 코드 블록에는 해당 코드의 언어를 명시한다.
- 공식 문서를 요약하는 데 그치지 않고 실제 사용, 설정, 실패, 수정 및 검증 경험을 우선한다.
- 테스트로 확인한 결과와 작성자의 추측·가설을 명확히 구분한다.
- 운영체제, 런타임, 프레임워크, 라이브러리, API 또는 제품의 관련 버전 정보를 명시한다.
- 정책, 가격, 인터페이스, 설치 방법처럼 변경 가능성이 있는 내용은 확인 날짜를 적는다.

검증하지 않은 코드나 결과를 실제 확인된 내용처럼 제시하지 않는다.

# WordPress SEO

HuntLab WordPress 게시물은 다음 구조를 따른다.

- H1은 WordPress 게시물 제목 하나만 사용한다.
- Markdown 본문은 H2부터 시작한다.
- Slug는 짧고 의미 있게 작성하며, 핵심 주제를 식별하는 데 불필요한 단어와 반복 표현을 제거한다.
- 공개 후 Slug 변경은 기존 URL 단절 가능성이 있으므로 `publisher-guide.md`의 승인 정책을 따른다.
- 각 게시물에 본문을 정확히 요약하는 고유한 Meta Description을 작성한다.
- 동일하거나 유사한 콘텐츠가 여러 URL에 존재할 수 있으면 대표 URL을 식별할 수 있도록 Canonical URL을 지원한다.
- 같은 카테고리와 직접 관련된 기존 글을 적극적으로 내부 링크한다.
- 내부 링크는 독자의 다음 질문을 해결하는 위치에 자연스럽게 배치한다.

# EEAT

E-E-A-T는 별도의 검색 순위 공식이 아니라 HuntLab 콘텐츠의 신뢰성을 검토하는 운영 기준으로만 사용한다.

- **Experience:** 실제 사용, 실패, 수정 및 검증 과정을 근거와 함께 밝힌다.
- **Expertise:** 기술의 적용 조건, 버전, 예외 및 한계를 정확하게 설명한다.
- **Authoritativeness:** 공식 자료와 실제 프로젝트를 근거로 HuntLab만의 분석을 제공한다.
- **Trustworthiness:** 출처, 작성자, 확인 날짜, 이해관계 및 불확실성을 투명하게 밝힌다.

실제 경험과 검증을 최우선으로 한다.

# AI 작성 정책

- AI로 작성하거나 보조받았다는 사실 자체를 품질 문제로 간주하지 않는다.
- AI가 생성한 내용을 사실 검증 없이 게시하지 않는다.
- 경험하지 않은 사용, 방문, 테스트 또는 결과를 경험한 것처럼 쓰지 않는다.
- 동일한 템플릿에서 일부 단어만 바꾼 콘텐츠를 대량 생성하지 않는다.
- AI가 만든 코드, 명령어, 설정값 및 버전 정보는 실제 환경이나 공식 자료로 검증한다.
- 모든 AI 작성·보조 콘텐츠는 발행 전에 사람의 리뷰를 반드시 거친다.

# Agent 연계

## Writer Agent

- `seo-guide.md`와 `style-guide.md`를 따라 검색 의도, 제목, 본문 구조 및 표현을 구성한다.

## Reviewer Agent

- `seo-guide.md`를 기준으로 검색 의도, 정확성, 실제 경험, 코드 검증, WordPress 구조 및 AI 작성 정책을 검토한다.
- 검토를 통과하지 못한 콘텐츠를 승인하거나 Publisher Agent로 넘기지 않는다.

## Publisher Agent

- SEO 정책을 새로 만들거나 수정하지 않는다.
- `seo-guide.md`를 참고해 Validation만 수행하고, 발행 동작과 오류 처리는 `publisher-guide.md`와 `publisher-agent.md`를 따른다.
- 콘텐츠를 SEO 목적으로 임의 수정하지 않는다.

## 9. 발행 전 체크리스트

### 제목

- [ ] 핵심 주제가 첫 절에 보이는가
- [ ] 20~40자 안팎에서 읽기 쉬운가
- [ ] 같은 단어를 반복하지 않았는가
- [ ] 본문에 없는 과장·낚시 요소가 없는가

### 본문

- [ ] 첫 화면에서 글의 문제와 경험 근거가 드러나는가
- [ ] 첫 화면에서 검색 질문의 핵심 답을 확인할 수 있는가
- [ ] 검색자가 궁금해할 순서로 소제목을 구성했는가
- [ ] 직접 경험·비교·실패·수치 중 하나 이상이 있는가
- [ ] 해당 요소가 Research의 구체적인 근거와 대응하는가
- [ ] 중요한 정보가 이미지 안에만 있지 않은가
- [ ] 바뀔 수 있는 정보에 날짜와 출처가 있는가
- [ ] 장단점을 균형 있게 다뤘는가
- [ ] 테스트 결과와 추측을 구분했는가
- [ ] 관련 버전과 실행 환경을 명시했는가
- [ ] 코드 블록에 언어가 표시돼 있고 실제 실행 가능성을 검증했는가

### WordPress

- [ ] WordPress 제목 외에 본문 H1이 중복되지 않는가
- [ ] 본문이 H2부터 시작하고 Heading 단계가 자연스러운가
- [ ] Slug가 짧고 의미가 명확한가
- [ ] 고유한 Meta Description이 있는가
- [ ] Canonical URL이 필요한 콘텐츠인지 확인했는가
- [ ] 같은 카테고리의 관련 글을 자연스럽게 내부 링크했는가

### 키워드

- [ ] 제목과 도입에 자연스럽게 들어갔는가
- [ ] 읽을 때 반복이 거슬리지 않는가
- [ ] 관련 없는 유입용 키워드가 없는가

### 이미지와 태그

- [ ] 이미지마다 새 정보가 있는가
- [ ] 대표 이미지가 작은 화면에서도 명확한가
- [ ] 캡션이나 주변 본문이 사진의 의미를 설명하는가
- [ ] 해시태그가 본문과 직접 관련되는가

### 품질과 투명성

- [ ] 다른 글을 복사·짜깁기하지 않았는가
- [ ] 광고·협찬 관계를 명확히 표시했는가
- [ ] 독자가 읽고 실제 행동이나 판단을 할 수 있는가
