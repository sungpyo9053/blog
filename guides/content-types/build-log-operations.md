# Build Log·운영기 유형

## 독자에게 줄 결과

실제 작업의 시간순 기록이 아니라, 어떤 제약에서 무엇을 선택했고 결과가 어떻게
달라졌는지를 재사용 가능한 운영 판단으로 남긴다.

## 필수 근거

- 실제 대상, 날짜, 환경과 변경 전 상태
- 실패한 시도 또는 버린 대안과 그렇게 판단한 근거
- 명령·설정·로그 중 핵심 증거와 민감정보 제거 여부
- 같은 조건의 변경 전후 결과, 롤백 기준과 남은 문제

## 권장 흐름

`목표와 제약 → 변경 전 관측 → 첫 접근과 실패 → 원인 판단 → 실제 변경 → 전후
검증 → 운영 결정 → 남은 문제`

실패가 없었다면 만들지 않는다. 대신 비교한 대안이나 예상과 달랐던 관측을 근거가
있는 범위에서 설명한다.

## Reviewer 거절 조건

- Research 증거 없이 `직접 해봤다`, `운영에서 확인했다`고 쓴다.
- 성공 과정만 매끈하게 재구성해 선택 이유가 사라졌다.
- 로그·주소·키·사용자 식별정보가 노출됐다.
- 변경 전후 조건이 달라 비교 결과를 인과관계처럼 주장한다.
