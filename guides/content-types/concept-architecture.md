# 개념·아키텍처 유형

## 독자에게 줄 결과

독자가 용어를 외우는 데서 끝나지 않고 시스템 경계와 데이터 흐름을 그린 뒤,
자신의 제약에 맞는 설계를 선택할 수 있게 한다.

## 필수 근거

- 해결하려는 요구사항과 범위 밖의 문제
- 요청·데이터·상태가 이동하는 순서와 책임 경계
- 선택한 구조가 지불하는 비용과 선택하지 않은 대안
- 병목, 장애 격리, 보안 또는 확장 조건 중 실제 관련 항목

## 권장 흐름

`문제와 제약 → mental model → 시스템 경계 → 데이터 흐름 → 핵심 선택 → 대안과
trade-off → 실패 조건 → 도입 판단`

구조도는 박스 이름만 나열하지 않고 화살표가 의미하는 호출, 이벤트 또는 상태
변화를 본문에서 설명한다.

## Reviewer 거절 조건

- 구성 요소 목록만 있고 연결 흐름이나 책임 주체가 없다.
- 대안 비교 없이 하나의 구조를 모범 답안처럼 단정한다.
- 규모·일관성·지연·비용 조건 없이 확장성이 좋다고 주장한다.
- 공식 자료 요약만 있고 HuntLab의 적용 판단이 없다.
