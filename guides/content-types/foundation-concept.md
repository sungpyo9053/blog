# foundation_concept — 기초·용어·원리 해설 계약

피지컬 AI와 관련 에이전트를 처음 배우는 독자가 한 개념을 이해하고, 작은 예제를
계산/판단할 수 있게 만드는 유형이다. 실제 프로젝트 장애나 변경 기록은 필수 출발점이
아니다. `technical_explainer`의 시의성 뉴스 경로나 사건형 `evidence_deep_article`과 구분한다.

## 후보와 입력

독자 질문·학습 결과·선수 지식·독립 구성 예제·1차 자료·예제 검증 기록·한계를
갖추고, 현재 WordPress 공개 글과 모든 초안의 전체 검색 의도 비교를 완료한다.
기존 글 보강보다 신규 기초 글이 필요한 이유와 별도 후보 승인 기록을 남긴다.
DEV.to는 발견 경로로 허용하되 원자료 독립 확인 없이 번역/재작성하지 않는다.
가짜 commit·운영 장애·실패 경험으로 사건형 후보를 만들지 않는다.

## Research

- 핵심 주장마다 확인한 공식 문서·원논문·공식 저장소와 확인 날짜/버전을 대응시킨다.
- 하나의 정의에 충분한 자료가 있으면 링크 개수를 채우지 않는다. 논쟁적 주장이나
  비교는 대조할 1차 자료를 추가한다. 초록만 확인했다면 논문 전체 확인으로 쓰지 않는다.
- 직접 구성한 예제는 가정·변수·단위·절차·결과·검산 방법을 기록한다.
- 산술 검산은 산술 검산이며 로봇/물리 엔진/모델 실행이 아니다. 외부 실험 결과와
  자체 검증을 분리하고, 실물 안전성·성능을 보장하지 않는다.
- `original_contribution`, `evidence`, `limitations`와 글에 적용할 검증 범위를 남긴다.
  `not_directly_tested`를 쓰는 경우 무엇은 실행하지 않았고 무엇은 확인했는지 밝힌다.
- 실제 경험이 아닌 설명용 상황은 그렇게 표시한다. 예상 출력은 실측 결과가 아니다.

## Writer·Assembler

첫 부분에 독자 질문·학습 목표·선수 지식을 밝힌다. 첫 등장 용어는 쉬운 한국어 뜻과
영문을 함께 설명하고 쉬운 예 → 정확한 원리 → 적용 조건을 연결한다. 비유의 한계를
밝히며 한 글에 필요 이상의 최신 모델/라이브러리를 나열하지 않는다.

예제에는 독자가 다음 값이나 선택을 직접 판단할 질문과 답의 이유를 둔다. 수식은
변수·단위·가정을 설명하고, 계산 결과와 해석을 분리한다. 필요한 표/그림만 사용한다.
고정 `20초 핵심 요약`, FAQ, 표 개수, 분량, 캡처 장수와 실패 서사를 강제하지 않는다.
이미지와 코드로 근거가 생기지 않는다. 개념 그림을 실제 로봇 실험 사진으로 표현하지 않는다.

내부 링크는 실제 공개된 관련 글만 연결한다. 준비 중인 다음 편을 가짜 링크로 만들지
않는다. 설치/실행을 약속하지 않는 해설에는 실행 튜토리얼을 강제하지 않는다. 실행
코드를 제공하면 최종 복사 블록과 독자용 준비 절차를 실제로 확인해야 한다.
본문은 기존 Publisher 계약의 frontmatter·category·이미지·승인 해시를 그대로 따른다.

## Reviewer

`guides/physical-ai-quality.md`의 필수 게이트와 20항목을 실제 최종 글·근거로
평가한다. `content-quality-review.md`와 `physical-ai-quality-review.json`의 계약을
지킨다. 구조 검사 성공은 사실성·독자 이해·고유 가치 검토를 대신하지 않는다.

다음은 보류/반려 사유다.

- 출처가 없는 핵심 주장, 정의/단위/수식 오류, 예제 검산 누락.
- 관측과 상태·행동과 결과·피드백과 학습을 구분하지 못하는 설명.
- 홍보성 용어 정의를 보편적 표준으로 단정하거나 오래된 연구를 최신 성능으로 소개.
- 직접 하지 않은 로봇/물리 엔진/모델 실행을 자체 실험처럼 표현.
- 번역·요약만 있고 자체 예제·설명·판단이 없음.
- 초보자가 필요한 선수 지식 없이 이해/재현을 약속하거나 존재하지 않는 링크를 연결.
- 전체 중복 검사 미완료, 미평가 항목을 만점으로 채움, 작성자와 동일 주체의 검수를
  이름만 바꾸어 독립 검수처럼 표시.

## 발행 경계

후보 승인은 Writer 입력 자격이며 최종 콘텐츠 승인이나 99점이 아니다.
최종 Reviewer 승인·품질 JSON·Publisher 계약·공개 결과 확인이 별도로 필요하다.
기존 10:00 KST 평가, 하루 최대 1건, 동일 잠금/일일 한도와 중복 검사를 공유한다.
후보가 없으면 `no_publishable_topic`으로 끝내며 개념 글을 보충 발행 경로로 쓰지 않는다.
