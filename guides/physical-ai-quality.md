# 피지컬 AI 글 품질 기준 — 목표 99/100

## 평가 대상

최종 글과 그 글을 발행하는 편집 판단을 평가한다. 서버 복구·배포 성공·모바일
화면·테스트 개수·발행량을 글의 점수에 더하지 않는다. 99는 목표이며 현재 점수가
아니다. 과거 운영 점수를 콘텐츠 점수로 재사용하지 않는다. 이 척도는 DEV.to의
공식 기준이나 AdSense 승인 확률이 아니다.

## 점수 이전의 필수 게이트

하나라도 실패하거나 확인되지 않으면 점수와 무관하게 보류한다.

1. 피지컬 AI 또는 관련 에이전트의 독자 문제/학습 목표가 제목·본문·결론과 일치한다.
2. 핵심 주장에 직접 확인한 1차 자료 또는 공개 가능한 실제 실행 증거가 있다.
3. 시뮬레이션/실물, 문서 검토/실행, 외부 연구 결과/자체 재현을 구분한다.
4. 경험·측정·출처·성공 결과를 만들지 않았고 권리·개인정보·비밀정보 문제가 없다.
5. WordPress 공개 글과 모든 초안의 전체 검색 의도 비교 기록이 있다. 불완전한
   API/페이지 수집은 '중복 없음'이 아니다. 업데이트는 자기 자신을 제외한 비교와
   수정 이유를 남긴다.
6. 글 유형에 맞는 예제/실행 검증과 독자가 결과를 판단할 기준이 있다.
7. 중요한 오류·잘못된 코드·근거 없는 성능 우위·위험한 실물 동작 안내가 없다.
8. 별도 Reviewer의 최종 승인과 Publisher 계약을 충족한다.

READY는 후보 자격이다. 최종 글이 없는 후보를 99점 또는 발행 승인으로
기록하지 않는다. 최종 본문이 바뀌면 재검수한다.

## 100점 척도

아래 20개 항목을 각각 0~5점으로 평가한다. 모든 점수에 본문 위치와 근거 경로/URL,
판단 이유가 필요하다. 미확인 항목은 추정하지 말고 `NOT_EVALUATED`로 남기며
총점과 통과 판정을 내리지 않는다.

| 영역 | 항목 (각 5점) | 배점 |
| --- | --- | --- |
| 독자 가치 | 1. 구체적 독자 질문과 학습 성과 / 2. 한 글의 범위와 완결성 / 3. 기존 글과 구별되는 결론·설명 / 4. 읽은 뒤 가능한 판단·행동 | 20 |
| 기초와 원리 | 5. 선수 지식과 단계별 설명 / 6. 용어의 첫 설명과 일관성 / 7. 원리·인과·가정의 정확성 / 8. 비유·예제와 원리의 연결 및 한계 | 20 |
| 사실과 증거 | 9. 핵심 주장별 출처 추적 / 10. 날짜·버전·환경의 적절성 / 11. 외부 결과와 자체 검증 구별 / 12. 불확실성·반례·적용 한계 | 20 |
| 예제와 재현 | 13. 질문을 해결하는 구체적 예제 / 14. 유형에 맞는 검산 또는 실행 기록 / 15. 결과 해석과 정상·실패 판단 | 15 |
| 글과 학습 연결 | 16. 도입부터 결론까지의 논리 / 17. 자연스럽고 명확하며 중복 없는 문장·코드 설명 / 18. 필요한 표·그림·선수/후속 연결의 유용성 | 15 |
| 발행 판단 | 19. 전체 중복 비교와 신규/보강 선택의 타당성 / 20. 독립 검수·정정 책임·근거와 승인 산출물의 일치 | 10 |

공통 채점 기준:

- 0: 없거나 잘못됐다.
- 1: 이름만 언급됐고 독자가 사용할 수 없다.
- 2: 일부 설명/근거가 있으나 중요한 누락이 있다.
- 3: 기본 이해/사용은 가능하지만 구체적인 개선이 필요하다.
- 4: 증거로 확인되며 경미한 개선점 하나가 남는다.
- 5: 글의 범위에서 필요한 설명과 검증을 충족했고 Reviewer가 확인한 구체적
  미해결 결함이 없다. '완벽하다'는 감상은 근거가 아니다.

5점 조건을 해당 글에 적용한 이유를 적는다. 링크 존재만으로 사실성 5점이
아니며 실제 주장과 자료가 일치해야 한다. 불필요한 이미지/수식을 억지로 넣지
않는다. 기초 글도 예제와 확인 과정을 평가하므로 '해당 없음'으로 배점을 면제하지 않는다.

## 자연스러움 필수 검수 (2026-09-17 사용자 승인)

99점 발행에는 아래 다섯 검수를 모두 통과하고 항목17이 5점이어야 한다.
다른 항목의 점수로 문체 결함을 상쇄하지 않는다. AI 탐지기나 인간 작성 확률을
측정하는 조건이 아니라 독자가 읽는 문장과 구성의 편집 판단이다.

- `structure`: 최근 글과 도입·H2 진행·마무리를 대조했다. 주제에 필요한 구조이며
  독자 소개→용어→예제→한계 틀의 빈칸 채우기나 같은 결론의 반복이 없다.
- `rhythm`: 문장과 문단 길이가 설명의 필요에 맞는다. 균일한 호흡, 밀집 문답,
  번역투, 관료적인 추상 명사 대신 구체적 대상과 행동을 쓴다.
- `restraint`: 독자·목적·검증 범위 안내와 부정 대비문을 불필요하게 반복하지 않는다.
  중요한 제한은 해당 주장 가까이에 유지하고, 짧게 만들려고 위험·불확실성을 숨기지 않는다.
- `judgment`: 실제 근거에서 무엇을 비교했고 왜 선택했는지 알 수 있다. 문서 해설은
  근거 있는 해석을 보여주며, 없는 실험이나 사용 경험을 요구하지 않는다.
- `honesty`: 사람처럼 보이려고 경험·실패·감정·저자 정체성을 만들지 않았고,
  윤문 전후의 사실·한계·확실성·출처 의미를 보존했다.

각 항목은 본문 위치와 구체적인 문장/구성 증거로 판단한다. '자연스럽다' 한 줄,
금칙어 0개, 기계 검사 성공은 근거가 아니다. 수정 글은 전후 사례와 남은 결함을
기록하고, 신규 글은 실제 본문 사례를 기록한다. 최근 비교 글이 없으면 그 사실과
비교한 배치/문체 입력을 명시하며 가짜 비교를 만들지 않는다. 문제가 있으면 HOLD,
수정 뒤 다시 검수한다. 예전99점 승인에는 이 검수가 포함되지 않았으므로 재사용하지 않는다.

## 글 유형별 검증

- **용어·원리:** 검증한 정의 + 직접 구성한 설명용 예제 + 계산/논리 검토 기록
  + 이해 확인 질문과 답의 이유. 실행 주장이 없으면 실행 로그를 강제하지 않는다.
- **최신 개념·도구 해설:** 원자료 날짜·버전 + 기존 대비 실질적 차이 + 적용/비적용
  사례. 저자 주장과 편집자 추론을 구별한다. DEV.to는 발견 자료이지 실측 증거가 아니다.
- **실습·설치·문제 해결:** 환경/버전·의존성·코드/커밋·입력·명령·실제 출력
  + 성공/실패 판별. 소스 검토나 예상 출력을 실행 증거로 대체하지 않는다.
- **비교·실험:** 같은 비교 조건·기준선·측정 방법·반복/표본·결과·변동성·실패·제한.
  문서 기반 비교에는 범위를 명시하고 실측 수치를 붙이지 않는다.

모든 유형에서 자체 결과와 외부 근거의 경계를 밝힌다. 실물 검증이 없다면
시뮬레이션 성공만으로 현실 성능을 결론 내리지 않는다.

## 개선 사이클과 판정

1. 최종 글과 근거를 고정하고 별도 Reviewer가 필수 게이트와 20개 항목을 평가한다.
2. 부족한 항목의 위치·독자 영향·수정 내용·필요한 증거를 기록한다.
3. Writer가 수정한다. 증거가 없으면 주장 범위를 줄이거나 조사/실험을 추가한다.
4. 수정된 본문과 근거를 재검수한다. 점수를 맞추려고 배점이나 기준을 바꾸지 않는다.
5. 모든 게이트 통과, 전 항목 평가 완료, 합계 99 이상, 중대 결함 없음일 때만
   이 기준의 `APPROVED`다. 99는 최대 한 항목의 경미한 개선점만 남는 수준이다.
6. Publisher 계약은 별도 충족해야 한다. 공개 URL·저장 본문 일치는 발행 성공의
   증거이지 글 점수를 올리는 보너스가 아니다.

자동 구조 검사 통과는 독립 내용 평가를 대신하지 않는다. 자동 확인과 Reviewer의
실제 내용 판단을 보고서에서 구분한다. 자료·환경·권한이 부족하면 `HOLD`와 부족
조건을 남긴다. 검증하지 못한 상태를 99로 올리지 않는다. 빈 후보는
`no_publishable_topic`이다.

평가 기록에는 article_id/경로, 글 유형, 본문 SHA-256, 근거 목록, 검수자/시각,
항목별 점수·이유·본문 위치, 게이트 결과, 미해결 결함, 수정 전후, 최종 판정을 남긴다.
점수 기록이 실행 가능한 발행 게이트와 연결됐는지는 별도 검증한다. 문서 변경만으로
자동화 적용을 완료했다고 말하지 않는다.

## 실행 게이트용 검수 JSON

Reviewer는 사람이 읽는 `content-quality-review.md`와 기계 검증용
`physical-ai-quality-review.json`을 같은 현재 주제 디렉터리에 작성한다. 내용 판단이
완료되지 않았다면 승인 JSON을 꾸며 채우지 말고 Markdown에 `HOLD`와 부족한
근거를 남긴다. 실행 검증 구현은 `scripts/physical_ai_quality_gate.py`다.

승인 JSON은 다음 **정확한 키와 타입**을 사용한다. 알 수 없는 키와 중복 JSON
키도 거절한다. 아래는 스키마 설명이지 복사해 승인할 예시 데이터가 아니다.

- `schema_version`: 정수 `2`. 과거 schema1은 이력을 보존하되 새 발행 승인으로 재사용하지 않는다.
- `publish_sha256`: 최종 `publish.md`의 **원본 바이트**에 대한 소문자 SHA-256.
  본문만 추출한 해시가 아니며 frontmatter를 포함한다.
- `writer_id`, `reviewer_id`: 실제 수행 주체의 비어 있지 않은 문자열. 공백 제거와
  대소문자 정규화 후 서로 달라야 한다. 문자열 차이만으로 실질적 독립성이 증명되지는 않는다.
- `reviewed_at`: 시간대가 포함된 ISO8601 검수 시각.
- `gates`: 정확히 `gate_1`부터 `gate_8`까지의 객체. 각 값은 문자열이나 숫자가
  아닌 boolean `true`다. 순서는 위 필수 게이트와 대응한다. `gate_8`은 내용 승인과
  발행 준비 계약의 검토이며 이미 공개됐다는 증거가 아니다. Publisher는 이후 별도 검증한다.
- `items`: 정확히 20개 객체. 각 객체는 `id`(중복 없는 정수 1~20), `score`(정수 0~5),
  `reason`, `body_location`, `evidence_ref`(각각 비어 있지 않은 문자열)만 갖는다.
  항목 번호는 위 척도에 대응한다. 위치는 실제 본문 절/문장, 근거는 해당 자료를
  추적할 경로/URL과 지점을 기록한다. `NOT_EVALUATED`는 승인 JSON의 유효 점수가 아니다.
- `total`: 항목 합계와 동일한 정수이며 99 이상.
- `verdict`: 정확히 문자열 `APPROVED`.
- `naturalness`: 정확히 `verdict`, `checks`, `comparison_refs`, `unresolved_issues`를 가진 객체.
  `verdict`는 `PASS`, `unresolved_issues`는 빈 배열이다. `comparison_refs`는 실제 최근 글
  또는 배치 비교 기록 경로/URL의 비어 있지 않은 문자열 배열이다.
  `checks`는 정확히 다섯 객체이며 각각 `id`, `passed`, `reason`, `body_location`,
  `evidence_ref`만 가진다. id는 위 structure/rhythm/restraint/judgment/honesty 각 하나씩,
  passed는 boolean true, 나머지는 실제 이유·본문 위치·근거의 비어 있지 않은 문자열이다.
  항목17의 score는 5여야 한다. naturalness의 의미 판단은 독립 Reviewer가 수행한다.

기계 검사는 필드·타입·점수·해시 결합을 검증한다. 출처의 진실성, 본문 위치의
실제 적합성, 검수자의 실질적 독립성까지 자동 입증하지 않는다. 별도 Reviewer의
내용 검토를 대신할 수 없으며, 실행 pipeline에서 이 검사를 호출하는지도 별도
검증해야 한다. 승인 후 `publish.md`가 바뀌면 Markdown 검수와 JSON 모두 갱신한다.

## '전체 콘텐츠 99' 보고 조건

한 편의 점수나 평균을 전체 블로그 점수라고 부르지 않는다. 평가 시점 공개 글 목록,
전체 초안 비교 범위, 학습 경로, 기존 운영 아카이브의 유지/처분 상태를 명시한다.
핵심 학습 경로의 모든 공개 글이 이 기준을 통과하고 독립적으로 읽을 수 있는지,
미검수 글을 핵심 추천 목록에서 분리했는지 확인한다. 아카이브는 새 컨셉 점수에
합산하지 않되 중대한 사실·권리·보안 오류를 방치하지 않는다.
글을 검수하지 않았다면 '기준 갱신 완료, 콘텐츠 점수 미평가'로 보고한다.
KST 10:00 평가, READY 조건, 하루 최대 1건, 후보 없을 때 무발행은 유지한다.
