# HuntLab 편집 컨셉 — 2026-09-16

피지컬 AI를 처음 접하는 개발자가 용어와 원리를 이해하고, 도구를 선택하고,
작은 실험을 직접 수행하도록 돕는 한국어 실전 기술 블로그다.
목표는 사이트 운영 점수가 아니라 **글의 품질과 발행 판단의 수준**이다.
DEV.to의 좋은 실전 글에서 문제 설명과 예제의 방식을 참고하되 사이트 전체를
동일한 품질로 간주하거나 다른 저자의 글·경험을 복제하지 않는다.

## 독자와 학습 경로

독자는 프로그래밍 기초는 있으나 로봇·제어·학습 용어에는 익숙하지 않은 개발자다.
필요한 수학과 선수 지식을 밝히고, 첫 전문용어는 쉬운 한국어 뜻과 영문을 함께
설명한다. 부정확한 비유로 원리를 대체하지 않는다.

1. 큰 그림과 용어: 피지컬 AI, 센서, 액추에이터, 관측, 행동, 정책, 좌표계.
2. 작동 원리: 인식·행동·피드백, 제어와 학습, 데이터와 시뮬레이션의 역할.
3. 최신 개념: 기존 방식과의 차이, 적용 조건, 논문에서 확인된 범위와 한계.
4. 프레임워크·라이브러리: 해결하는 문제, 최소 예제, 실행 환경과 실패 진단.
5. 실전 실험과 선택: 기준선과 비교, 결과 해석, 도구 선택, 현실 적용의 한계.

에이전트 글도 인식·계획·도구 사용·제어·안전 및 이에 필요한 공통 기초를
설명하면 범위에 포함한다. 피지컬 AI가 중심이며, 무관한 일반 에이전트 소식으로
범위를 채우지 않는다. 선수 지식 없이 고급 도구 소개부터 시작하지 않는다.
위 분류는 편집 분류다. WordPress 카테고리 생성·매핑·이관은 별도 검토와
발행 계약을 따른다. 없는 기초 글을 링크하거나 존재하는 것으로 쓰지 않는다.
기존 WordPress 운영 글은 운영 아카이브로 분리할 대상이며, 제목만 바꾸어
피지컬 AI 글로 위장하거나 관련 없는 글을 학습 경로에 끼워 넣지 않는다.

## 후보 발견과 두 근거 경로

DEV.to의 피지컬 AI/에이전트 글에서 독자 질문과 주제를 발견할 수 있다.
인기도·좋아요·최신성은 사실이나 품질의 증거가 아니다. 발견 URL은 기록하되
공식 문서·원논문·공식 저장소로 독립 확인하고 자체 예제와 결론을 구성한다.
번역·재작성·코드 복제만으로 고유 가치가 생기지 않는다. 인용과 라이선스를 준수한다.

- **기초·원리·개념 해설:** 독자 질문, 확인한 1차 자료, 직접 구성한 구체적인
  예제와 검산/검토 기록이 필요하다. 프로젝트 변경이 없어도 후보가 될 수
  있지만 번역·요약만으로는 충분하지 않다.
- **설치·실습·문제 해결·성능 비교:** 실제 실행 환경과 버전, 코드/커밋,
  입력, 명령, 로그/결과, 정상·실패 판단이 필요하다. 소스 읽기만으로
  실행 성공을 주장하지 않는다. 시뮬레이션과 실제 하드웨어 검증을 구분한다.

뉴스·RSS·검색 수요도 발견 신호이지 READY의 근거가 아니다. 하나의 검증된
문서로 충분한 정의에 출처 개수를 채우지 않으며, 논쟁적 주장이나 비교는
대조할 1차 자료와 차이를 추가한다. DEV.to 발견은 별도 자동 발행 lane이 아니다.

## 작성 전 질문

- 독자가 이해·설명·실행·선택할 수 있게 되는 것은 무엇인가?
- 필요한 용어와 선수 지식은 무엇이며 어디까지 본문에서 설명하는가?
- 주장과 예제의 자료·버전·확인일·검증 기록은 무엇인가?
- WordPress 공개 글과 모든 초안을 전체 비교했는가? 같은 검색 의도라면
  기존 글 보강이 나은가? 새 글 고유의 결론은 무엇인가?
- 비유와 실제 원리는 어디서 달라지는가? 적용되지 않는 조건은 무엇인가?
- 근거는 공개 가능한가? 비밀정보·개인정보·재배포 권리 문제는 없는가?

답과 증거가 없으면 READY가 아니다. 기초라고 얕게 쓰거나, 발표문을 재작성하거나,
글 수를 늘리려고 용어마다 짧은 독립 글을 양산하지 않는다.

## 글의 구성과 운영

개념 글은 쉬운 정의 → 예시 → 정확한 원리 → 확인 문제/작은 실습 → 한계로,
실전 글은 독자 문제 → 가설과 시도 → 재현 → 결과 해석 → 적용과 한계로 연결한다.
고정 H2·FAQ·분량을 모든 글에 강제하지 않는다. 내부 작업 보고서를 독자용 글로
오인하지 않으며 경험·실험·사람의 검수·수치를 만들지 않는다.

평가 기준은 `guides/physical-ai-quality.md`다. 목표 99는 내부 편집 기준이며
실제 글의 증거 기반 재검수 없이 달성했다고 표현하지 않는다.
예약형 대기열 활성화 후에는 02:00/14:00 KST에 후보를 평가하고 회당 최대1편을
미리 작성·검수한다. 대기 목표3편·상한7편이며 준비 중 WordPress 쓰기는 없다.
매일 10:00 KST에는 동결 원고와 원자료·최신 전체 목록을 재확인한 후 하루 최대1편
공개한다. 통과한 대기 원고가 없으면 `no_publishable_topic`으로 정상 종료한다.
활성화 전 기존 10시 후보→작성·검수·발행 경로는 유지한다.
READY는 후보 자격이지 발행 승인 자체가 아니다. 최종 승인은 Reviewer와
`guides/publisher-guide.md`의 발행 계약을 따른다.
브리핑은 별도 `noindex, follow` 참고 기록이며 이 글의 품질 점수에 합산하지 않는다.
기존 글 업데이트도 백업·정정 이유·검토·공개 확인을 남긴다.
점수를 AdSense 승인 확률이나 외부 플랫폼 인증으로 표현하지 않는다.
