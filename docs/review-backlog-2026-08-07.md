## Planner 우선 개선 후보

### 기술 키워드 선정

기술 주제의 Primary Keyword는 가능하면 다음 조합으로 선정한다.

> 제품·기술명 + 실제 오류·문제·해결 행동

예시:

- `Cloudflare Workers 메모리 지표` → `Cloudflare Workers Exceeded Memory 해결`
- `WordPress REST API 재시도` → `WordPress REST API 429 오류 재시도`
- `GitHub Actions 워크플로 승인` → `GitHub Actions 의심 워크플로 실행 차단`
- `Cloudflare Tunnel connections 제거` → `Cloudflare Tunnel API connections 필드 제거 대응`

검토 기준:

- 사용자가 실제 화면에서 보는 오류 문구인가
- 원인·확인·해결·설정 중 분명한 행동 의도가 있는가
- 한국어 설명과 영문 제품명·오류 메시지를 자연스럽게 함께 다룰 수 있는가
- 내부 기획 용어가 아니라 사용자가 검색할 표현인가
- 검색량 수치를 확인하지 못했다면 임의로 만들지 않는가

HuntLab의 장기 방향 후보는 `기술 주제 소개`보다 `기술 문제 해결`을 우선한다.
실제 운영에서 관찰한 증상, 오류 메시지, 실패 조건과 선택 기준을 개념 설명과
함께 다루되 경험하지 않은 장애를 창작하지 않는다.

문제 중심 조합 예시:

- Cloudflare Workers Memory → `Exceeded Memory`
- Datadog → `CPU Spike`
- FastAPI → `Timeout`
- PostgreSQL → `Deadlock`
- AWS ALB → `502`
- OpenTelemetry → `Trace 누락`

제목 후보 예시:

- `FastAPI BackgroundTasks가 실행되지 않는 이유와 Celery를 써야 하는 경우`
- `Datadog SLO가 계속 깨질 때 Golden Signals로 원인 찾는 방법`

각 예시는 실제 Search Console 수요와 HuntLab의 검증 가능한 경험·근거가 있을
때만 주제로 선정한다. 특정 도구나 장애 조합을 할당량처럼 강제하지 않는다.

### 검색 의도 범위

> 검색 의도는 하나, 관련 키워드는 여러 개

- 글 하나가 해결하는 핵심 문제는 하나로 유지한다.
- 관련 오류 문구, 지표, 원인과 해결 행동은 동일한 문제를 설명하는 범위에서만 확장한다.
- 여러 제품·오류·검색 의도를 한 제목에 나열하지 않는다.
- 서로 다른 해결 결과를 요구하는 질의는 별도 글 또는 기존 글의 후속 후보로 분리한다.
- Related Keywords는 Primary Keyword의 의도를 넓히는 용도가 아니라 같은 문제를 다른 표현으로 찾는 독자를 연결하는 용도로 사용한다.

### 제목 계약

제목의 기본 구조 후보:

> 제품·기술명 + 실제 오류·문제 + 독자가 얻는 해결 결과

예시:

> Cloudflare Workers Exceeded Memory 원인과 메모리 사용량 확인법

- 제목에 모든 연관 키워드를 나열하지 않는다.
- P50·P99·Memory Usage 같은 세부 의도는 본문에서 실제로 다룰 때만 H2와 FAQ로 확장한다.
- Planner의 최종 제목과 Primary Keyword가 Reviewer에서 서로 충돌하지 않게 함께 검증한다.
- 본문이 약속하지 않는 오류·결과를 제목에 추가하지 않는다.

## 적용 판단 조건

- 기술 글이 색인됐지만 비브랜드 노출이 거의 없고 검색 표현 불일치가 반복되면 Planner 기준을 최소 수정한다.
- 기술 글이 미색인이라면 제목보다 sitemap, robots, canonical과 크롤링 상태를 먼저 점검한다.
- 노출은 있는데 CTR이 낮으면 제목·Meta Description 보강을 검토한다.
- 평균 순위가 낮으면 검색 의도, 본문 깊이와 내부 링크를 먼저 검토한다.
- `색인 + 노출 + 클릭 발생` 글은 초기 성공군으로 분류하고 성급하게 수정하지
  않는다. 검색어·순위·클릭의 지속 여부를 관찰해 이후 글의 비교 기준으로 쓴다.
- 표본이 부족하면 기존 글 일괄 수정이나 Agent 추가를 하지 않는다.

## 하지 않는 것

- 기존 글 일괄 수정
- Agent 추가
- Workflow 변경
- 대규모 리팩토링

8월 7일 검토의 기본 범위는 Search Console 실측에 근거한 Topic Planner의
키워드·제목 선정 기준 최소 수정이다. 기존 글의 개별 수정도 노출·CTR·순위 등
구체적인 근거와 별도 검토 없이 자동으로 수행하지 않는다.

## 현재 확인된 기준점

- `석유 최고가격제 8차 가격`은 개별 글 색인과 첫 페이지 롱테일 노출을 확인했다.
- 이 노출은 검색 수요, 최신성, 제한된 경쟁 범위와 제목·검색어 일치의 영향을 받았을 가능성이 크다.
- 기술 글은 영문 오류 메시지 중심 수요와 한국어 검색량 부족 가능성이 있으므로 콘텐츠 품질과 검색 수요를 분리해 평가한다.
- Search Console의 초기 `huntlab` 클릭은 운영자의 회사 검색 테스트가 포함돼 외부 자연 유입으로 단정하지 않는다.
- Cloudflare에서 HTTP→HTTPS, `www`→apex 301, `Full (strict)`와 apex canonical을 적용·검증했다.
