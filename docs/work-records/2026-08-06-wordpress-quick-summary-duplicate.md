## 작업을 시작한 계기

공개 글을 다시 확인했을 때 작성된 `## 20초 핵심 요약`과 플러그인이 만든 빠른 요약이
동시에 노출됐다. 공개 HTML에서 `.huntlab-article-quick-summary`가 1개였고,
`<h2>20초 핵심 요약</h2>`은 2개였다. 작성된 요약의 `무엇` 값도 비어 있었고,
fallback 문장인 `문제 또는 판단 기준을 놓치지 않기 위해서`와
`순서로 확인합니다`가 남아 있었다.

## 실제 작업 순서

1. 공개 HTML의 요약 클래스, H2 제목, fallback 문구를 각각 세어 증상을 분리했다.
2. 플러그인의 기존 제목 감지가 `핵심 요약`만 허용하고 `20초 핵심 요약`을 놓치는 것을
   소스와 테스트에서 확인했다.
3. 선택적인 `20초` 접두어를 인식하도록 요약 감지와 후보 제외 정규식을 함께 수정했다.
4. Publisher 계약에 `## 20초 핵심 요약` 정확히 1개와 두 fallback 문구 금지를 추가했다.
5. 로컬과 서버에서 전체 테스트 97개를 통과시켰고 서버는 같은 Git 커밋을 pull했다.
6. WordPress에 플러그인 ZIP 전체 교체를 시도했으나 기존 `.bak` 파일의 권한 문제로
   일부 파일을 복사하지 못했다.
7. 전체 디렉터리를 덮어쓰지 않고 WordPress 공식 플러그인 편집 경로로 변경된 PHP 파일
   하나만 갱신했다. 첫 시도에서는 페이지의 다른 nonce를 골라 실패했고, 편집 전용 nonce를
   선택하도록 적용 도구를 고친 뒤 성공했다.
8. 캐시를 우회해 공개 URL을 다시 요청하고 같은 세 항목을 재검사했다.

## 확인한 결과

수정 후 공개 HTML에서 `.huntlab-article-quick-summary`는 0개,
`<h2>20초 핵심 요약</h2>`은 1개였다. 두 fallback 문구도 검색되지 않았다. 따라서 이번에
확인한 해결 범위는 **작성된 `20초 핵심 요약`을 플러그인이 인식해 자동 요약을 추가하지
않는 것**이다.

## 판단 기록

- 글 작성 규칙과 WordPress 렌더 규칙 중 한쪽만 고치면 같은 문제가 다시 생길 수 있어
  Writer, Publisher 계약, 플러그인 제목 감지를 함께 맞췄다.
- ZIP 교체 실패 후 권한을 강제로 바꾸거나 백업 파일을 지우지 않았다. 필요한 PHP 파일만
  관리자 기능으로 바꾸는 쪽이 영향 범위가 작다고 판단했다.
- 공개 HTML의 개수와 금지 문구를 최종 기준으로 삼았다. 관리자 화면의 성공 메시지만으로
  배포 성공을 판정하지 않았다.

## 막혔던 지점과 예상 밖의 점

문제의 직접 원인은 복잡한 WordPress 필터 순서가 아니라 제목 정규식의 누락이었다. 반면
실제 배포에서는 코드보다 플러그인 디렉터리에 남은 백업 파일 권한과 여러 nonce 구분이 더
오래 걸렸다.

## 아직 남은 범위

- 권한이 다른 기존 `.bak` 파일은 삭제하거나 권한을 바꾸지 않고 그대로 두었다.
- 이번 공개 검증은 작성된 요약을 보존하는 경로를 확인했다. WordPress가 동일한 필터
  결과에 다시 `the_content`를 적용했을 때 전체 TOC HTML까지 완전히 동일한지는 별도의
  PHP 런타임 회귀 테스트가 필요하다.
- 검색엔진 캐시와 이미 수집된 검색결과 스니펫 반영 시점은 이번 작업으로 보장하지 않는다.
